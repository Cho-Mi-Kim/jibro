## 배경·결정

신규 접수 중·예정 공고의 PDF·한글본에서 자격·예외·서류를 대조하고, 신청 상황 질문과 필요한 서류를 내 준비·일회성 확인에 함께 연결한다. 기존 `SourceCoveragePolicy → DocumentVariantComparison → OfficialGuidanceRows/EvidenceGuidanceCompiler → ApplicantSituationCompiler` 경계를 개선했다. 전체 문맥을 확인하지 못한 채 일치한 행만으로 개인화 질문을 승인하는 대안은 채택하지 않았다. 공통 예외가 서류 의무에 영향을 줄 수 있기 때문이다.

## 더한 것과 뺀 것

- 같은 순위의 서로 다른 법정 신청 유형, 은/는·의 경우를 포함한 번호 참조, 독립 주거급여 기준, 자체 완결 열거와 외부 참조를 구분한다. 수치·예외·추천 조건은 원문 그대로 유지한다.
- 발급처가 빈 완전한 서류 행과 공급대상 2열 표를 읽는다. 대체 서류와 기한은 묶음으로 보존한다. 원문 번호 열거로 계층의 구성원을 확인하고, 조건부 서류 질문은 유형 범위만 좁힌다. 공유 어휘와 기존 입력/필요도 계산을 사용한다.
- 한글 표의 실측 미세 경계, PDF 반복 머리말/계속 표, 실제 그림 화살표의 1픽셀 차이, 같은 칸의 여러 줄 절차를 보완한다. 연속 본문의 줄바꿈을 내용 차이로 오인하던 비교를 교체한다.
- 독립 리뷰에서 서류의 열 소속 변경을 놓친 임시 divided-row 평탄화 분기는 제거하고 반례를 추가했다. 디버그용 파서 사본 14개를 정리했다. 제품에 별도 파서·게시 경로·화면별 범위 규칙은 추가하지 않았다.
- 재검토의 반복 머리말 소속 변경 반례는 본문과 머리말에 동일한 열 대응을 적용하도록 수정했다. 공통 서류 행의 제출 면제는 기존 제출 제한 판별을 재사용해 직접 유형 연결에서 제외하고 조건 질문을 유지한다. 각각 새 반례 검사로 검증한다.
- 정책 `source-review-v20`. 자동 검수·미리보기·후속 자료 경로가 공유하며 접수종료 제외, 기존 수동 검수 원고와 개인 기록 보존 경계는 유지한다. 의미 변경이며 단순 리팩토링으로 분류하지 않는다.

## 수원 절차도 판독 후속 — 2026-11-23

- 범위는 기존 파서와 전체 변형 비교에 한정한다. PDF의 독립 화살표 원점을 보존하고 같은 위치의 중복 인쇄는 제거했다. 채색 셀, 수평 절차 패널과 머리말 아래 빈 띠, 아래 방향 화살표로 이어진 다열 계약 절차 상자를 실제 좌표·셀·병합 관계로 읽는다. 합성 격자에도 기존 MAX_GRID_TILES를 적용한다.
- 점선은 동일 선폭/색/관측 획·간격을 확인한 실제 구간만 연결한다. 글자 advance가 선을 넘어 보여도 읽을 수 있는 임베디드 글꼴의 실제 윤곽이 그 선을 침범하지 않을 때만 점선 연결을 허용한다. 글꼴 불명·손상·세로쓰기·회전은 기존 보수적 판정을 유지한다.

### 최종 회귀 수정

DB 통합 첫 실행에서 산곡·북구 2건이 실패했다. 북구는 같은 쪽의 rowgroup 표 및 동의 상자 사이에 새 SAME_PAGE가 들어갔는데 기존 두 조각 결합이 직접 인접만 허용한 원인이었다. 동일 쪽 표시 한 개만 통과시키며 NEXT·본문·다른 표·숫자/열 소속 변경은 계속 거부하도록 고쳤다. 산곡은 새 빈 영역 보존이 기존 단일 1×1 HWPX 래퍼 계약까지 바꾼 원인이었다. 기존 단일 셀 text-only 계약을 복원하고 여러 행의 빈 입력란·실제 PDF 빈 영역은 유지했다. ‘그림만 식별해 제외’하는 기능이라고 보고하지 않는다. 두 실제 원형 재판독 동치 true 확인, 기존 테스트 기대값/기준 변경 없음. 독립 리뷰는 이 범위 수정을 수락했고, 수정 뒤 최종 전체 검사는 재실행한다.

### 최종 검증·실행 반영

최종 변경 뒤 관련 단위646·PostgreSQL통합26·프런트 실제 소비자76(합계748) 모두 통과했다. 타입·실제 IntelliJ8파일 및 마지막2파일 재검사·변경 공백 검사·bootJar 통과. 아래방향 판독 제거 mutation에서 실제 PDF 계약 절차 검사가 실패하고 원복 후 전체 통과했다. 최종 독립 read-only 리뷰에서 추가 지적 없음. Iron Laws/GPT Pro 전용 도구는 제공되지 않아 미실행이다.

v22 runtime와 내장 새 문서 작업 프로세스를5173에 반영해 재시작했다. health/DB UP, 서울v4(15질문34서류)/수원v4(21질문38서류) AVAILABLE/canStart 유지, 공개 질문·서류·검수항목·일정 전체가 재시작 전과 동일함을 HTTP로 확인했다. 기존 수동안내와 개인기록을 재게시하거나 변경하지 않았으며 종료공고를 수동으로 검수하지 않았다. 운영배포/커밋/push 없음.

요청 전체는 미완료다. 이번 완료 범위는 수원 절차도 판독과 공고문 PDF/HWPX 전체 문맥 대조 및 기존두소비경로 회귀검증이다. 상세/부속서식의 모든 추가 자격·계약·동의 조항을 구조화해 검수·질문에 자동 연결하는 구현은 남아 있다. 실제 문맥 차이를 모두 기관확인 문제로 돌리거나 기존 수동v4를 자동 성공으로 계산하지 않는다.

## 수원 부속서식 연결과 실제 검수 반영
