## 배경과 범위

사용자가 기존 후속 목록의 7·8·9·11·12·13·20·21 구현을 요청했다. 7번은 한국시간 매일 00시·06시·09~18시 정각으로 명시했다. 8·9는 이전 Sites 사이트 기능을 현 저장소 기준으로 새로 구현하며 옛 코드는 재사용하지 않도록 했다. 다국어 제외와 기존 로컬 변경을 보존했다. 원격 push·배포·상주 Codex 예약은 수행하지 않았다.

## 문제 발견과 해결

- Java 17에서 ExecutorService가 AutoCloseable이 아닌 테스트 코드를 정리했다.
- 통합 테스트 컨텍스트 증가로 로컬 PostgreSQL 연결 한도에 도달했다. 시험 환경의 풀 크기와 컨텍스트 캐시 크기를 제한했다. 운영 DB 설정은 바꾸지 않았다.
- LH의 실제 `fileDownLoad` 첨부 링크와 `panDtlInfo` 본문 범위를 확인해 메뉴/거대한 주택별 공급 격자를 발췌 대상에서 제외했다. 입력 URI의 사용자 정보를 정규화 전에 검증하도록 보완했다.
- 첨부별 재발췌 결과 영속화, 이미 처리한 첨부 재다운로드 방지, stale 원고 반영 차단, 수정 중 기존 발췌 보존을 추가했다.
- 새 첨부가 없는 반영 요청은 불필요하게 공개 보류·버전 증가를 하지 않는다. 동일한 경우에도 최신 revision은 확인한다.
- 점검 시작·완료 시각에 transaction-start `now()`를 사용하여 생기는 동률을 실제 `clock_timestamp()`로 수정했다. 첨부 통합 테스트 10개를 두 차례 연속 재실행해 확인했다.
- 새 보안 계약에 맞지 않는 오래된 체험 쿠키가 새 체험을 막는 문제는 401 응답 쿠키 정리로 해결했다. 기존 준비를 다른 사람에게 다시 연결하지 않는다.
- 마지막 재시도에서 받은 Retry-After가 FAILED 전환 뒤 사라지는 경계를 추가 발견했다. V17의 독립 공급자 대기 기록으로 실행 실패·기록 삭제 후에도 대기를 유지하고 관리자에게 재요청 가능 시각을 표시한다.
- 장시간 첨부 처리가 정각 수집 등록과 알림 예약을 지연하지 않도록 Spring 예약 실행 풀을 3개로 분리했다. 목록 수집 자체는 DB 임대로 단일 실행을 유지한다.
- 360px 브라우저 검증에서 확인일 라벨에 기존 2.5em 스타일이 섞이는 문제를 발견해 전용 모듈로 분리했다. 125% 글자 확대에서 공고 상세 하단 버튼이 잘리는 문제도 줄바꿈·자동 높이로 해결했다.

## 한계와 운영 조건

- 이 PC의 `LH_SERVICE_KEY`가 비어 있어 실제 목록 예약 수집은 비활성이다. 일정·중복·페이지·429/5xx 재시도는 통제된 테스트로 검증했다. 실제 정각 장시간 관찰과 외부 API 인증은 별도다.
- SMTP는 미등록이며 로컬 메일 보관함 경로를 사용한다. 실제 이메일 수신·외부 OAuth 왕복·운영 서버 적용은 수행하지 않았다.
- 파일 제한·미검출·이미지·암호화 자료는 직접 확인 필요다. 발췌는 조건 판정이나 사용자 질문의 자동 공개가 아니다. 문서 파서 별도 프로세스 격리와 OCR은 범위 밖이다.
- 실제 기기 검증과 브라우저 크기 검증은 구분한다. 큰 프런트 번들 경고와 Gradle 향후 버전 경고는 기존대로 남았다.

## 후속 작업과 발표 범위

- 운영 담당자가 실제 LH 키·SMTP를 설정한 환경에서 정각 수집·외부 수신을 확인한다. 이 컴퓨터에서 키 없는 상태를 성공 수집으로 보고하지 않는다.
- 이전 로그인은 V13 세션 계약 적용으로 재로그인이 필요하다. 기존 준비 데이터의 사용자 소유권은 변경하지 않았다.
- 발표에서는 기능별 저장·권한·검수 경계와 실제 텍스트 발췌 확인을 설명할 수 있다. 사용자 효과나 공식 기관 검수 완료를 주장하지 않는다. 구현 보조·분담 검토는 Codex가 수행했으며 실제 팀 검토는 별도다.
