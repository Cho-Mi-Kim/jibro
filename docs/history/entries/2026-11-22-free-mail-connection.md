# 무료 메일 발송 연결 준비

현재 작업 상태: **해결** (2026-11-23, Asia/Seoul). 도메인·발신자 인증과 운영 서버에서 Gmail 수신 서버로의 실제 전달을 확인했다. 아래 준비·실패 내용은 당시 이력이다.

## 배경·선택·결정
사용자가 jibro.live에 무료 메일 연결을 요청했다. Brevo와 Resend의 공식 무료 안내를 검토하고, 하루300통과 기존 SMTP 연동을 고려해 Brevo Free를 선택했다. 유료 플랜이나 카드 등록은 진행하지 않는다.

## 확인·현재 상태
기존 SMTP 환경 설정과 STARTTLS 강제 설정을 확인했다. Brevo 공식 SMTP 호스트/587포트/SMTP 키 방식이 현재 코드와 맞는다. 가입 화면은 카드 불필요라고 표시한다. 새 비밀번호·약관 동의·이메일 인증은 사용자 진행 대기다. 운영 설정은 아직 변경하지 않았다.

## 검증·한계·후속
현재는 문서와 설정 계약 확인 단계이며 가입·도메인 인증·서버 연결·실제 수신은 미완료다. 가입 후 실제 발급 DNS로 도메인 인증하고 SMTP 키를 안전하게 연결하여 사용자 지정 수신처에서 확인한다. AI는 비교와 설정 확인을 보조했으며 사용자 계정 생성이나 발송 성공을 주장하지 않는다. 발표 자료에서는 준비와 실제 연동을 구분한다.

## 실제 연결 결과
사용자가 가입과 이메일 인증, SMTP 키 생성을 완료하고 안전한 로컬 파일을 지정했다. 도메인 DNS4개 저장을 명시 승인하여 기존 웹 A를 보존하고 등록했다. 서버에 키를 root 전용으로 저장하고 SMTP STARTTLS 인증235, 운영 설정검사 오류0, backend재시작 healthy, 공개 health/DB/목록/상세/OAuth 재검증 성공.

가입 Gmail로 테스트1통을 보내도록 사용자 승인받아 EC2에서 실제 발송했다. SMTP는 수락했으나 Brevo 후속 로그에서 미인증 발신자로 거절했다. 전달 성공은 아니다. 권한 DNS 서버 직접 조회 시 소유TXT와 DMARC가 서버별로 다르게 나타나며 Brevo 도메인 인증 대기다. TXT 재저장 후에도 현재 반영 불일치가 남았다. 도메인 인증 후 발신자 인증과 재발송·수신 확인이 남았다. 서버 설정 연결 완료와 메일 서비스 전체 완료를 구분한다. 키·토큰 값은 기록하거나 Git에 추가하지 않았다.

## 2026-11-23 인증 완료와 재발송 결과

사용자가 DNS 반영 대기 후 재개를 요청했다. 권한 네임서버4곳에 메일 레코드4개가 모두 일치하는 것을 직접 확인했다(16/16). 기존 사이트 A와 SMTP 설정을 유지하고 Brevo의 도메인 인증을 완료했다. 도메인은 Authenticated, 집으로 발신자는 Verified 및 DKIM/DMARC 정상으로 표시된다.

운영 EC2의 STARTTLS·SMTP 인증235, 실행 중 backend의 발신 설정, 공개 메일 모드 smtp와 health/database UP을 확인했다. 승인된 수신처에 테스트1통을 다시 보냈으며 2026-11-23 20:10(KST) Brevo에서 Sent와 Delivered 이벤트를 확인했다. 전날의 미인증 발신자 오류와 달리 이번 요청은 Gmail 수신 서버까지 전달됐다. UI 로그 반영에는 잠시 지연이 있었다.

Free plan과 잔여299/300통, 대기열0을 확인했다. 새 유료 서비스·카드 등록·앱 코드 배포는 없었다. 비밀값은 기록하지 않았다. 로컬 증거는 `.tools/qa/free-mail-20261123/sender-verified.jpg`, `delivered.jpg`에 보관했으며 Git에 추가하지 않았다.

AI는 DNS 대조, 기존 SMTP 설정 검증, 도메인 인증과 승인된 테스트 발송·전달 로그 확인을 수행했다. 키 생성·사용자 승인 등 기존 사용자 역할과 구분한다. 받은편지함/스팸함 분류나 사용자 열람은 확인하지 않았고, 운영 비밀번호 계정이 없는 테스트 수신처에 새 계정을 임의 생성하여 인증·재설정 흐름을 완주하지는 않았다. 계정별 사용자 흐름과 메일 전달 완료의 범위를 구분한다. 현재 메일 연결 차단은 해소됐다.
