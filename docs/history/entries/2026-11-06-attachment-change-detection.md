# 공식 첨부 내용 변경 감지와 후속 결정표

- 기록일: 2026-11-06 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 해결 (로컬 구현·실행, 후속 결정은 설계 채택)
- 유형: 개발 / 의사결정
- 담당·검토: Codex 보조 구현·분담 검토. 실제 팀 담당자·검토자는 미확인
- 관련 이슈·PR·커밋: 이번 작업 미등록. HEAD `e288a993a9a828a798d44eea165c0f276ab34a60`, 브랜치 `feature/attachment-change-detection-20261106`

## 배경·문제

사용자가 전체 후속 목록의 10번도 보완하고 미결 사항을 적절히 정해 표로 정리하도록 요청했다. 10번은 같은 첨부 URL의 파일 내용 변경을 감지하는 기능이다. 기존 목록 필드 해시만으로는 이 변경을 감지하지 못했다. 앞선 1·2·3·5의 미커밋 변경을 보존했고 다국어 제외 결정도 유지했다.

## 고려한 선택지

- URL·ETag·Last-Modified만 비교: 파일 서버가 메타데이터를 갱신하지 않는 경우 내용 변경을 놓칠 수 있다.
- 전체 파일 영구 보관·본문 비교: 과거 원문 재열람은 가능하지만 저장 비용·보관 정책·문서 해석까지 범위가 커진다.
- 실제 파일 스트리밍 SHA-256 비교: 동일 주소의 바이트 변경을 확인하고 현재 단계에서는 파일 보관 없이 적용할 수 있어 채택했다.

## 결정·이유

[첨부 감지 계약](../../contracts/attachment-change-detection.md)을 적용한다. 등록된 공식 첨부만 관리자 요청과 기존 수집 실행에서 검사한다. 첫 성공은 기준 등록이며 이후 다른 해시만 변경으로 인정한다. 실패는 기존 기준과 공고를 유지하고, 변경은 기존 공고 재검수 전환을 사용한다. 개인 준비 스냅샷은 수정하지 않는다.

20MiB·15초·실행당 10개 요청, 45초 이후 신규 요청 중단을 채택했다. 허용 공식 호스트·HTTPS·DNS 사전 검사·리다이렉트 금지·파일 서명 검사를 적용했다. IP 고정이나 문서 내용의 정당성 검증을 구현한 것으로 표현하지 않는다.

나머지 결정은 [후속 결정표](../../planning/backlog-decisions-20261106.md)에 번호를 유지해 정리했다. 민감 답변의 저장 선택은 기존 문서의 확정 원칙이며 미완료 구현으로 구분했다. 운영 계정·실제 비용·기간·담당자·비밀값을 임의로 만들지 않았다. 결정표 작성이 후속 기능 구현이나 배포 완료를 뜻하지 않는다.

## 변경·해결 과정

- `collection/attachments`에 다운로드/해시, 실행 조율, 짧은 저장 트랜잭션, 관리자 API를 분리했다. V11에 기준과 실행·파일별 결과를 저장한다.
- `NoticeService`의 기존 재검수 전환을 공통 메서드로 묶었다. 등록 첨부 변경은 한 실행당 한 번 version/revision을 올린다.
- 다운로드 동안 DB 잠금을 유지하지 않고 반영 시 revision을 검증한다. 점검 중 원고가 바뀌면 SUPERSEDED로 남기고 기준 해시를 적용하지 않는다.
- 관리자 화면은 열린 공고만 이력을 조회하고, 미저장 원고·실행 중 요청을 제한한다. 점검 후 공고/준비 조회 캐시를 갱신한다.
- 독립 검토 과정에서 만료된 실행 재시도, 한도 미처리 상태, 공고 간 검사 순서를 보완했다. 기존 API 수집에서도 목록이 같아도 첨부를 점검한다.

## 기여·한계

- 관리자 UI의 React 동작 검사는 수행했으며 이번 변경의 별도 브라우저 시각·실제 휴대전화 검증은 수행하지 않았다.
- 기존 공개 공고에 대해 자동 점검을 일괄 실행하거나 검수 상태·개인 준비를 변경하지 않았다. 첫 기준 등록 전에 발생한 변경과 미등록 첨부는 감지할 수 없다.
- 원문 HTML의 첨부 자동 발견, 정기 수집, 자동 재시도, 이전 PDF 원본 재열람, 원본 API 응답 보존은 별도 후속 범위다.
- 로컬 변경만 했고 커밋·push·병합·운영 배포는 하지 않았다. 작업 브랜치의 미커밋 파일에는 선행 1·2·3·5 작업도 포함되므로 나중에 업로드할 때 작업별 차이를 구분해야 한다.

## 발표·포트폴리오 메모

같은 URL의 공식 첨부 변경을 실제 바이트 기준으로 감지하고 재검수·개인 기록 보존 흐름에 연결했다. 실패를 변경으로 오인하지 않는 처리와 DB/네트워크 경합을 자동 검사로 확인했다. 실제 팀의 개인 기여는 담당자 확인 후 기재한다.
