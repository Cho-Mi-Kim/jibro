## 배경·문제

정렬 메뉴 수정 후 PR 검사 45378383541의 edge-security가 실패했다. 진단 메시지를 추가한 검사 45379701069에서 호스트 단조 시각 28.960초, 가입 요청 응답 `[204, 204, 204, 204, 429]`를 확인했다. 첫 요청+여유 4건인 계약상 다섯 번째까지 허용되어야 한다. 오래 실행한 호스트의 같은 Nginx 이미지는 통과했다.

## 고려한 선택지

단순 재실행이나 검사 대기·허용 수 완화는 실패를 가리므로 채택하지 않았다. 실제 Nginx 1.30.6 소스의 제한 초기화와 CLOCK_MONOTONIC 사용을 대조하고 Linux time namespace에서 Nginx만 부팅 후 20초로 실행해 동일 실패를 재현했다. 호스트 시간과 운영 컨테이너는 변경하지 않았다.

## 결정·이유

공통 API 위치의 네 제한을 로그인·메일·사람 확인별 하위 위치로 교체했다. 적용되는 세부 제한을 마지막에 두면 Nginx가 첫 요청을 직접 초기화한다. 기존처럼 마지막이 아닌 mail 제한의 첫 기록이 0으로 초기화되면, 부팅 약 30.3초 이내에는 첫 요청 부채가 남는다. rate·burst·IP 기준·응답·보안 권한은 유지한다.

근거: [Nginx 1.30.6 limit_req 구현](https://github.com/nginx/nginx/blob/release-1.30.6/src/http/modules/ngx_http_limit_req_module.c), [단조 시각](https://github.com/nginx/nginx/blob/release-1.30.6/src/core/ngx_times.c), [제한 상속 계약](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html).

## 변경·해결 과정

- 책임: 운영 Nginx 템플릿이 경로별 제한과 프록시 연결을 소유한다. 공통 헤더와 연결 설정은 부모 위치에서 공유한다.
- 추가: 각 하위 위치에 공통 API 제한과 해당 세부 제한, 프록시 핸들러를 명시했다. 자식 선언 시 부모 제한은 상속되지 않고 정규식 자식의 proxy 핸들러도 필요하므로 이 선언은 필수다.
- 삭제: 모든 세부 제한을 공통 위치에 동시에 붙이던 경로를 제거했다. 새 서비스·우회 API·환경 옵션은 없다.
- 기존 실제 이미지 검사에 모든 매핑 주소의 공유 예산, 끝 슬래시, OAuth GET, 전달 IP 위조 제거, 제출이 아닌 GET·OAuth 복귀 경로를 포함했다.
- 초기 후보에서 자식 proxy 핸들러가 빠져 404가 발생한 것을 격리 검사로 발견해 같은 템플릿에서 수정했다.
- 요청 한도 자체를 바꾸지 않는 설정 수정이다. 잘못 조기 차단되던 첫 예산만 계약대로 복구한다.

## 검증·결과

- 기존 템플릿을 부팅 20초로 실행하면 다섯 번째 가입 요청이 429로 실패, 수정 템플릿은 같은 조건 통과. 원래 결함을 되돌린 경우 검사 실패를 확인했다.
- 부팅 1초 환경에서도 확장된 실제 HTTP 검사가 7개 항목 모두 통과했다. 시각 재현은 root의 별도 namespace 실행이며, 이것만으로 컨테이너 권한 검증을 주장하지 않는다.
- 별도로 일반 사용자+Docker 그룹에서 실제 hardened Compose 그대로 `verify_edge.py`를 실행해 7개 항목 통과. 운영 API나 실제 메일을 호출하지 않았다.
- 운영 스크립트 검사 35개 중 31개 통과·4개 POSIX/OpenSSL 검사는 Windows에서 건너뜀. Linux CI 결과는 push 후 별도 확인한다.
- Iron Laws는 변경 Python 1파일을 실제 검사해 고위험 0, 중위험 6, 저위험 1을 보고했다. IL-301은 제한된 기동 대기 이후 로그를 포함해 실패하는 계약으로 기각. AI-101 5개는 loopback·문서용 위조 IP와 독립 기대값으로 기각. ARC-201은 임시 자원 생명주기와 순차 HTTP 계약을 조율하는 함수로 유지하며 크기만 맞추는 분리는 하지 않았다. 억제 설정이나 실패 기준 완화 없음.

## 기여·한계

AI가 원격 실패 로그·공식 구현·제어된 재현으로 원인을 조사하고 수정했다. 독립 작업자·GPT Pro 리뷰와 전체 보안 재감사는 이번 좁은 오류 수정에서 실행하지 않았다. 시간 namespace 재현 도구는 Git에서 제외된 조사 자료이며 제품·CI의 새 실행 경로로 추가하지 않았다.

## 발표·포트폴리오 메모

새 VM에서만 나타난 초기 요청 제한 오류를 실제 구현과 단조 시각 재현으로 좁히고, 제한 강도를 유지하면서 설정의 적용 범위를 수정했다.
