## 배경·선택

선행 작업은 공식 연결이 등록된 공고의 원공고를 목록에서 제외했다. 사용자는 이후 수집되는 정정 공고도 공식 자료로 자동 연결하고 새 제목도 같은 방식으로 축약하도록 요청했다. 제목 유사성으로 합치거나 목록 요청 때 원문을 불러오는 방식을 쓰지 않고, 수집 후 지속 큐와 별도 확인 worker를 선택했다.

## 구현

수집 처리기에 AutomaticCorrectionService를 추가했다. 큐 등록만 수집 흐름에 포함하며 별도 한 작업이 공식 상세의 현재/원공고 ID, 공고이력조회 각 행의 링크·제목·날짜·종류·정정사유를 대조한다. 정정 제목은 우선순위에만 사용한다. 원공고가 나중에 수집되거나 기본 정보가 비공개면 재시도한다. 기존 수집 응답·준비 안내 검수 경로를 복제하지 않는다.

OfficialCorrectionHistory는 최대 20개 버전의 공식 이력만 읽는다. AutomaticCorrectionLinkService는 각 이전 버전과 최신 상세를 검증한 뒤 NoticeCorrectionRepository를 통해 동일 관계 테이블에 저장한다. 새 이력이 이전 대상도 포함하면 A→B를 A→C 및 B→C로 갱신하고 기존 근거를 보존한다. 무관한 기존 연결/순환/오래된 원문으로의 되돌림은 거부한다. 수집 지문·revision·lease를 재확인하고 네트워크 요청은 트랜잭션 밖에서 실행한다.

V34 마이그레이션으로 관계 대상 unique를 index로 변경하고 지속 확인 큐를 추가했다. 자동화 설정은 기본 켜짐, 30초마다 한 건; 5분 lease, 실패 시 10분~6시간 재시도, 연결 후 6시간/정정 없음 24시간 재확인이다. 접수 종료 제외는 공통 AutomaticReviewEligibility를 재사용한다. 원공고 내용·개인 준비·준비 안내 공개 상태는 변경하지 않는다.

신규 제목은 기존 NoticeCard → noticeListTitle 표시 경로가 이미 일괄 처리하고 있어 추가 저장/AI 호출을 넣지 않았다. 원문·검색·접근성 이름은 유지하며 2027년 신규 공고 회귀 사례를 추가했다.

## 검증·결과

- 기존/확장 공식 원문 파서 단위 23개 통과. 자동 연결 통합 6개에서 최초·반복 정정·멱등·지연 수집·비공개·접수 종료·유사 제목 불일치·HTTP 실패 재시도·지문 변경·만료 lease 복구를 검사했다. 기존 수동 정정 15개·정렬 6개·수집 페이지 3개·수집 후속 등록 1개도 통과. 수집 후속 등록 테스트 수정 후 해당 검사 및 자동 연결/페이지 검사를 최종 재실행해 통과했다.
- 실제 CollectionService 경로에서 신규 수집 → 큐 등록, 같은 원문 재수집 시 중복/재시도 시각 초기화 없음, 수집 중 원문 HTTP 요청 없음 확인. 최초 테스트의 외부 트랜잭션이 JPA flush 전 JDBC 조회를 만들던 테스트 경계를 수정하고 실제 수집 트랜잭션 경계로 재검증했다.
- 제목 31개 검사 통과. IntelliJ 저장소 설정으로 변경 Java 정렬, Prettier 테스트 파일 정렬, bootJar 성공.
- 실제 LH 평택·안성 원문으로 큐 → 공식 HTTP/이력 → LINKED 재확인 성공. 기존 관계를 자동 경로로 검증한 사례이며 신규 실공고가 이후 도착하는 상황은 별도 테스트 DB에서 재현했다. 양쪽 공고 내용과 개인 준비 지문 보존 확인.
- 5173 서버 재시작 후 해당 제목 검색 1건(정정본 ID), 원공고 상세200 확인. 실행 패키지는 backend-auto-correction.jar이며 V34 로컬 적용 완료.
- 로컬 근거: .tools/qa/automatic-correction/live.log 및 verified.txt. 실제 브라우저 스타일 변경/실제 휴대폰 검사는 이번 범위에 없음.

## 한계·후속

공식 판독 형식이 달라지거나 관계가 불명확하면 기존 공고를 임의로 숨기지 않고 재시도 사유를 남긴다. 서버가 켜져 있어야 수집/확인이 진행된다. 모든 과거 공고를 일괄 연결했다고 보증하지 않으며 앞으로 기존 수집 흐름에서 처리되는 공고에 적용한다. 운영 배포·원격 push는 수행하지 않았다. 팀 검토와 실제 신규 정정 공고 유입 후 모니터링이 후속이다.
