# 모바일·PC 시안 기반 프론트엔드 재디자인

- 기록일: 2026-11-01 (Asia/Seoul)
- 기록 상태: 검증 완료
- 작업 상태: 구현 완료 / 팀 검토 대기
- 유형: 개발 / 의사결정
- 담당·검토: 사용자 요청, Codex 구현·검증 보조. 팀 담당자 검토 전.

## 배경·문제
사용자가 모바일 brick-20261031-clean 및 PC desktop-20261031-compact의 10개씩 화면과 최대한 동일한 반응형 구현을 요청했다. 기존 PC 화면은 좁은 모바일 본문과 소개 영역으로 구성되어 시안과 구조가 달랐다.

## 고려한 선택지
전체 화면을 이미지로 표시하는 방식은 실제 데이터·상호작용을 보존할 수 없다. 기존 API와 상태 관리 위에 공통 UI와 페이지 레이아웃을 재구성하는 방식을 선택했다.

## 결정·이유
- 별도 feature/frontend-responsive-redesign-20261101 브랜치. 기존 미커밋 동기화 기록은 보존하고 이번 변경에 포함하지 않는다.
- 1024px 이상은 PC 상단 메뉴 및 2단 구성, 그 미만은 하단 메뉴와 세로 흐름. 중간 너비에서도 내용을 숨기지 않는다.
- 샘플 이름·65%·D-5는 하드코딩하지 않는다. 실제 API 값과 한국 날짜 기준으로 표시한다.
- 현재 조건 응답 API는 YES/NO/UNKNOWN이다. 시안의 지역 선택지를 이 값으로 임의 매핑하지 않는다. 기존 질문·응답 계약을 보존하면서 레이아웃을 맞춘다.
- 확인되지 않은 공고 날짜·발급 대상·공식 링크를 만들어 넣지 않는다. 미제공 정보는 확인 필요로 표시한다.
- SEED ActionButton을 유지한다. 공식 React 문서 https://seed-design.io/llms/react/components/action-button.txt 확인. 디자인 시안에 맞는 제품 CSS 및 SVG 아이콘·단계별 벽돌 집을 작성한다.

## 변경·해결 과정
1. PC 상단 메뉴/모바일 하단 메뉴, 공통 색상·타이포·카드·버튼과 벽돌 집 SVG 구성.

## 검증·결과
- `frontend`에서 `npm run ci` 통과: Prettier, ESLint(경고 0), TypeScript, Vitest 5개 파일 20개 테스트, Vite 프로덕션 빌드.
- 저장 실패 후 재시도, 서류 전환 시 미저장 메모 보존, 검수되지 않은 공고 준비 시작 차단, 검색 AND 조건, 관리자 접근 검증을 유지했다. 서류 완료 바로 기록, 신청 기록 저장/취소, 로그아웃 후 보호 화면 접근 및 한국 날짜 기준 마감 계산 회귀 검증을 추가했다.
- 독립 시연 서버(5174)에서 홈·공고·조건·서류·일정·가이드·마이의 모바일/PC 화면과 준비 저장 흐름을 확인했다. 390px 모바일, 1440/1584px PC에서 주요 화면을 검토했고 320px 준비 개요, 768px 일정/서류, 1024px 서류의 문서 가로 넘침이 없음을 확인했다. 모든 화면×너비 조합을 자동 이미지 비교한 것은 아니다.
- 브라우저 검토 중 카드 너비 축소, 다음 행동 문구 겹침, 페이지 포커스에 의한 상단 잘림을 수정했다. 최종 브라우저 error 로그는 없었다.
- 실제 Google·카카오 인증, LH 수집, 운영 DB는 이번 시각 변경 검증에서 다시 실행하지 않았다. 실제 계정/DB에 검증 데이터를 추가하지 않았다.

## 기여·한계
AI 보조 구현이다. 사용성 개선 수치나 사용자 테스트 결과는 아직 없다. SVG 장식은 시안을 참고한 벡터 재현이며 원본 일러스트와 픽셀 단위 동일하지 않다.

## 발표·포트폴리오 메모
모바일/PC의 서로 다른 정보 배치를 기존 API·저장 흐름과 결합하는 반응형 재구성 작업. 검증 완료 후 결과를 추가한다.

## 후속 작업
- 팀에서 실제 공고 데이터로 문구 길이·내용을 최종 검토한다.
- 지역 선택형 질문이 필요하면 질문 스키마 및 응답 API를 별도 변경한다. 현재 YES/NO/UNKNOWN 계약은 유지했다.
- 원본 장식 에셋 확보 시 SVG와 교체할 수 있다. 시안의 수치·날짜·계정명과 실제 데이터 차이를 픽셀 오차로 취급하지 않는다.

### 2차 구현
- 홈 대시보드, 공고 검색/복수 필터/목록 및 상세, 가이드 카테고리와 아코디언 구현.
- API 없는 발표·서류 마감은 확인 필요로 표시. 제공된 일정만 사용.
- 1·2차 구현 후 TypeScript 빌드 검사 통과. 전체 동작 검증은 계속 진행.


### 3차 구현과 회귀 검증
- 내 준비 개요·조건 질문/결과·서류 목록/상세·일정·마이를 재구성했다.
- PC 서류 목록/상세 분리와 모바일 펼침 UI에서도 편집 컴포넌트를 유지해 다른 서류의 미저장 입력을 보존한다.
- 기존 테스트의 화면 탐색을 새 UI에 맞춰 변경했다. 저장 실패→재시도 및 다른 서류 메모 보존 시나리오는 유지했다.
- ESLint 통과, TypeScript 통과, Vitest 4개 파일 15개 테스트 통과.
- 별도 5174 시연 서버에서 PC 조건 응답→결과→서류 완료 기록 및 모바일 서류 화면을 확인했다. 실제 계정/DB에 테스트 기록을 추가하지 않았다.

### 최종 반응형 보완
- 모바일 검색 필터를 펼침 방식으로 제공하고 PC에서는 상시 노출한다. 모바일 공고 상세의 조건 확인 버튼을 핵심 안내 아래에 배치했다.
- 조건 화면에 모바일 뒤로가기를 제공하고, 질문 선택 후 버튼 크기와 준비/일정 카드 배치를 보완했다.
- `3a97f0d` 공통 UI, `105422a` 홈·공고·가이드, `55274d9` 준비 흐름 단위로 먼저 커밋·푸시했다. 마지막 보완과 검증 기록도 같은 작업 브랜치에 별도 커밋한다.
- 검토 스크린샷은 로컬 `.tools/redesign-review/`에 보관하며 Git에는 포함하지 않는다. 기존 `2026-10-31-local-develop-sync.md` 미커밋 기록은 변경·스테이징하지 않는다.

### 후속 요청: 소셜 로그인 버튼
- 사용자 예시와 정정에 따라 이메일 로그인 아래에 Google → 카카오 버튼을 세로 배치했다. 별도 카드 대신 같은 로그인 카드 안에 구분선과 버튼을 배치하고 회원가입 화면에도 동일하게 적용했다.
- Google 다색 G/흰색 배경/테두리, 카카오 말풍선/노란색 배경(#FEE500)을 적용했다. SVG 로고는 외부 요청 없이 렌더링한다. 기존 제공자 활성 여부와 OAuth 이동·복귀 경로는 유지했다.
- 참고 자료: [Google 브랜드 가이드](https://developers.google.com/identity/branding-guidelines), [카카오 로그인 디자인 가이드](https://developers.kakao.com/docs/ko/kakaologin/design-guide). 문구는 사용자가 요청한 '계속하기'를 사용한다.
- PC·390px 실화면에서 세로 배치와 동일 크기를 확인했다. 320px에서도 가로 넘침이 없었으며 `npm run ci` 전체 통과(20개 테스트, 빌드 포함). 외부 계정 로그인은 다시 수행하지 않았다.
- AI 구현 보조이며 팀 검토 대기. 최종 스크린샷은 `.tools/redesign-review/login-social-mobile.png`에 보관한다.
- 후속 색상 조정: 사용자 승인에 따라 Google 버튼 테두리를 `#747775`에서 `#b8b0aa`로 밝게 변경했다. 입력란의 `#d8d1cc`와 같은 따뜻한 회색 계열이며 입력란보다 진한 경계를 유지한다. CSS 색상만 변경하여 Prettier 및 Git 공백 검사를 수행했으며 기능 테스트는 재실행하지 않았다. 위 스크린샷은 이 색상 조정 전 기록이다.

### 후속 요청: 벽돌 층별 엇갈림

- 사용자 벽돌 사진과 요청에 따라 지정한 `feature/frontend-responsive-redesign-20261101` 브랜치에서 수정했다. 기존 브랜치 작업이 PR #16으로 병합된 것을 확인하고 최신 develop까지 전진시켜 새 PR에는 이번 수정만 포함되게 했다. 기존 미커밋 지침·동기화·검토 기록은 보존하며 포함하지 않는다.
- 같은 열에 세로 이음새가 겹치던 4열 배치를, 한 층씩 반 칸(15.5 SVG 단위) 이동하는 배치로 바꿨다. 이동한 층의 양끝은 벽 폭에 맞는 반쪽 벽돌로 마감한다. 건축 단계별 채움·지붕·문·창문 조건은 유지했다.
- 실제 BrickHouse 컴포넌트를 임시 검토 화면에 렌더링해 1~5단계의 이음새 엇갈림과 벽 경계를 브라우저로 확인했다. 검토 화면은 삭제했고 캡처는 Git에서 제외된 `.tools/redesign-review/brick-staggered-stages.png`에 남겼다.
- `npm --prefix frontend run ci`: 포맷·린트·타입 검사, 23개 테스트, 프로덕션 빌드 통과. 작은 SVG 배치 변경이므로 구현을 그대로 반복하는 추가 테스트는 만들지 않았다.
- AI 보조 구현·시각 검토이며 사진의 재질까지 복제한 작업은 아니다. 단계별 집 표현은 기존 벡터 스타일을 유지한다. 별도 사람 검토 및 사용자 효과 평가는 미실시다.
- 후속 피드백으로 지붕 아래 삼각형 벽면에도 같은 벽돌 패턴을 연장했다. 경사 경계로 잘라 지붕 밖으로 나오지 않게 하고, 1~3단계는 미완성 윤곽, 4~5단계는 채워진 벽돌로 표시한다. 실제 컴포넌트의 5단계 화면을 다시 확인했으며 캡처는 `.tools/redesign-review/brick-staggered-gable-stages.png`다. 프론트엔드 CI 23개 테스트·빌드를 다시 통과했다. 동일한 디자인 작업의 별도 PR #17에 추가한다.
