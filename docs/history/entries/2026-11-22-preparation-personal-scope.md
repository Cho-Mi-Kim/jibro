## 배경·문제

사용자는 신청자 질문의 답변 결과에 따라 내 준비의 조건·서류·일정에 해당 내용과 공통 내용만 표시하도록 요청했다. 서류는 이미 필요 여부가 계산되고 있었지만 조건·참고 안내·일정 및 현재 진행률은 전체 항목을 포함했다. 입력 질문 분리는 직전 applicant-guidance 작업이며 이번에는 표시 범위와 파생 일정을 연결했다.

## 고려한 선택지

- 화면마다 제목을 검색해 숨김: 화면·진행률·시연 모드의 규칙이 달라질 수 있어 채택하지 않았다.
- 별도 분류 데이터와 저장 형식 도입: 현재 확인할 수 있는 답변·서류 연결과 공식 접수 회차 자료를 먼저 사용한다. 근거 없는 공고별 분류를 생성하지 않았다.
- 기존 서류 필요도 유지, 공통 정책으로 확실한 비해당만 제외: 채택. 미응답·모름·모순·검수·분류가 불명확한 항목은 보존한다.

## 결정·이유

Java `PreparationApplicability`와 프런트 `housing/preparationApplicability`가 표시 범위의 소유자다. 서버와 서버 없는 시연이라는 실행 경계가 달라 두 구현을 두되 공통 어휘와 독립 기대값 사례로 대조한다. 서류 필요도는 기존 계산을 재사용한다. `currentPreparationScheduleSource`가 현재 버전의 선택된 접수 방식에 맞춘 날짜를 계산하고 모든 일정 소비자가 이를 사용한다.

이는 표시 및 현재 진행률의 의미 변경이다. 공고 원문·자격 기준과 저장된 질문·답변·서류 메모·일정 완료·이전 보관 기록은 수정하지 않는다. 자격 불충족은 비해당으로 숨기지 않는다. 답변 수정 화면에는 원래 질문을 남겨 다른 유형으로 바꿀 수 있다.

- 제거: 시연 준비 생성 시 공고에 서류·일정이 있어도 전역 예시를 대신 사용하던 경로와 답변 평가 시 전역 서류 연결을 참조하던 경로. 공고별 준비 스냅샷의 자료와 연결 규칙을 사용한다.

- 임시 코드: 없음. 범용 NLP 추론·외부 API·새 예약 실행은 추가하지 않았다.

## 리뷰 처분

독립 읽기 전용 검토에서 발견한 5건은 모두 수정 확인했다.

1. 목록 경량 준비가 최신 공고 상태를 놓침 → 현재 버전·검수 상태를 포함해 상세와 일치.
2. 신청 유형과 일반공급/주거약자 등 다른 분류 축 혼동 → 전체 선택지의 동일 분류 범위에서만 제외.
3. 온라인·현장 혼합 또는 부정 문구를 단일 방식으로 오인 → 모호한 채널과 비접수 일정 보존.
4. 개인 회차를 숨겨도 대표·다음·캘린더에 전체 마감일이 남음 → 동일한 개인 일정 출처 사용, 선택 방식의 미확인 경계는 다른 방식에서 가져오지 않음.
5. 같은 날짜의 미확인 시각을 자정으로 대입 → 대표 날짜부터 선택하고 시각 미확인 회차가 함께 있으면 대표 시각을 단정하지 않음.

최종 읽기 검토에서 추가 P1/P2 결함은 없었다. 전용 Iron Laws 도구 및 기존 GPT Pro 검토 세션은 제공되지 않아 실행하지 않았고 저장소의 서식·린트·계층·순환·타입 검사를 실행했다. 이를 해당 외부 검토 완료로 표현하지 않는다.

## 같은 날 후속: 이전 준비 기록의 표시 범위

사용자는 이전 준비 기록에도 보관 당시 답변에 해당하는 조건·서류·일정과 공통 내용만 표시하도록 개정했다. `HistorySnapshot`의 전체 목록 사용을 공통 정책으로 교체하고, 서류는 저장된 필요도가 비해당인 항목만 제외한다. 조건의 당시 선택지·숫자 기준·공통 참고 안내와 미확인 항목은 보존한다. 표시되지 않는 항목의 메모와 완료 기록을 원본에서 삭제하지 않는다.

일정은 최신 공고를 가져오는 방법을 배제했다. `snapshotPreparationScheduleSource`가 보관된 준비만 받고 `currentPreparationScheduleSource`와 같은 내부 계산을 사용하도록 기존 계산을 옮겼다. 요약과 개별 회차는 같은 개인 날짜·시각을 표시한다. 공개 공고 일정과 저장 일정의 완료 필드는 타입으로 구분하며, 한쪽만 개인화됐을 때 다른 공통 날짜를 잃지 않도록 보관 일정의 대표 경계를 유지한다. 추가 API·서버 변경·별도 일정 계산 경로는 없다. 임시 코드 없음.
