# 백엔드 시작 실패: 중지된 PostgreSQL 복구

- 기록일: 2026-10-31 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 해결
- 유형: 문제 해결 / 문서
- 담당·검토: 사용자 오류 로그 제공, Codex 실행 조사·복구·문서화, 팀 검토자 미확인
- 관련 이슈·PR·커밋: 미등록

## 배경·문제

사용자는 Start-Backend.ps1 실행 실패와 깨진 한글 경로를 보고 경로가 원인인지 문의했다. 제공된 로그의 핵심은 SQL State 08001 및 localhost:15432 연결 거부였다.

## 고려한 선택지

- 한글 경로·출력 인코딩 문제: 프로젝트 이동 전 같은 경로에서 Gradle 실행을 확인했다.
- PostgreSQL 미실행: 실제 컨테이너 상태와 연결 준비 상태를 확인했다.

## 결정·이유

개발용 PostgreSQL 컨테이너가 Exited (255) 상태여서 기존 컨테이너를 재시작했다. 데이터 삭제·폴더 이동·키 변경은 필요하지 않았다. 컨테이너가 종료된 원인 자체는 이번 조사에서 확정하지 않았다.

## 변경·해결 과정

docker start로 jibro-housing-dev-postgres-1을 시작했다. 직후에는 연결을 거부했으나 이후 pg_isready가 accepting connections를 반환했다. 기존 Start-Backend.ps1로 백엔드를 다시 실행했다. 개발 환경 안내에 백엔드 실행 전 DB 시작 단계와 해당 오류의 확인 방법을 추가했다.

## 검증·결과

- 동일한 한글 경로에서 gradlew.bat help 성공.
- Docker 상태 조회: 개발 DB 중지 확인, 재시작 후 pg_isready 성공.
- 백엔드 로그: PostgreSQL 17.6 연결, Flyway 3개 마이그레이션 검증, 스키마 최신 상태 확인, Tomcat 8080 시작 및 Started JibroApplication 확인.
- Codex 제한 환경에서는 별도의 Gradle 통신·HTTP 소켓 접근 오류가 발생했다. 제한 밖의 Gradle 및 백엔드 실행은 성공했으며 이를 사용자의 DB 오류와 구분했다.
- 전체 기능 테스트 및 실제 OAuth·LH 연동은 이번 범위에서 수행하지 않았다. HTTP 상태 API 확인은 제한 환경의 소켓 접근 오류로 완료하지 못했다.

## 기여·한계

사용자가 제공한 오류 로그와 AI 보조 실행 조사를 기반으로 작성했다. 깨진 한글 로그의 표시 문제는 별도로 남아 있으며 런타임 성공과 구분한다. 기존 사용자 수정 파일은 보존했다.

## 발표·포트폴리오 메모

표시상 경로 깨짐과 실제 연결 오류를 구분하고, DB 프로세스 상태와 백엔드 시작 로그로 원인과 복구 결과를 확인했다. 개인 성과로 사용할 때는 실제 담당·검토 범위를 별도로 확인한다.

## 후속 작업

- Docker 실행 후 DB 준비 완료를 확인하고 백엔드를 실행한다.
- 실제 외부 서비스 인증·수집 검증은 별도로 진행한다.
