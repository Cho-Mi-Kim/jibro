# 실제 LH 공고 기반 공고 찾기 전환

- 기록일: 2026-11-01 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 해결
- 유형: 개발 / 의사결정 / 데이터 검증
- 담당·검토: Codex가 공식 자료 조사·구현·검증 보조. 팀 담당자 및 별도 사람 검토자 미확인.
- 관련 브랜치: `feature/official-notice-catalog-20261101` (기존 반응형 재디자인 브랜치에서 분기)
- 데이터·API 커밋: `7eb90e2`. 원문 링크·확인일·공식 일정·반응형 줄바꿈은 후속 화면 커밋으로 분리했다.

## 배경·문제

사용자가 실제 공고를 찾아 공고 찾기 페이지에 반영하도록 요청했다. 로컬 DB의 기본 검수 통과 공고는 가상 예시 3건이었으며, 기존 LH 자동 수집 276건은 HOLD/HOLD 상태였다. 목록에 날짜가 있어도 게시 기간인지 신청 접수기간인지 확인이 필요했다.

## 고려한 선택지

- 기존 수집 자료 일괄 공개: 신청 일정·개인별 안내 검수가 없어 채택하지 않았다.
- 화면의 예시 문자열만 교체: 실제 검색 API·DB와 내용이 달라지므로 채택하지 않았다.
- 공식 상세 원문을 확인한 소수 자료를 재현 가능한 파일로 보존하고 DB에 추가: 채택했다. 이후 자료 확대를 막는 수량 제한은 두지 않았다.

## 결정·이유

전국 청년 전세임대 1순위 수시모집, 서울 3차 청년 매입임대, 경기남부 3차 청년 매입임대 정정공고를 선정했다. 공식 기본 정보를 대조하여 PASS, 개인별 준비 안내는 HOLD로 함께 기록했다. 접수 종료 공고도 실제 과거 일정과 후속 발표 확인을 위해 유지했다. 출처·확인일·한계는 `data/notices/README.md`와 JSON에 기록했다.

## 변경·해결 과정

- 로컬 전용 명시적 가져오기 스크립트: 출처·날짜 검증, 적용 전 공개 공고 백업, 동일 panId 중복 방지, 기존 데이터 덮어쓰기 금지.
- 기본 검색·필터에서 local-sample 공고를 제외했다. 개발 검증은 includeSamples=true로 예시를 조회하며 기존 상세·준비 기록을 유지한다.
- Notice API에 공식 schedules를 추가하여 준비 안내가 보류되어도 기본 검수된 일정을 표시한다. 개인별 질문·서류는 공개하지 않는다.
- 목록에 원문 확인일과 공식 원문 링크를 추가했다. 실제 공고명 줄바꿈을 보완하고 상세 일정에서 발표 종류를 구분했다.
- 8080 서버가 예전 검증 프로세스와 달라 최초 재시작은 안전 검사에서 중단됐다. 실행 경로·프로젝트 경로·org.jibro.JibroApplication을 확인한 뒤 해당 개발 서버만 새 빌드로 재시작했다.

## 검증·결과

- 데이터 파일 검증 및 로컬 적용 2회 성공. 공고 279→282건, 재적용 후 동일 282건. 기존 개인 준비 6건 유지.
- Gradle test / integrationTest / bootJar 통과: 단위 10건, 통합 13건. 새 회귀 검사는 예시 검색 제외와 기존 준비 보존, 기본 검수 일정 공개와 개인 안내 차단을 검증한다.
- 프론트엔드 npm run ci: 포맷·린트·타입·20개 테스트·빌드 통과. 마지막 화면 보완 후 재검사도 통과했다.
- 실행 API에서 실제 공고 3건, 접수 중 1건·접수 종료 2건, 전건 REVIEWING / canStart=false 확인.
- PC 브라우저에서 서울 필터 1건, 전세 검색 1건, 공식 링크와 전세임대 상세 요약 확인. 390px 모바일에서 목록·줄바꿈·하단 메뉴를 확인하고 가로 넘침 없음(문서 폭 375px)을 확인했다. 결과 화면은 로컬 `.tools/redesign-review/official-notices-{desktop,mobile}.png`에 저장했다.
- 재시작 후 HTTP 검사: 기본 목록 3건, 접수 중 1건, 서울 1건, 예시 포함 6건, 서울 공식 일정 3건, 개인별 안내 비공개 확인.

## 기여·한계

공식 웹페이지의 기본 필드 대조는 AI 보조 결과이며 사람의 자격·서류 검수 완료로 표현하지 않았다. PDF 전체 검수, 자동 수집 분류 확대, 주기 갱신, 조기 종료 감지는 이번 범위에 포함하지 않았다. 날짜 단위 API는 당일 마감 시각을 반영하지 못한다. 신청 전 공식 원문 확인이 필요하다.

## 발표·포트폴리오 메모

가상 데이터 기반 화면을 실제 출처가 있는 검색 화면으로 전환하면서 기존 개인 준비 기록을 보존했다. 기본 정보와 준비 안내 검수 상태를 나누어 미검수 안내가 신청 가능 판단으로 오인되지 않도록 했다. 사용자 효과나 개인 기여 수치는 검증하지 않았다.

## 후속 작업

### 같은 날 화면 피드백 반영: 일정 구분선

사용자 요청에 따라 공고 찾기·상세의 2×2 일정 배치에서는 공고일에도 다른 항목과 동일한 왼쪽 구분선·여백을 적용했다. 한 줄 배치의 첫 항목은 구분선 없이 유지한다. 전체 공통 규칙을 변경하는 대신 해당 화면과 기존 2열 전환 조건에만 스타일을 추가했다. 다른 준비 화면의 표현은 변경하지 않았다.

브라우저에서 390px 목록 및 상세 일정 탭의 2열은 네 항목 모두 1px 선/8px 여백, 1280px 상세 요약의 2열은 모두 1px 선/18px 여백임을 확인했다. 1280px 목록과 390px 상세 요약의 4열에서는 첫 항목이 0px 선/0px 여백으로 유지됐다. CSS Prettier 검사와 git diff --check 통과. CSS만 수정하여 별도 자동 테스트는 추가하지 않았다.

### 같은 날 화면 피드백 반영: 목록 이동 링크

사용자 요청에 따라 공고 상세 상단의 `공고 > 공고 상세` 링크를 왼쪽 화살표와 `공고 목록 보기`로 단순화했다. 이동 대상 `/notices`와 기존 스타일은 유지한다. JSX 변경 내용을 확인하고 Prettier 및 git diff --check로 검증했다. 문구·아이콘 수정이므로 별도 테스트는 추가하지 않았다.

- 매입·전세임대 분류(13), 장기 수시모집을 포함한 수집 범위 및 갱신 전략 보완.
- 공고 PDF·정정 이력 대조와 개인별 질문·제출서류의 별도 검수.
