# 개별 결과 발표 설명의 미래 자동 수집 반영

## 배경·문제

사용자가 미래 수집 공고에서도 공식 원문의 개별 발표 설명을 공고별로 반영하고 접수종료는 제외하도록 요청했다. 이전 작업은 공개 공고를 직접 대조한 수동 반영이며 이번 작업은 자동 검수 파이프라인 변경이다.

## 선택지·결정

공통 10주 기본값, 날짜 추정, 개별 통보라는 단어만으로 분류하는 방식을 제외했다. 원문에서 결과 발표 주체와 기간·예외·전달 방식을 함께 확인하는 제한된 문법을 채택했다. 다열 PDF를 임의로 재조합하지 않고 HWPX는 기존 검증된 구조 읽기를 공유한다.

## 변경·해결

- IndividualAnnouncementCompiler: 전체 문맥·URL·SHA·위치·추출 상태가 있는 공식 자료의 결과 안내를 설명 일정으로 생성. 계약·소명·부정문은 제외.
- IndividualAnnouncementTableReader: HwpxContextReader 검증을 재사용해 최종 발표 헤더와 동일 열 값의 관계 확인. 병합 열·손상 구조·계약 열 제외.
- AutomaticScheduleCompiler: 동일 설명 중복 제거, 서로 다른 설명과 고정 발표일 충돌은 결과 발표만 검토 대상으로 격리. 지난 마감 공고의 개별 결과 추가 제외.
- 기존 종료 제외 대기열/게시 잠금, 수동 원고 보호, 빈 날짜 일정의 캘린더 제외 계약 유지.
- 캐시 정책 갱신. 최초 긴 정책 이름으로 합성 키의 DB varchar(100) 제한을 넘긴 통합 테스트 실패를 확인해 source-review-v8로 줄인 후 재검증했다.

## 검증·결과

- 관련 검수 단위 테스트 314개, PostgreSQL 통합 테스트 33개 통과. 새 테스트는 4주/조건부 10주/단축·연기/SMS·이메일, 표의 예정 월, 계약·소명·부정문·출처 부족, 종료 제외, 기간·날짜 충돌, 중복, 실제 자동 검수→공개 API 저장→재시도 버전 보존을 포함한다.
- 기존 수집 원문 20개 읽기 전용 재생: 신혼Ⅰ/Ⅱ·다자녀 설명 추출, 남원노암의 상이한 출처 표현 포착. 과거 평택·안성 평탄화 표는 추정해서 읽지 않음. 이 재생을 20개 전체 자동 승인으로 표시하지 않는다.
- bootJar 및 git diff --check 통과. 새 backend-individual-auto-v8.jar로 5173 연결 백엔드 교체, 프런트 HTTP200·API/DB UP.
- 별도 bootRun/Vite 중복 실행 시 포트 사용 중을 확인했으며 기존 서비스 위치를 확인한 뒤 백엔드만 교체했다. 프런트는 기존 실행 유지.
- 준비 기록 0행 해시 동일. 종료 27행 전체 해시는 기존 수집 작업의 collected_at 갱신과 겹쳐 달라져 무변경 검증으로 주장하지 않는다. 이 구간 종료 공고 자동 검수 감사 기록 0건을 별도로 확인했다.
- 실행 자료: .tools/qa/automatic-individual-announcements-20261110/{replay.json,runtime.json,before.txt,after.txt}. 실제 기기 UI 재검증은 하지 않았으며 UI 코드 변경 없음.

## 기여·한계

AI 보조로 구현·테스트·로컬 실행했다. 인간 담당자·검토자는 미확인. 읽을 수 없거나 지원 문법 밖인 문서까지 자동 해석한다고 주장하지 않는다. 정정 관계와 전체 근거 검증을 통과한 범위에만 게시한다. 원격 배포·커밋·push 없음.

## 발표·포트폴리오 메모

공식 문장의 개별 발표 조건을 날짜와 분리한 모델에 연결하고, 출처 충돌을 선택하지 않고 해당 항목만 격리했다.

## 후속 작업

새 원문 형식은 근거·회귀 예제를 확인해 문법을 확장한다. 운영 서비스 배포는 별도다.
