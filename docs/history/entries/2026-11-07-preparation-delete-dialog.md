# 준비 기록 삭제 팝업 UI 정리

- 기록일: 2026-11-07 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 해결
- 유형: 개발 / 의사결정
- 담당·검토: 사용자 요청, Codex 구현·검증, 담당자 최종 검토 미확인
- 관련 이슈·PR·커밋: 미등록, 로컬 반영만 수행

## 배경·문제

사용자가 준비 기록 삭제 팝업의 UI 개선을 요청했다. 기존에는 공고 제목과 긴 삭제 안내가 비슷한 문단으로 이어지고, 하단 버튼의 모양이 사이트의 다른 팝업과 달랐다.

## 고려한 선택지

간격·버튼 스타일만 조정하는 방법과 삭제 대상·영향·입력을 시각적으로 구분하는 방법을 검토했다. 삭제 확인 단계를 줄이는 방식은 요청 범위에 포함하지 않았다.

## 결정·이유

삭제 대상 공고를 별도 영역에 표시하고 복구 불가 안내를 강조했다. 삭제 범위와 유지되는 기록은 짧은 문단으로 나누며 인증·명시 확인 절차는 유지했다.

## 변경·해결 과정

- 제목·닫기, 삭제할 준비, 주의 문구, 인증/확인 입력, 같은 너비의 취소·영구 삭제 순서로 정리했다.
- 입력칸과 버튼의 여백·모서리·색상을 기존 토큰에 맞췄다. 비활성 삭제 버튼은 중립 색상이며 활성화되면 기존 행동 색상을 사용한다.
- 모바일 입력 글자는 16px 기준이다. 중첩 라벨 기본 여백과 전역 dialog 최대 너비의 간섭을 전용 스타일로 정리했다.
- 팝업 설명을 복구 불가 문구와 연결했다. 삭제 API·인증 조건·revision·캐시 정리·취소 초기화는 변경하지 않았다.

## 검증·결과

- 타입 검사·변경 TSX의 ESLint 통과, Prettier 정리 완료.
- `npx vitest run src/features/preparation/PreparationDeleteDialog.test.tsx`: 기존 5개 테스트 통과. 명시 문구·비밀번호·메일 코드·취소 초기화·충돌·체험 확인 조건을 검사한다.
- 5173 브라우저에서 393×852·360×800 확인. 360px 기본 글자에서 팝업 내부 가로 넘침 없음.
- 360px 다크 모드·아주 큰 글자에서 내용과 버튼이 화면 안에 표시되고 가로 넘침 없음. 검증 후 표시 설정 복원.
- 확인 문구 입력 후 삭제 버튼 활성화, 취소 후 재진입 시 입력 초기화·삭제 버튼 비활성 확인. 실제 준비 기록 삭제나 메일 발송은 하지 않았다.
- 확인 이미지: `.tools/qa/preparation-delete-dialog/mobile-393.png` (로컬 산출물).

## 기여·한계

Codex가 UI를 수정하고 별도 에이전트가 스타일 간섭·검증 범위를 읽기 검토했다. 화면 검증은 브라우저 기준이며 실제 휴대전화·키보드·스크린리더 검증은 아니다. 실제 비밀번호/메일 계정의 화면 왕복은 자동 테스트로만 확인했다.

## 발표·포트폴리오 메모

삭제 대상과 영향을 구분하고 기존 명시 확인 절차를 유지한 팝업 개선 사례다. 사용성 개선 수치는 측정하지 않았다.
