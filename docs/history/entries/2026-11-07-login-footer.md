## 배경·문제와 고려한 선택지

직전 로그인 전체 화면 개선을 롤백한 뒤 사용자는 체험하기·안내·회원가입·비밀번호 재설정 부분만 지정했다. 전체 인증 화면을 재구성하지 않고 해당 영역의 그룹·간격·터치 크기만 조정했다.

## 결정·이유와 변경

체험 버튼과 설명을 흰색 카드로 묶고 버튼을 전체 너비·48px 이상으로 배치했다. 조건·서류·일정 설명과 기록 삭제/24시간 보관 안내는 별도 문단과 구분선으로 나눴다. 계정 링크는 카드 아래 중앙에 16px 간격으로 정렬하고 각각 44px 터치 영역을 확보했다. 좁거나 확대된 화면에서는 링크가 줄바꿈할 수 있다.

`TrialEntry`의 사용자·로딩·시연·trialAvailable 조건과 pending 비활성·시작 함수, 회원가입 returnTo·복구 주소는 유지했다. 버튼은 명시적으로 type=button이다. 변경은 `Auth.module.css`의 하단 영역 선택자와 `TrialEntry.tsx`, `AccountPages.tsx`의 링크 래퍼에 한정했다. 앞서 삭제한 로컬 배너와 위쪽 로그인 폼은 그대로다.

## 검증·결과

TypeScript·ESLint·대상 Prettier·모듈 경계 검사(10개) 통과. 실제 localhost:5173 비회원 화면의 393/360px에서 가로 넘침 없음. 체험 버튼16px/48px, 링크14px/44px 측정. 체험 시작이나 가입을 실행하지 않았고 기존 로그인 세션도 종료하지 않았다. 실제 휴대폰 확인은 아니다.

## 기여·한계와 발표 메모

지정 영역의 정보 묶음과 보조 동작을 정리한 UI 변경이다. 인증 구현이나 사용자 성과 개선 수치를 주장하지 않는다. 화면 캡처는 `.tools/qa/login-ui/footer-393.png`에 보관한다.

## 후속 요청: 소셜 버튼 주변 정리

사용자는 Google·카카오 버튼 UI를 유지하면서 주변 영역 개선을 요청했다. `AccountPages.tsx`의 구분 문구를 “또는 다른 계정으로”로 줄이고, 미연결 안내를 전용 `social-note` 클래스로 분리했다. 안내는 14px·중앙 정렬·두 줄 구성, 버튼 아래 12px·문장 사이 4px 간격을 사용한다. 구분선과 보조 글자는 기존 색상 토큰을 사용하고 구분선 아래 여백은 16px로 정리했다. 체험 카드와 계정 링크 구조는 유지한다.

Google·카카오 버튼의 마크업·동작·스타일 선언은 변경하지 않았다. 393px 브라우저에서 변경 전후 두 버튼의 너비 304.71875px, 높이54px, 글자15px, 배경·테두리·투명도가 동일함을 측정했다. 360px에서도 가로 넘침 없이 소셜 버튼54px·체험 버튼48px을 확인했다. TypeScript, ESLint, 대상 Prettier, 모듈 경계 검사10개 통과. 인증 제출이나 실제 외부 계정 연결은 실행하지 않았다. 실제 기기·글자 확대 검증은 하지 않았다. 캡처: `.tools/qa/login-ui/social-surroundings-393.png`.

TypeScript·대상 Prettier 통과, 별도 읽기 검토로 중복 없음과 경로 보존 확인. 393×852 브라우저에서 실제 순서를 확인했다. 캡처: `.tools/qa/login-ui/account-links-above-trial.png`.

사용자 후속 요청으로 소셜 연결 준비·이메일 이용 안내 두 줄과 사용되지 않게 된 `social-note` 스타일을 삭제했다. 소셜 버튼과 제공자 가용성에 따른 비활성 조건은 유지했다. TypeScript·대상 Prettier 통과, 393×852 브라우저에서 안내와 해당 여백 제거 확인. 캡처: `.tools/qa/login-ui/social-note-removed.png`.

추가 요청으로 TrialEntry의 ‘이메일 없이 예시 공고의 조건·서류·일정을 준비해 보세요.’ 문단을 삭제했다. 기록 삭제·보관 기간 안내는 유지하며 대상 Prettier 검사 통과. 이번 문구 삭제는 코드로 확인했고 브라우저를 재검증하지 않았다.

## 후속 요청: 홈 소개 카드 통합

사용자가 홈의 공고 확인·내 조건 정리·준비 이어가기 안내를 하나의 카드에 세 행으로 묶는 구성을 채택했다. `HomePage.tsx`에서 개별 Card 세 개를 하나의 Card와 의미 있는 순서 목록으로 바꾸고, 아이콘·제목·설명을 한 객체로 묶어 병렬 배열 인덱스 의존을 없앴다. `Home.module.css`의 전용 home-intro 스타일로 아이콘44px/왼쪽·텍스트/오른쪽, 제목18px·설명14px·설명 간격4px·행 간격20px을 적용했다. 기존 노출 조건과 대시보드에는 변화가 없다.

TypeScript, Prettier 정리, 모듈 경계 검사10개 통과. 별도 읽기 검토에서 공통 카드 스타일에 영향이 없음을 확인했다. 실제 브라우저 393×852·360×852에서 가로 넘침과 하단 메뉴 겹침 없이 세 행이 표시됨을 확인했고 글자 크기와 간격을 측정했다. 실제 휴대폰·글자 확대 검증은 별도다. 캡처: `.tools/qa/login-ui/home-intro-rows-393.png`.
