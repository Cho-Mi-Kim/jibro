# 참고 시안에 맞춘 공고 목록 화면 정리

- 기록일: 2026-11-04 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 해결
- 유형: 개발 / 리팩토링 / QA
- 담당·검토: Codex 구현 및 별도 에이전트 문서·회귀 검토, 사람 검토자 미확인
- 관련 이슈·PR·커밋: 미등록, 로컬 변경만 수행

## 배경·문제

사용자가 첨부한 공고 찾기 이미지와 screenshot-to-code 스킬을 활용해 5173 공고 탭 첫 화면을 수정하도록 요청했다. GitHub 문서 우선, 모듈화와 QA, 기존 홈 수정 보존이 작업 조건이다. 실제 저장소는 `C:/Users/Administrator/Documents/jibro`, 시작 HEAD는 `ebccaa71bf2dc11671cdb0f5fc85409d768ce5cc`다. 시작 시 이미 다수의 미커밋 변경이 있었다.

## 고려한 선택지

- 시안의 고정 3건·가상 날짜·준비 중 상태까지 복제하는 방식은 실제 데이터·이미 구현된 기능과 충돌하므로 사용하지 않았다.
- 기존 전역 스타일에 규칙을 추가하는 방식 대신 목록·카드·날짜 CSS 모듈을 분리하고 사용되지 않는 이전 목록 규칙을 제거했다.
- 모바일에 네 날짜를 모두 한 행으로 넣는 방식 대신 문서의 보조 글자 14px을 유지하며 두 열로 배치했다.

## 결정·이유

검색창, 필터 3개, 결과 수와 비교 진입, 배지, 카드, 일정, 공식 링크와 페이지 이동의 시각 구조를 시안에 맞췄다. 화면설계서 3절의 본문색/브랜드색/글자 역할을 우선했다. 작은 글자에 브랜드색과 연한 벽돌색을 함께 쓰면 문서가 정한 대비 기준에 못 미치므로 접수 배지에는 본문색을 사용한다. 정렬·적용 필터 칩과 기존 기능은 유지한다.

## 변경·해결 과정

- `NoticePages`의 검색/결과 배치를 `NoticeList.module.css`로 분리했다.
- `NoticeCard`를 제목·메타 정보·관심 저장·날짜·행동·공식 근거 영역으로 구성하고 `NoticeCard.module.css`로 한정했다.
- `NoticeCardDates`와 해당 CSS 모듈을 추가했다. 실제 기간의 연도 중복만 줄이고 일정이 없는 항목은 생성하지 않는다.
- `NoticeFilters.module.css`를 시안의 3개 진입 버튼 배치에 맞췄다. 선택·취소·적용 로직은 유지했다.
- `Product.module.css`에서 실제 참조가 없어진 목록/카드/북마크 규칙만 제거했다. 홈·상세·공통 검색/날짜 규칙은 보존했다.
- `App.test.tsx`에 필터 임시 선택 취소, 복수 지역 OR, 정렬 보존, 페이지 초기화, 칩 해제 검증을 추가했다. 이전 사용자 요청으로 제거한 홈 전체 여정 버튼의 낡은 테스트는 준비 방법 버튼 기준으로 정정했다.

## 검증·결과

- `npm run ci`: 포맷·린트·타입 검사·테스트 8개 파일 39개·빌드 통과. 로그: `.tools/feature-qa/notice-redesign-ci.log`.
- 이후 문서 기준 글자/색상과 미사용 CSS 정리 후 대상 파일 Prettier 확인 및 `npm run build` 재통과. 이후 변경은 CSS뿐이므로 기능 테스트는 재반복하지 않았다.
- `git diff --check`: 오류 없음. 기존 파일의 CRLF→LF 안내는 존재한다.
- 실제 5173/8080 연결 브라우저에서 필터 닫기/적용/칩 제거·정렬·검색 결과 없음/초기화·미리보기·상세 왕복과 원래 제목 링크 포커스 복원·비교 화면 진입 확인.

- 모바일 결과: `.tools/feature-qa/notice-redesign-mobile-393.png`.

## 기여·한계

AI가 구현·정적 검토·자동 검사와 브라우저 크기 검증을 보조했다. 실제 모바일 기기, 모바일 키보드, 운영 환경, 글자 200% 확대는 검증하지 않았다. 관심 저장 API의 사용자 기록은 이번 수동 QA에서 변경하지 않았다. 기존 테스트 범위를 넘어 실제 메일·외부 서비스 연결을 검증한 것이 아니다. 시안과 다른 실제 긴 제목, 문서상 글자 크기, 유지된 미리보기/홈 링크로 카드 높이는 시안보다 커질 수 있다. 네이티브 플랫폼 화면은 변경하지 않았다.

## 발표·포트폴리오 메모

참고 시안의 목록 구조를 제품 문서와 실제 API 계약에 맞게 변환하고, 페이지/카드/날짜 표시 책임을 분리했다. 기능 회귀 테스트와 여러 브라우저 폭 검증을 수행했다. 사용자 효과나 개인 성과 수치는 측정하지 않았다.

## 후속: 393×852 두 안 비교

사용자는 393×852에서 시안과 더 가깝게 맞추도록 요청했다. 문서 글자 크기(제목 18px·보조 14px)와 시안의 작은 글자 비율 중 어느 것을 적용할지 확인하자, 두 안을 직접 보고 비교하고 싶다고 답했다. 따라서 기본 문서 기준은 유지하고 시안 비율안은 최종 채택하지 않은 비교용으로 추가했다.

- 공통: 모바일 필터 한 줄, 정렬을 결과 도구 행으로 이동, 제목 두 줄 표시·전체 접근성 이름, 카드 우측 44px 미리보기/관심 저장 조작 영역. 홈 선택과 원문 링크, 검수 중 공고의 추가 일정은 펼침 안으로 이동했다. 문서 H01의 목록 내 홈 선택 경로를 유지한다.
- A: `/notices`, 카드 제목 18px·보조 14px.
- B: `/notices?appearance=reference`, 모바일 제목 15px·메타 정보 12px·날짜 11px. 글자와 간격은 페이지 범위 CSS 변수로 분리하고 실제 데이터·상태는 A와 동일하다. appearance는 API 쿼리에 보내지 않는다.
- `/notice-comparison.html`은 A/B 앱을 각각 너비 393px·높이 852px으로 고정한 두 iframe에 표시한다. 내부 스크롤·검색·공고 조작이 가능하다. 비교용 작은 글자는 문서의 최종 개정으로 간주하지 않는다.
- 검증: `npm run ci` 8파일 39테스트 및 포맷·린트·타입·빌드 통과(`.tools/feature-qa/notice-393-comparison-ci.log`). 이후 비교 HTML/모바일 스크롤바·간격 조정 후 빌드 재통과. 홈 선택 테스트는 미리보기 진입을 추가하고 기존 기록 미생성 검증을 유지했다.
- 실제 브라우저에서 B의 공고 3건과 하단 안내·페이지 이동 표시, 펼침 시 홈 링크·추가 일정·공식 링크 표시를 확인했다. 비교 페이지 iframe 외곽 393×852, 카드 제목 계산값 A18/B15px을 확인했다. 실제 기기 및 글자 확대 검증은 미수행.
- 결과 화면: `.tools/feature-qa/notice-393-comparison.png`. 로컬만 변경, 사용자 최종 선택 대기.
- 최종 정적 검토에서 페이지 이동 시 API용 쿼리로 비교안 설정이 제거되는 경로를 발견해, 화면 URL 복사본에서 page만 변경하도록 수정했다. 브라우저에서 B안 page=1 → 이전 페이지 → appearance=reference&page=0 유지 확인. 이후 타입 검사·App.test 18/18·대상 포맷 검사 통과.

## 최종 선택: GitHub 문서 기준 A안

2026-11-04 사용자가 두 안을 본 뒤 “github문서대로 해줘”라고 확정했다. 카드 제목18px·보조/날짜14px·입력/버튼16px인 A안을 유지하고, 정렬 조작 글자도16px로 맞췄다. 시안 비율 분기·비교용 CSS 변수·임시 `public/notice-comparison.html`을 제거했다. 이전 appearance 쿼리가 남은 링크도 동일한 문서 기준으로 표시하며 업무 API에는 보내지 않는다. 배치·필터·미리보기·홈 선택·관심 저장 기능은 유지한다.

이번 정리의 대상 포맷 검사 및 프로덕션 빌드 통과. 앞 절의 테스트 결과는 당시 코드 결과이며 이번 작은 분기/스타일 제거에는 새 테스트를 추가하지 않았다. 최종 화면을 393×852 브라우저에서 확인했다. 로컬만 수정하고 커밋·push·배포하지 않았다.

## 제목 아래 공고 수·조회 시각

사용자 첨부 이미지에 따라 설명 문구를 실제 검색 결과의 `totalElements`를 사용한 “공고 N개를 확인해요.”로 바꿨다. 숫자는 브랜드색으로 강조한다. 아래에는 TanStack Query의 마지막 성공 응답 시각 `dataUpdatedAt`을 한국 시간으로 표시한다. 서버의 원문 수집 시각을 뜻하지 않으며 로딩/오류 시 임의의 개수나 시각을 생성하지 않는다. 대상 파일 포맷 정리 및 빌드 통과. 이 작은 문구 변경에 새 테스트는 추가하지 않았다.
