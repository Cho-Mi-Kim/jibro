# 공고별 지원 대상·지원 내용을 2~3문장으로 표시

- 기록일: 2026-11-10 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 해결
- 유형: 개발 / 문제 해결
- 담당·검토: AI 보조 구현·검증, 인간 검토자 미확인
- 기준: feature/launch-integrations-20261107 / e288a99, 기존 변경 보존

## 배경·문제

‘어떤 지원인가요?’에 공고별 요약 내용을 보여 달라는 요청이다. 기존에는 summary의 첫 문장만 표시하고 지원 대상·모집 내용·예외 등이 포함된 나머지 문장은 출처와 함께 접어 두었다. 자동 검수의 EvidenceGuidanceCompiler에는 공고 요약을 검수 작업 설명·원문 구간 수로 덮는 경로도 있었다.

## 고려한 선택지·결정

최초에는 서버의 기존 요약 전체를 기본 표시하고 출처만 접었다. 이후 사용자가 “전체 내용을 다 보여주는 게 아니라, 지원 대상이랑 어떤 지원을 받을 수 있는지 위주로 2~3문장”이라고 범위를 명확히 했다. 이 최신 요청을 적용해 현재 공개된 접수 중·예정 21건의 요약 원고를 다시 작성했다. 앞 문장만 자르거나 지원 유형으로 자격·금액을 추측하지 않고, 공식 PDF와 기존 검수된 조건에서 대상·지원 방식·필요한 비용 또는 예비입주 의미를 골랐다.

## 변경·해결 과정

- `frontend/src/features/housing/NoticeSupportSummary.tsx`를 분리하고 NoticeDetailContent에서 사용한다. 요약을 details 바깥에 표시하고 우측 상단 버튼으로 EvidenceLink만 펼친다. 모바일 긴 문장을 위해 본문은 카드 전체 너비를 사용한다.
- `EvidenceGuidanceCompiler`는 기존 공고 요약을 보존한다. 검수 구간 수가 공고 내용 대신 표시되는 덮어쓰기를 제거했다.
- `NoticeSummary.display`는 빈 요약·기존의 정해진 수집/처리 문구를 실제 기관과 공고명으로 대체하는 읽기 보정이다. 검수된 일반 요약은 그대로 반환한다. 관리자 원고·CLOSED에는 적용하지 않는다. DB 원고·revision·승인·개인 준비를 변경하지 않는다.
- 5173 연결 백엔드를 backend-notice-summary.jar로 재시작했다. 커밋·push·외부 배포 없음.

## 검증·결과

- NoticeDetailContent 프런트 테스트9 통과: 여러 문장·소수점·날짜·예외 보존, 출처만 접기, 조건/서류/일정 경로 회귀.
- NoticeSummary 및 EvidenceGuidanceCompiler 단위14 통과. bootJar 성공.
- 변경 TS ESLint, typecheck, frontend build 및 모듈 경계 검사10 통과. build에는 기존 크기의 500kB 이상 번들 경고가 남아 있다.
- 현재 OPEN/UPCOMING21건의 API 내용·요약·version은 전후 동일. CLOSED27건도 수집 시각 collectedAt을 제외한 응답 동일. 실제 자료는 `.tools/qa/notice-support-summary/validation.json`과 before/after JSON.
- 실제5173 브라우저393×852·360×800에서 요약 전체 및 출처 접기/펼치기를 확인했다. 360px 문서 가로너비360으로 가로 넘침 없음. 실제 기기·글자 확대는 별도 미검증.

## 기여·한계

AI가 기존 요약 표시·자동 생성 보존 경로를 수정했다. 현재21건의 공고 요약을 새로 작성하거나 원문 전체를 재검수한 것은 아니다. 요약이 없는 검수 중 공고는 확인된 기관·공고명만 제공하며 조건을 추측하지 않는다.

## 발표·포트폴리오 메모

요약 내용과 출처 공개 동작을 분리해 공고 내용이 첫 문장 뒤에 숨지 않도록 하고, 자동 검수가 내용 요약을 처리 통계로 덮지 않도록 했다.

## 후속 작업

수동 원고 편집 단계에서는 미래 공고 자동 요약을 포함하지 않았다. 이후 추가 요청에 따라 아래 ‘향후 수집 자동 요약’ 절에서 구현했다.

## 후속 사용자 수정 반영: 대상·지원 중심 2~3문장

- 2026-11-10 현재 접수 중·예정 21건을 각각 2~3문장, 115~183자로 편집했다. 일정·제출서류·검수 절차는 요약에서 제외했다. 신혼·신생아 전세임대는 대상과 LH 재임대 방식, 유형별 본인 부담을 구분했고, 예비입주 모집은 빈집 발생 시 순번에 따른 계약임을 유지했다.
- 요약 작성에 사용한 공식 PDF는 변경 직전 공식 상세 페이지에 여전히 첨부돼 있는지, 공개 상태가 종료되지 않았는지, 새로 받은 파일의 SHA-256이 대조한 파일과 같은지 21건 모두 확인했다. 전체 페이지를 다시 검수하거나 기존 남원 날짜 충돌을 해결했다고 주장하지 않는다.
- 로컬 전용 단발성 작업으로 현재 revision·원고·검수 상태를 재확인한 뒤 한 트랜잭션에서 summary를 수정했다. 내용 변경 계약에 따라 version/revision을 1씩 올리고 기존 출처 검수 이력에 SUMMARY_ONLY_EXPLICIT_EDIT 사유와 전후 원고·공식 출처를 남겼다. 앱 소스 코드는 이 후속 작업에서 추가 변경하지 않았다.
- 최초 Java 소스 직접 실행은 클래스 로더 접근 오류로 쓰기 전 중단됐다. 동일 소스를 컴파일해 실행한 두 번째 시도에서 21건을 원자적으로 반영했다. 중복 반영 없음.
- DB 비교: 기존 생성자가 빈 reviewIssues, reviewRequired=false, 선택 필드 null을 명시하는 직렬화 정규화를 제외하면 summary만 변경. 질문·서류·일정·확인 필요 항목의 의미와 API 응답은 보존됐다. API 변경 필드는 summary·version·guideVersion뿐이다. 접수종료 27건은 collected_at 제외 DB 지문 동일, 개인 준비 테이블 0행 지문 동일.
- 5173 실응답 21건의 요약이 편집 원고와 일치하고 모두 2~3문장임을 확인했다. 브라우저 393×852에서 신혼·신생아Ⅱ 요약 3문장 표시, 공식 근거 접기/펼치기, 가로 넘침 없음(문서 너비393)을 확인했다. 임시 화면 크기는 복원했다. 실제 기기 검증은 수행하지 않았다.
- 이 후속 작업은 데이터 편집이므로 앞 절의 단위 테스트·빌드를 다시 실행한 것은 아니다. 자료: `docs/reviews/2026-11-10-support-summaries.json`, `.tools/qa/notice-support-summary/brief/validation.json` 및 전후 원고. 커밋·push·외부 배포 없음.

## 향후 수집 자동 요약 구현

- 추가 요청: 앞으로 수집되는 공고도 지원 대상·지원 방식 중심 2~3문장 자동 요약, 종료 공고 제외.
- 선택: 외부 AI에 원문을 다시 전송하거나 제목에서 지원 조건을 추정하는 대신, 이미 검증된 원문의 모집 제목·자격 절·지원 제도 정의를 로컬에서 읽는 순수 요약 모듈을 연결했다. `SupportSummarySource` / `SupportSummaryRules` / `SupportSummaryCompiler`로 읽기·표현·조립 책임을 분리했다.
- `GuidanceReviewCompiler`의 게시 가능한 후보 생성 시 summary만 교체한다. 기존 일반/후속 자동 검수 경로를 함께 사용한다. 지원 금액·비율·연한은 만들지 않으며, 예비입주 의미가 명시된 경우에만 세 번째 문장을 추가한다. 대상 충돌·미지원/불완전 문맥·미대조 OCR·자격 정정의 옛 원문은 기존 요약 유지. API 호출·테이블·별도 예약 작업 추가 없음.
- 기존 접수종료 큐/게시 방어에 더해 원고의 공식 조기종료와 신청 마감 시각을 요약 전 확인한다. `AutomaticReviewEligibility.closed`의 순수 날짜 판정을 재사용하고 정책 키를 v10으로 올렸다. 구체 계약은 `docs/contracts/automatic-support-summary.md`.
- 검증: 관련 단위 464건 통과, PostgreSQL 자동 게시/경쟁/부분 안내 통합 43건 통과. 마지막 공식 종료 경계 보강 후 요약 전용 13건 재통과, bootJar 성공. 최초 테스트에서 잘못된 테스트 기준일·발췌 문장 경계를 발견하고 수정했으며 실패를 통과로 보고하지 않았다. Gradle 기존 폐기 예정 기능 경고 있음.
- 실제 공식 PDF 본문 21건을 쓰기 없이 재생해 모두 2~3문장 후보를 확인했다. 자동 게시 가능성이나 전체 원문 신규 검수 통과와 구분한다. 현재21건의 이미 편집한 API 내용/version 보존, 종료27건·개인 준비0행 DB 지문 보존. 새 수집 공고 유입을 실제로 기다려 승인한 것은 아니며 일반/후속 조립 경로는 자동 테스트로 검증했다.
- 5173 연결 백엔드를 `backend-support-summary-auto.jar`로 재시작(PID100956), health/DB UP 확인. 화면 수정 없음. 커밋·push·외부 배포 없음. 근거: `.tools/qa/notice-support-summary/automatic/validation.json` 및 로그/입력 재생 자료.


## 현재 수집 공고 재점검과 요약 단독 공개

- 사용자 요청: 현재 수집 공고의 누락·부실 요약을 보완하되 접수종료 제외. 검수 전 요약 공개와 문서 기준의 충돌을 확인했고, 사용자가 “공식 원문으로 확인한 요약만 공개하고 나머지 준비 안내는 검수 중 유지”로 결정했다.
- 범위: DB 18,922행 전체를 검수했다고 주장하지 않는다. 공개 OPEN/UPCOMING 21건과 공식 최신 상태가 활성인 후보를 합쳐 66건의 상세·현재 첨부 자료를 확인했다. 종료일 누락을 접수 중으로 추정하지 않았고, 상태 미확인 과거 목록과 접수종료 공고는 제외했다. 정정본/원공고가 별도 행인 경우 각각 계산한다.
- 결과: 기존 21건은 대상·지원 내용이 충분해 유지. 나머지 45건을 2~3문장, 113~187자로 편집했다. 그중 3건은 길었던 상시모집 설명을 줄였고, 42건은 누락/처리 안내에 머물던 요약을 보완했다. 공공임대·고령자·다자녀뿐 아니라 기업 기숙사 공급, 어린이집 운영자 모집을 개인 입주자 모집과 구분했다. 광주두암4 스캔 원문은 1·2·3·10쪽을 이미지로 대조했다.
- 반영 직전 45건의 공식 활성 상태·첨부 연결·새 다운로드 지문을 다시 확인했다. revision, 기존 JSON, 검수 상태, 종료 여부를 재검사한 단일 트랜잭션에서 content.summary와 version/revision만 수정했다. 이전 작업과 달리 JSON의 다른 필드 직렬화 형태도 바꾸지 않았다. 전후 요약·근거·보존한 검수 상태를 VERIFIED_SUMMARY_ONLY로 기록했다.
- 41건은 5173 공개 상세 API에서 새 요약을 확인했다. 기본 정보 검수 보류 4건은 내부 원고만 보완하며 계속 404. 다른 조건·서류·일정·확인 필요·변경 검토·검수 상태는 유지했다.
- 발견·수정: 기존 후속 검수 후보는 출처 검토 이력이 하나라도 있으면 제외하므로, 요약만 보완해도 남은 안내 검수가 멈출 수 있었다. FollowupReviewRepository에서 정확한 VERIFIED_SUMMARY_ONLY 범위만 제외 조건에서 빼고, 기존 전체 검수/수동 편집/관리자/차단 보호는 유지했다. 이전 SUMMARY_ONLY_EXPLICIT_EDIT 이력의 보호도 변경하지 않았다.
- 검증: AutomaticFollowupPublicationIntegrationTest 29건 통과, bootJar 성공. 신규 회귀 테스트는 요약만 검토한 HOLD 공고의 후속 처리 가능성과 전체 검수 이력이 추가됐을 때 기존 승인 대기 결과도 무효화되는 것을 확인했다. DB 전후 18,895행 대조에서 대상45건 외 18,850행과 대상의 나머지 모든 필드 동일. 종료27건 및 개인 준비0행의 별도 지문 동일. 기존 공개21건 응답도 동일. 실 API 45건의 요약/비공개와 미검수 질문·서류 비노출 확인.
- 실행: 5173 연결 백엔드를 backend-support-summary-audit.jar(PID100708)로 재시작하고 health/DB UP 확인. 화면 구조 변경 없음. 이번 단계의 모바일 실제 기기/브라우저 시각 검증은 수행하지 않았고 API와 기존 공개 경로를 확인했다. 커밋·push·외부 배포 없음.
- 자료: docs/reviews/2026-11-10-current-support-summary-audit.json 및 .tools/qa/notice-support-summary/current-audit/validation.json. 요약 편집은 AI 보조 공식 자료 검토이며 기관의 자격 확정이나 나머지 준비 안내 검수 완료가 아니다. 미래 미검수 공고의 요약만 별도 자동 승인하는 새 경로를 구현한 작업도 아니다.


## 요약을 한눈에 읽는 화면 구성
