# 캡스톤 포스터의 로컬 모바일 화면을 인쇄 해상도로 교체

- 기록일: 2026-11-16 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 해결
- 유형: 문서 / 사용자 피드백 반영
- 담당·검토: 사용자 요청, Codex 제작·검수 보조. 개인별 구현 기여와 최종 제출 담당자는 별도 확인
- 관련 이슈·PR·커밋: 미등록

이하 본문은 2026-11-16 제작 당시 단계별 기록이다. 각 단계의 파일 크기·검증 결과와 ‘커밋·푸시 없음’은 해당 시점의 사실이며 현재 공유 상태가 아니다. 2026-11-25 사용자의 문서 공유 요청에 따라 이 기록을 PR에 포함한다. 최종 산출물은 저장소 밖 `../output/poster/final-submission`에 보존하며 PDF·SVG·미리보기·제출 안내가 존재하고 PDF 크기가 마지막 기록의 5,743,638 bytes와 일치함을 확인했다. 이번 문서 검토에서 포스터 렌더링·인쇄 규격·QR 검사를 다시 수행하지 않았고 산출물이나 외부 제출 여부를 변경하지 않았다.

## 배경·문제

90×140cm 포스터의 로컬 모바일 화면이 기존 415~430px 너비여서 화면 속 작은 글씨의 인쇄 선명도가 부족했다. 사용자는 고해상도 재캡처와 스크롤 바 제거를 요청했다. 제작 도중 사례의 신청 유형을 대학생에서 `19~39세 청년`으로 변경하도록 요청했다.

## 고려한 선택지

- 기존 이미지를 확대하는 방식은 원본 글자의 디테일을 늘리지 못한다.
- 실제 로컬 화면을 높은 기기 픽셀 비율로 렌더링하면 모바일 배치를 유지하면서 글자의 실제 픽셀 수를 늘릴 수 있다.

## 결정·이유

Chrome 모바일 보기 430×932 CSS px, 기기 픽셀 비율 7에서 화면을 직접 PNG로 저장했다. 공개 Pages 시연이나 AI로 다시 그린 화면을 사용하지 않았다. 스크롤 바는 캡처할 때만 숨겨 제품의 일반 스크롤 사용성을 변경하지 않았다.

## 변경·해결 과정

- 기존 포스터 PDF·SVG·근거 문서를 출력 폴더 내 `build/before-hires`에 보존했다.
- 로컬 캡처용 계정에서 `19~39세 청년`을 선택했다. 대상 서류가 5개에서 4개로 바뀌고, 기존 2개 완료 기록에 따른 서류 완료율은 50%, 전체 준비도는 51%로 표시되는 것을 확인했다.
- 질문·서류 목록·내 준비 개요를 같은 사례로 다시 캡처했다.
- 캡처용 CSS는 백업 원본과 비교 후 복구했다. 제품 코드에는 변경이 없다.
- 저장소 밖 작업 폴더 `../output/poster`의 PDF·편집 SVG·미리보기·문안 및 검수 문서를 갱신했다.

`../output/poster/v17-concrete-wording`에 PDF·편집 SVG·미리보기·검수 기록을 생성했다. 전체 렌더에서 잘림·겹침 없음, PDF 90×140cm 1페이지 5,743,351 bytes, 한글 글꼴 포함·SVG 유효·QR 두 개 해독 및 HTTP 200·배치 오류 0건. 최초 네트워크 제한으로 URL 확인이 DNS 오류였으나 접근 허용 후 재검사 통과. 화면 764.5ppi 및 기존 버전 보존. 실제 인쇄·외부 제출·제품 코드 변경·커밋·푸시 없음.

사용자가 현행 v18을 최종 제출본으로 확정하고 마지막 검수를 요청했다. 소제목 ‘신청 준비·관리’와 기대 효과의 가운뎃점 수정까지 반영한 PDF·SVG를 `../output/poster/final-submission`에 복사하고 원본과 SHA-256 일치를 확인했다. 확정 문안·팀 정보·기술명에서 추가 오탈자는 발견하지 못했다. 디자인·문안은 변경하지 않았다.

최종 PDF를 2700×4200px로 직접 렌더링해 전체 배치를 검토했다. 900×1400mm 세로 1페이지, 5,743,600 bytes, 한글 글꼴 포함. MiKTeX의 pdfimages 보조 점검은 환경 권한 오류로 종료하고 pypdf의 PDF 내부 이미지·배치 직접 검사로 대체했다. 실제 종이 인쇄·외부 제출·커밋·푸시는 하지 않았다.
