# 공고 상세에서 검색 목록 위치 복원

## 배경과 결정

상세에서 목록으로 돌아오면 검색 주소는 복원됐지만 미리보기가 접히고 카드 쪽으로 다시 스크롤됐다. 기존 관심 공고의 위치 복원 기능을 일반 목록과 공유하고, 공고 탭은 방문별로 선택한 카드와 검색 도구의 펼침 상태도 기억한다.

## 변경

상세 링크를 누를 때 목록 주소·선택 카드·스크롤 및 끝 여백을 보관한다. 복귀하면 목록 데이터가 준비된 시점에 위치를 적용한다. 원래 목록을 알 수 없는 상세 진입은 기존 카드 찾기 동작을 따른다.

## 검증과 범위

로컬 5173의 Chrome 360·390·768px에서 검색어·지역 필터·정렬을 적용한 목록, 2페이지 마지막 카드, 기본 목록을 점검했다. 상세 일정 탭에서 화면의 복귀 링크와 브라우저 뒤로 가기를 사용했다. 캐시를 비워 목록을 다시 조회할 때도 카드, 검색 도구 상태, 스크롤 좌표와 화면 속 카드 위치가 복원됐다. 프론트엔드 빌드와 테스트 436개 통과.

## 기여와 후속 작업

Codex가 구현 및 브라우저 검증을 진행했다. 현재 방문에 대한 복원이며 팀 검토와 실기기 검증은 별도다.

## 비교 화면에서 목록으로 복귀

일반 비교 경로를 목록과 같은 방문 범위에 포함하고, 비교 링크에서도 펼친 카드·검색 도구와 스크롤을 저장한다. 비교 대상 선택과 해제는 원래 목록의 주소와 방문 키를 유지한다. 5173 Chrome에서 검색·필터를 적용하고 비교 대상을 바꾼 뒤 상단 버튼으로 돌아오는 경우, 2페이지 마지막 카드에서 브라우저 뒤로 가기, 모든 카드가 닫힌 목록을 확인했다. 각 경우에 스크롤 좌표와 펼침 상태가 일치했다. 빌드와 프론트엔드 테스트 437개 통과.

## 상세에서 비교로 복귀

두 비교 칸의 상세 링크는 방문 키와 비교 주소를 전달하고, 상세의 돌아가기 링크는 원래 일반 또는 관심 비교 화면으로 연결한다. 각 칸의 공고는 원래 주소에서 복구하며 필요한 비교 자료가 준비된 시점에 방문 좌표를 적용한다. 로컬 Chrome 360·390·768px에서 상세 일정 탭을 연 뒤 화면의 복귀 링크와 브라우저 뒤로 가기를 확인했다. 비교 자료 캐시를 비운 경우에도 양쪽 공고 순서와 실제 스크롤 좌표가 일치했다. 빌드와 프론트엔드 테스트 439개 통과.

## 비교에서 원래 상세 탭으로 복귀

상세의 공고 자료와 비교에서 비교를 열 때 원래 공고 주소·탭·방문 키를 전달한다. 비교할 공고를 변경하거나 해제해도 돌아갈 상세 주소는 유지한다. 상세 자료를 다시 불러온 후 원래 열었던 자료와 스크롤 여백을 적용하고 모바일 상세 패널 또는 데스크톱 창의 위치를 복원한다.

로컬 5173의 Chrome 360·390·768·1024px에서 핵심 요약·조건·제출서류·일정 탭을 확인했다. 상세 자료 캐시를 비운 후 비교 화면의 뒤로 링크와 브라우저 뒤로 가기로 복귀했을 때 스크롤 좌표와 공고 비교 링크의 화면 위치가 일치했다. 프론트엔드 빌드와 테스트 440개 통과.

## 수정 전후 비교에서 상세로 복귀

수정 전후 비교가 일반 비교와 같은 상세 방문 정보를 사용하도록 연결했다. 화면의 뒤로 링크와 현재 공식 근거 보기는 상세를 열었던 탭과 위치를 복원한다. 이전 공개본 선택은 복귀 주소에 영향을 주지 않는다.

로컬 5173에서 공개본 4개인 공고의 이전 공개본을 바꾼 뒤 상세 데이터를 다시 불러오는 조건으로 Chrome 360·390·768·1024px를 확인했다. 화면의 뒤로 링크·브라우저 뒤로 가기·현재 공식 근거 보기로 복귀했을 때 네 탭의 스크롤 좌표와 링크의 화면상 위치가 일치했다. 프론트엔드 빌드와 테스트 442개 통과.

## 일회성 조건 확인에서 상세로 복귀

저장하지 않고 이번만 확인 링크와 조건 확인 방법 선택을 상세 방문 범위에 연결했다. 질문 도중, 결과 확인 후, 시작할 수 없는 버전 안내에서 원래 상세 탭으로 돌아갈 수 있다. 일회성 답변과 결과는 화면을 벗어나면 지워진다.

5173의 실제 공고에서 직접 진입과 방법 선택을 거친 진입을 확인했다. Chrome 360·390·768·1024px에서 질문 및 결과 화면의 복귀 링크와 브라우저 뒤로 가기를 사용했고, 상세를 다시 조회한 후에도 네 탭의 스크롤 좌표와 펼친 자료 위치가 일치했다. 프론트엔드 빌드와 테스트 444개 통과.

## 내 준비에서 공고 상세로 복귀

공고 상세의 준비 이어하기를 누를 때 현재 탭과 스크롤 좌표, 펼친 자료를 저장한다. 내 준비에서 조건·서류·일정 탭을 이동해도 같은 공고의 복귀 링크를 유지한다. 개요의 공고 제목과 공고 확인 링크도 같은 위치로 돌아간다.

5173에서 체험 계정으로 실제 공고의 제출서류 탭을 확인했다. Chrome 360·390·768·1024px에서 브라우저 뒤로 가기, 세부 탭 이동 후 복귀, 공고 확인 및 제목 선택 모두 출발 시점의 좌표와 일치했다. 프론트엔드 빌드와 테스트 446개 통과.
전체 lint는 관심 공고의 SavedNotices.tsx에 있는 Fast Refresh 경고 1건으로 통과하지 않았다.

후속 수정에서 관심 공고 조회 훅을 저장 버튼 파일에서 분리해 Fast Refresh 경고를 해결했다. 전체 검사에서 추가로 발견된 30개 파일의 서식을 정리했고, 근거 자료 JSON 5개의 값이 저장소 기준과 일치하는지 확인했다. 프런트엔드 npm run ci 전체 통과(코드 형식, ESLint 경고 0건, 모듈 경계, 타입, 테스트 446개, 빌드). 원문 위치 재연결 테스트 2개도 통과했다.
