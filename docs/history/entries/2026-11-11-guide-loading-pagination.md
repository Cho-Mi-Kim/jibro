- Git 기준: feature/launch-integrations-20261107 / e288a99. 새 커밋·push 없음.

## 배경·문제

사용자가 사이트가 느리며 특히 탭 이동과 화면 로딩이 버벅인다고 확인했다. 로컬 health 6ms, HTML 2ms, 공고 목록 88ms 수준이었으나 가이드 응답은 20,980,715바이트였다. `GuideRepository`가 공개 공고 전체 Content를 읽고 Service가 가이드 전체를 조립했으며, 프런트가 모두 렌더링했다. 사용 중인 Chrome 가이드 탭 제어도 타임아웃됐다.

## 고려한 선택지와 결정

브라우저에서 표시만 줄이면 약21MB 전체 전송과 서버 전체 객체 생성이 남는다. 자료를 삭제하거나 가이드 전체 개수를 잘라내지 않고 서버 페이지 단위 응답과 프런트 페이지 교체를 함께 적용했다. 같은 조건의 전체 자료 검색과 기존 공개/검수 경계를 유지한다.

## 변경·해결 과정

- `/guides?category=&keyword=&page=0`은 `items`, `page`, `hasMore`를 반환하며 페이지 크기는20이다. 자료32건 단위로 읽고 충분한 결과를 찾으면 중단한다. 필터 후 페이지를 나눠 검색 결과가 첫32개 자료에 제한되지 않는다.
- 초기 구현에서 무검색 결과 조회가20초를 넘는 것을 확인했다. SQL에서 검색어가 있는 자료를 먼저 좁힌 후 Java에서 각 가이드에 정확히 매칭하게 보완했다. 서비스에서 생성하는 안내 문구·주제명과 JSON 이스케이프 문자는 후보 필터에서 제외해 실제 결과를 누락시키지 않는다. SQL 값은 바인딩한다.
- `GuidePage`는 현재20개 항목만 렌더링한다. 다음/이전 페이지, 주제 재선택 해제, 검색 시 첫 페이지로 복귀, 입력250ms 대기를 적용했다. `useGuides`로 요청 책임을 분리하고 별도 demo 어댑터도 같은 응답 형태로 맞췄다. 무제한 응답 경로는 제거했다.
- 관련 자동 요약 보완도 같은 실행본에 반영했다. 자세한 내용은 같은 날짜 `summary-plain-language` 기록과 자동 요약 계약에 남긴다.

## 검증·결과

- backend 요약/가이드 단위23·자동 게시 및 샘플 제외 통합15 통과. 검색 후보 SQL 보강 후 가이드 단위4·가이드 페이지/샘플 제외 통합3·bootJar 재통과.
- 프런트 GuidePage/App 40건, TS·변경파일 ESLint/Prettier, 계층 검사10건, production build 통과. 기존500kB 번들 경고와 Gradle 폐기 예정 경고는 유지.
- 로컬5173 첫 가이드 응답13,632바이트(약99.94% 감소), 첫/둘째 페이지 각각20개·ID 중복0, 검색20개·빈 검색0개. 최종 측정 첫 페이지83ms, 주민등록 검색711ms, 빈 결과666ms. 이 수치는 로컬 API 응답이며 실제 기기 체감 속도 수치가 아니다.
- API 기존62건의 요약·조건·서류·일정 및 버전은 이전 자료와 동일. 수집/확인 시각은 이전 스냅샷 이후 갱신된 항목이 있다. 재시작 전후 접수종료 공고·개인 준비 지문 동일. 데이터 삭제/일괄 재검수 없음.
- Chrome 기존 탭을 새로고침해 가이드 표시·공고 이동·가이드 복귀·검색·다음 페이지를 확인했다. UI 자동 클릭 일부는 CDP 입력 타임아웃이 있어 키보드 활성화와 실제 URL/화면으로 확인했다. 실제 기기 미검증.
- 실행본 `.tools/runtime/backend-guide-pagination-v2.jar`, 5173 프런트 및 health 정상. QA `.tools/qa/page-load-lag/validation.json`와 API 응답 파일.

## 기여·한계 및 후속

AI가 원인 조사·API/페이지 개편·테스트를 수행했다. 일반 화면 디자인/업무 규칙과 기존 사용자 선택을 보존했다. 페이지 번호 방식은 자료 갱신 도중 정렬 위치가 달라질 수 있다. 매우 깊은 페이지는 앞선 결과를 다시 읽으므로 운영에서 이 사용량이 커지면 전용 가이드 색인/커서 조회를 검토한다. 이번에 요청되지 않은 캐시 인프라나 자료 삭제는 추가하지 않았다.

## 발표·포트폴리오 메모

대량 수집 후 전체 자료 렌더링 병목을 API 응답량으로 확인하고, 검색 범위를 유지한 페이지 조회로 첫 전송량을 줄였다. 개인 기여 표기는 담당자 확인 후 사용한다.
