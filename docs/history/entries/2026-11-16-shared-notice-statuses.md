# 접수 상태와 준비 안내 상태의 공통 표시

공고 목록과 상세가 접수 중의 색상과 아이콘을 개별 선택했고, 비교표에서는 확인 필요 항목이 있는 공고에도 일반 제공 문구를 표시했다. 기존 펼침 동작과 공식 접수 상태 판정을 재사용하고 `noticeLabels.ts`에서 문구·아이콘·색상과 일부 확인 상태의 선택 기준을 관리하도록 했다. 홈·목록·상세·내 준비·비교가 같은 배지를 사용한다. 내 준비의 개인 진행 상태는 공고 상태와 함께 별도로 표시한다.

AI 보조로 실제 화면 경로를 연결하고 공식 조기 마감과 일부 확인이 동시에 있는 비교 사례를 검증했다. 프런트엔드 테스트 430건, 변경 파일 ESLint, 빌드 통과. 5173 Chrome의 360·390·768px에서 실제 공고와 격리된 개인 준비 테스트 기록으로 다섯 화면의 상태 문구와 아이콘 및 펼침·접힘을 확인했다. 브라우저 크기로 검증했으며 실제 기기에서는 확인하지 않았다.
관심 공고 카드에도 같은 목록 배지와 상태 갱신 주기를 적용했다. 저장 순서대로 현재 공개 가능한 공고 요약을 일괄 조회해 일반 목록과 같은 접수·검수·일부 확인 판정을 받는다. 체험 데이터도 공통 목록 구조를 쓴다. 프런트엔드 테스트 433건, 빌드, 회원·공급 지역·공개 범위·목록 조회·정렬·접수 시점 관련 통합 테스트가 통과했다. 5173의 임시 체험 계정에서 실제 7개 상태 조합을 대조하고 Chrome 360·390·768px에서 아이콘 위치, 왼쪽 펼침 및 바깥 클릭 닫힘을 확인한 뒤 체험을 종료했다.
사용자 요청으로 홈과 내 준비의 공고 카드는 공통 ApplicationBadge로 접수 상태만 표시한다. 공고 안내 배지를 함께 표시하던 기존 지침에 화면별 범위를 명시했다. 홈 두 경로, 내 준비 및 관심 공고에 대한 테스트 4개와 타입 검사가 통과했다.

## 공고 안내 버전 문구 제거

홈·내 준비·공고 상세·비교·보관함·이전 기록 및 검수 화면에서 안내 버전 번호를 제거했다. 이전 준비 기록은 저장 시각, 수정 전후 비교는 과거 공개 순서로 고른다. 데이터 조회, 기록 선택, 공고 변경 확인과 캘린더의 갱신 순서에는 기존 식별자를 사용한다. 캘린더 설명에는 공식 출처를 표시한다.

전체 프런트엔드 CI와 테스트 450개 통과. 5173에서 Chrome 390px로 실제 공고의 준비 안내 확인 현황을 펼쳐 표시를 확인했다.
