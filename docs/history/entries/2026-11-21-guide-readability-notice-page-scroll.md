# 가이드 줄바꿈과 공고 목록 페이지 스크롤

- 기록일: 2026-11-21 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 해결
- 유형: 화면 개선 / 리팩토링
- 담당·검토: Codex 구현·검증 보조, 사람 검토자 미확인
- 관련 이슈·PR·커밋: 원격 게시 없음

## 배경·문제

사용자는 공고 목록도 페이지를 넘기면 목록 맨 위로 0.75초 스크롤되게 요청했고, 이어 가이드 설명이 줄글로 계속 이어지지 않도록 줄바꿈을 요청했다. 두 요청을 함께 처리했다.

## 고려한 선택지·결정

가이드 공식 원고를 다시 쓰지 않고 표시 시 완결 문장 뒤 공백을 줄바꿈으로 바꿨다. 원고·DB·출처·검수 날짜를 유지하고 자동 수집 후 갱신되는 문장도 같은 표시 경로를 사용한다. 공고 페이지에는 가이드의 스크롤 로직을 복사하지 않고 공통 `usePageScroll`을 추출해 적용했다.

## 가이드 줄바꿈

`GuideAnswer`가 본문·목록 항목·적용 범위의 한국어 문장 끝에서 줄을 나눈다. 기존 문단 간격과 목록 구조, 날짜·시간·숫자·예외는 보존한다. 번호 목록은 1부터 연속되는 여러 행일 때만 해석해 `2026. 11. 21.` 같은 날짜를 목록 번호로 잘못 제거하지 않게 했다. HTML이나 임의 Markdown 실행은 추가하지 않았다.

## 공고 페이지 스크롤

`usePageScroll`은 클릭한 페이지의 자료가 준비될 때까지 기존 영역 높이를 보존하고, 목록을 고정 헤더·검색 도구 아래8px로 정렬한다. 공통750ms 토큰, 동작 줄이기, 사용자 스크롤 중단을 따른다. 검색 변경·이탈 때 정리하며 초기 진입·자동 재조회는 이동하지 않는다. 가이드도 같은 훅을 사용한다.

상세에서 돌아오는 기존 위치 복원은 유지한다. 페이지 버튼을 누른 경우만 현재 복원 상태와 선택 카드를 해제해 예전 카드의 자동 정렬과 충돌하지 않게 했다. 로딩 시 최종 업데이트 문구가 사라져 헤더가 약20px 줄던 현상은 해당 행의 최소 높이를 기존 문구 높이로 유지해 해결했다.

## 검증·결과

- 가이드 관련 표시 검사7개, 페이지·스크롤 검사11개, 공고 페이지 신규3개 회귀 검사 통과.
- 실제5173에서 가이드36개의 공백 제외 본문이 API 원고와 같고 문장별 개행이 적용되는지 대조했다.
- Edge390/1024px에서 공고 이전·다음 스크롤747~757ms, 헤더 아래 정렬,500ms 지연 동안 높이 유지 확인.
- 기존 가이드390/768px의 이전·다음·600ms 지연 및 동작 줄이기도 재검증했다. 실제 기기 검사는 아니다.
- 프런트 전체 CI의 85개 파일·655개 검사와 서식·린트·계층·타입·빌드가 통과했다. 기존 번들 크기 안내는 남아 있다. 실행 결과는 `.tools/qa/guide-breaks-notice-scroll`, 가이드/공고 개별 회귀는 `.tools/qa/guide-linebreaks`와 `.tools/qa/notice-pagination-scroll`에 보관한다.

## 기여·한계 및 발표 메모

2026-11-21 후속 요청으로 질문 카드를 native `details name` 그룹으로 묶어 하나만 펼치도록 했다. 이전 질문이 접히며 높이가 줄어드는 동안 기존 고정 스크롤 목표가 빗나가는 현상을 실제 화면에서 발견해 `alignQuestion`의 목표 위치와 하단 여백을 매 프레임 계산하도록 보완했다. 별도 펼침 상태나 중복 toggle 경로를 추가하지 않았다. 기존 기본 접힘·조회 조건 전환·자동 갱신 상태 유지는 보존한다. 관련 10검사·타입·린트·서식이 통과했다. jsdom 30은 name 그룹을 구현하지 않아 단일 펼침 동작을 가짜로 구현하지 않고 실제5173 Edge360/390/768에서 제목·여백·키보드 및 동작 줄이기로 검증했다. 앞/뒤/마지막 질문 전환에서도 헤더 아래8px 정렬과 약750ms 스크롤을 확인했다. 실행 자료는 `.tools/qa/guide-single-open`에 있다.

2026-11-21 후속 요청으로 가이드 첫 진입과 주제·검색·페이지 전환의 기본 상태를 모두 접힘으로 바꿨다. 첫 항목의 `open` 지정을 없애고 카드 키에 조회 조건과 질문 ID를 함께 사용했다. 같은 질문이 다른 주제에 포함되거나 캐시된 결과로 돌아와도 접혀서 시작하고, 같은 조회 조건에서 본문만 자동 갱신되면 사용자가 펼친 상태는 유지한다. GuidePage 관련 10검사·타입·변경 파일 서식·린트를 통과했다. 5173의 360/390/768px 브라우저에서 최초 진입, 주제 변경·선택 해제, 페이지 왕복, 검색·초기화의 접힘과 가로 넘침 없음을 확인했다. 실제 기기 검사는 아니며 실행 자료는 `.tools/qa/guide-default-collapsed`에 있다.

2026-11-21 후속 요청으로 자동 갱신 후에도 줄바꿈이 유지되는 경로를 다시 확인했다. 검증된 DB 원고부터 GuideService → useGuides → GuidePage → GuideAnswer까지 동일한 표시 경로이며 별도 형식 캐시나 우회는 없었다. 실행 로직은 이미 갱신 응답마다 줄바꿈을 계산하므로 중복 구현하지 않았다. 기존 화면 복귀 갱신 검사에 같은 ID의 새 본문·목록·적용 범위 및 날짜·시각·숫자·예외·출처 보존 검증을 보완했다. 관련 16검사와 변경 파일의 서식·린트가 통과했다. 외부 자료 갱신이나 AI 호출을 새로 실행한 검증과는 구분한다.

공식 내용과 표시 형식을 분리하고 동일한 페이지 이동 동작을 공통화했다. 사용자 만족도나 속도 개선율은 측정하지 않았다. 실제 미래 원고와 기기별 화면은 별도 운영 점검 대상이다. 백엔드·개인 기록은 변경하지 않았다.

## 후속 작업

추가 구현 없음. 가이드 문장 표시와 페이지 이동은 각각 공통 표시 함수·훅을 통해 관리한다.
