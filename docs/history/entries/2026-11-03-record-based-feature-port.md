# 준비 중 메뉴를 현재 사이트의 실제 기능으로 전환

- 기록일: 2026-11-03 (Asia/Seoul)
- 기록 상태: 실행 근거 정리·담당자 검토 전
- 작업 상태: 로컬 적용 및 검증 완료
- 유형: 기능 이식 / 계정·공고 계약 / 브라우저 검증
- 기준: `feature/local-mobile-screens-20261103`, HEAD `ebccaa7` 및 이 브랜치의 기존 로컬 변경

## 배경과 선택

사용자가 “이 Codex에서 진행했던 집으로 프로젝트 기록들”을 참고하되 예전 코드를 쓰지 말라고 요청했다. 이어서 준비 중인 기능을 전부 구현하고 싶다고 범위를 명시했다. “주거지원 준비노트 모바일 앱 구현”, “집으로 작업 기준 적용”, “모바일 웹사이트 처음부터 만들기”의 작업 결과와 당시 USER_FLOW·인계 문서에서 사용자 동작과 실패 시 기대 결과를 확인했다. 이전 앱의 코드, SQL, ZIP, 실행 중인 구버전 API는 가져오지 않았다. 현재 서비스의 React Router, Query, Spring 인증·검수·소유권과 PostgreSQL을 사용했다.

공고·계정 기능을 화면만 바꾸거나 브라우저에 개인 자료 전체를 저장하는 방안은 채택하지 않았다. 사이트 내 알림, 열린 브라우저 알림, 서버 발송, 캘린더 복사를 구분했다. 공식 일정·서류·로그인 정보의 실제 상태를 기준으로 동작한다. [로컬 계정 기능 계약](../../contracts/member-features.md)

## 구현

- 가이드 검색은 현재 공개된 공고 근거를 사용하고, 관심 저장·조회는 계정별 서버 데이터다. 선택 공고 비교와 공개본 버전 비교는 공개 상태를 검사한다.
- 서류는 원문·기관·검증된 발급 링크 또는 확인 경로를 제공한다. 일정은 선택한 항목만 iCalendar로 내보낸다. 검토 중인 개인 기한과 민감한 답변을 내보내지 않는다.
- 알림함·읽음·기한 설정, 명시적 기기 권한, 이메일 수신 설정, VAPID 브라우저 구독·해제, 발송 중복 방지와 재시도 기록을 분리했다. 현재 서비스 기본 발송 방식은 로컬 메일이다.
- 보관과 복원은 기존 준비 스냅샷을 유지한다. 경험 재사용은 소유자가 선택한 메모 참조만 추가하고 새 준비 건의 상태를 덮어쓰지 않는다.
- 설정에서 닉네임·선택 관심 지역과 비밀번호를 변경할 수 있고, 메일 확인·비밀번호 재설정·탈퇴는 단회성 링크를 사용한다. 접근 토큰과 갱신 토큰은 비밀번호 변경·재설정 및 탈퇴 후 사용할 수 없다.
- 회원 기능과 알림·메일 코드는 `backend/src/main/java/org/jibro/member/`, `auth/Account*.java`, 공개본 조회는 `notice/NoticeVersions.java`에 있다. 프론트 모듈은 `frontend/src/features/member/`, `features/preparation/CalendarExport.tsx`, `calendar.ts`, `IssueHelp.tsx`와 전용 페이지들에 있다. V6~V8은 기존 공고와 사용자 기록을 보존하는 추가형 마이그레이션이다.

## 검증과 한계

- 프론트 포맷·린트·타입·테스트 33개, 일반 및 Pages 빌드 성공. 서버 단위 10개·독립 PostgreSQL 통합 20개와 실행 JAR 빌드 성공.
- 별도 Chrome·DB·API로 가입, 관심 저장 후 새로고침, 읽음과 설정, 가이드 검색, 공고/공개본 비교, 캘린더 다운로드, 발급 근거 안내, 보관·복원·메모 연결, 프로필, 비밀번호 변경·재설정·재사용 거절, 이메일 확인·탈퇴를 확인했다. 8개 경로를 360·390·768·1280px 및 360px·기본 글자 200%에서 검사해 40개 조합에서 문서 가로 넘침이 없었다.
- 별도 iCalendar 파서로 실제 다운로드 파일을 읽어 종일 일정 2건·고유 UID·버전·공식 주소·75옥텟 줄 길이를 확인했다. 시각 있는 일정의 UTC 변환과 미확인 일정 제외는 단위 테스트에서 확인했다.
- 루프백 SMTP 수신기가 별도 검증 계정의 확인 메일과 예약 기한 알림을 실제로 수신했다. 미확인 이메일 수신 차단, 같은 이벤트 중복 발송 방지, VAPID 공개키·구독 등록/해제·잘못된 엔드포인트 차단을 확인했다. 외부 메일함, 원격 푸시 사업자 전달, 실제 휴대폰과 외부 캘린더 앱 가져오기는 검증 범위 밖이다.
- 실제 5173 서비스에서 DB·API 정상 상태를 재확인했다. 마이그레이션 전후 계정·준비 건·공고 행 수가 동일했다. 로컬 설치가 보존한 공개본 4개를 저장소의 검수 원고와 대조하여 추가했다. 현재 공고 3건 모두 비교 가능한 실제 공개 이력이 있다. 회원 검증용 데이터는 별도 테스트 DB에만 만들었다.
- 구현·검증은 Codex가 수행했다. 별도 이용자 효과 측정·사람 검토·원격 배포는 하지 않았다.
