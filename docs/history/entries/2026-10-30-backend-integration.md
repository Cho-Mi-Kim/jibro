# 백엔드 구현과 실제 API 연동

- 기록일: 2026-10-30 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 진행 중
- 사용자 요청: 기능별 계약에 따라 백엔드를 구현하고 프론트엔드를 연결한다. 기능 단위로 브랜치·커밋·push하고 미병합 작업의 PR을 만든다.

## 배경·문제

프론트엔드는 계약과 개발용 시연 흐름을 갖추었지만 실제 서버에는 DB 상태 확인만 있었다. 계정·공고·개인 기록과 검수 상태를 영구 저장해야 한다.

## 선택지·결정

- 인증은 JWT 접근 토큰과 DB에 해시로 보관하는 회전형 갱신 토큰을 채택했다. 브라우저에는 HttpOnly 쿠키와 메모리 접근 토큰을 사용한다.
- 회전 토큰의 단일 사용 보장을 위해 인증 저장소는 명시적인 JDBC 행 잠금을 사용한다. 공고 검색은 JPA·Querydsl을 사용한다.
- 개인 준비 기록은 공고의 버전별 스냅샷을 보존한다. 검수 전 안내 노출과 다른 소유자의 기록 접근은 서버에서 막는다.
- 외부 키가 필요한 소셜 로그인·공식 수집은 미설정 상태를 명시한다. 로컬 샘플 데이터와 실제 수집을 구분한다.

## 변경·해결 과정

- 계정·로그인 수단·갱신 토큰 스키마, 입력 검증, CSRF, JWT 발급·검증, 인증 API를 구현 중이다.
- 이메일이 같다는 이유만으로 소셜 계정을 자동 연결하지 않는다.

## 검증·결과

- 구현 진행 중. 최종 빌드·통합 테스트와 실제 화면 연결 결과는 완료 시 기록한다.

## 기여·한계

- 사용자: 요구사항과 구현·원격 게시 승인.
- AI: 계약 구체화, 코드·테스트·문서 작성. 사람 검토자 및 팀원별 기여는 미확인.
- 외부 제공자 키와 실서비스 정책 검수는 별도 운영 설정이 필요하다.

## 발표·포트폴리오 메모

단순 화면 시연에서 영구 저장·서버 권한 검증으로 확장하는 과정이다. 사용자 효과나 성능 수치는 측정 전이므로 주장하지 않는다.

## 후속 작업

도메인 API, 프론트엔드 연동, 통합 검증, 작업 단위 PR 생성.


### 인증 단위 검증
- Java 컴파일, 기존 단위 검사 2건, PostgreSQL 통합 검사 3건 통과. 토큰 회전·재사용 거절·로그아웃·일반 사용자 관리자 접근 거절·실제 CSRF 쿠키 쌍을 확인했다.
- 최초 DB 연결 실패는 중지된 프로젝트 컨테이너를 재시작해 해결했다. CSRF 테스트 도우미의 컨텍스트 변경은 테스트별 격리로 해결했다.

### 공고·개인 준비 단위
- JPA·Querydsl 복합 검색, 공개 필터, 공고별 질문·서류·일정과 출처, 버전별 개인 스냅샷, 준비도 및 집 단계 계산을 구현했다.
- 검수 결과와 검수자·시각을 보관한다. 구조화 내용 변경 시 공개 보류 및 재검수로 전환한다. 수정과 검수는 같은 공고 행 잠금으로 직렬화한다.
- 로컬 샘플은 명시적인 local-sample 프로필에서만 생성한다. 재시작으로 관리자의 검수 결과를 덮어쓰지 않는다.
- 단위 검사 2건, PostgreSQL 통합 검사 8건 통과. 검색 OR/AND, 소유권, 중복 방지, revision 충돌, 100% 준비도, 스냅샷 보존, 검수 공개 정책, 안전하지 않은 링크 거절을 확인했다.

### 수집·구조화 단위
- 공식 LH API 명세를 확인하고 관리자 실행형 자동 수집과 원본 목록 해시 변경 감지를 추가했다. 키 없음·부분 완료·실패를 구분해 DB에 기록한다.
- 공고 기본 정보와 질문·서류·일정을 편집하는 원고 API를 추가했다. 실제 신청 기간을 목록 게시 기간으로 추론하지 않는다.
- 단위 검사 4건, PostgreSQL 통합 검사 10건 통과. 외부 키가 없어 실제 LH 호출과 Google·카카오 왕복 로그인은 미검증이다.
- 구체적 상태·범위·운영 설정·남은 제약은 [백엔드 계약](../../architecture/backend-contracts.md)에 기록했다.

### 실제 연동·검증

- 프론트엔드의 빈 201 응답 처리, 갱신 요청의 만료 접근 토큰 제외, 재시도 후 409 보존을 수정했다.
- 일정 미확인 상태와 nullable 날짜, 활성 소셜 제공자, 서버 샘플 표시, 관리자 원고 편집·수집 시작 페이지를 연결했다.
- 관리자 원고 편집 중 별도 검수 저장으로 원고가 사라지지 않도록 저장 순서를 제한했다. NO 답변 자체를 자격 불일치로 단정하던 표시를 중립적인 답변 표시로 바꿨다.
- IntelliJ 2025.1.4.1 formatter를 실제 설치 경로로 실행했다. 최초 기본 경로가 존재하지 않아 IDEA_FORMATTER_PATH로 해결했다. Java 소스 인코딩은 UTF-8로 명시했다.
- 최종 로컬 검사: 프론트엔드 14건·포맷·린트·타입·빌드, 백엔드 단위 4건·PostgreSQL 통합 11건·JAR 빌드, 기록 자동화 7건 통과. IntelliJ spotlessCheck 통과 후 검수 상태/날짜 검증 보완에는 spotlessApply를 다시 적용하고 빌드·테스트를 재실행했다.
- 실제 HTTP 검사 스크립트로 가입/로그인, 복합 검색, 중복 준비 방지, 조건·서류·일정 저장, 100% 준비도, 409, 403, 갱신 복원, 로그아웃을 확인했다.
- 실제 브라우저에서 합성 계정으로 가입부터 준비 완료·새로고침 복원까지 확인했다. 관리자 원고 저장 후 HOLD 전환, 동시 검수 저장, 외부 키 미설정 수집 기록도 확인했다. 검증용 관리자 권한은 일반 사용자로 되돌리고 로그아웃했다.
- 가상 공고와 합성 계정의 로컬 검증이며 실제 청년 주거 정책의 적합성 검증이나 외부 OAuth/LH 왕복 성공을 뜻하지 않는다.
- 원격 PR 생성 연결 도구의 403은 기존 GitHub CLI 인증으로 대체했다. 권한 우회나 저장소 공개 범위 변경은 수행하지 않았다.
