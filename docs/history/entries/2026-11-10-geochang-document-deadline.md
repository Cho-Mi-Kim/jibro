- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 원인 확인 후 사용자 요청에 따라 로컬 반영·검증 완료
- 유형: 공식 일정 누락 보완 / 원문 재검증 경로 수정
- 담당·검토: Codex 공식 원문 및 코드 대조. 사람 담당자 검토 여부 미확인.
- 관련 이슈·PR·커밋: 없음

## 배경·확인

사용자가 경남 거창군 신원면 다자녀 매입임대 공고의 서류마감이 보이지 않는 이유를 질문했다. 대상 ID는 `06462f53-d47e-419e-b458-c8a6e212b96a`이다. 공개 API 일정은 신청 시작11.02, 신청 마감11.13, 입주대상자 발표 예정2027.01.15의 3개이며 별도 서류마감 일정이 없다. 마감 근거 자체에는 '신청 및 서류 제출 접수기간'이라고 기재되어 있다.

공식 PDF(fileid=69108015)를 새로 조회해 1·7쪽을 읽고 1쪽 표를 렌더로 확인했다. 선정절차의 첫 단계는 '신청접수 및 서류제출', 접수기간은2026.11.02~11.13이다. 날짜는 확인되지만 접수마감 시각이나 우편 도착·소인 기준을 임의로 만들 수는 없다.

`frontend/src/features/housing/schedules.ts`의 `scheduleKind`는 제목의 '서류…마감'만 서류 일정으로 분류한다. `noticeDetailDates.ts`는 해당 일정이 없으면 서류 날짜를 빈 문자열로 반환한다. 같은 날짜이기 때문에 자동으로 숨기는 분기는 없으며, 신청 마감만 저장되고 서류 제출 의미가 별도 일정으로 표현되지 않은 것이 원인이다.

## 판단·후속

이 공고에는 서류 제출 기간의 공식 근거가 있으므로 '서류마감 미확정'과 구분해야 한다. 표시를 보완한다면 '11/13 · 신청 시 함께 제출' 의미를 유지하는 것이 적절하다. 다른 공고의 신청 마감일을 무조건 서류마감으로 복사하는 변경은 근거 없는 일정 생성이므로 적절하지 않다.

최초 이유 확인 단계에서는 제품 코드·데이터를 수정하지 않았다. 이후 사용자가 “서류마감에 11/13로 나오게 수정”을 요청하여 아래 내용을 반영했다. 원문과 렌더/해시는 Git 제외 `.tools/qa/geochang-deadline-20261110/`에 보존했다. 공식 PDF SHA256: `5f55a68c49742e8d857e626af64a1621419d4abc3df4205b530d979fc684b6c2`.

## 반영·검증

- 신청과 함께 서류를 제출하는 공식 근거에 따라 `documents-end / 서류 제출 마감 / 2026-11-13` 한 건을 추가했다. 기존 신청시작·마감·입주대상자 발표, 질문 17개·서류 26개는 그대로 보존했다. 마감 시각은 추정하지 않았다.
- 기존 `SourceReviewVerifier`가 대표근거 URL을 HTML로 가정해 PDF를 대표근거로 둔 게시 원고를 재검증하지 못했다. 공식 LH 파일 URL에 한해서 같은 발췌의 `EXTRACTED` HTML 중 저장된 `sourceKey`와 결속된 유일한 상세 URL을 선택하도록 보완했다. 타 공고·임의 URL·미발췌·중복 후보는 거절하고 원문 전체 문맥·첨부 목록·SHA·revision 검사를 유지한다.
- 최신 공식 상세의 공고중 상태와 전체 문맥, HWPX/PDF 두 첨부의 원바이트 SHA 동일성을 재확인했다. 현재 revision의 새 발췌를 만들고 `SourceReviewPublicationService.amend`로 이전 게시 지문·fresh receipt를 검증해 반영했다. 직접 SQL로 공개 상태나 날짜를 덮어쓰지 않았다. 공고 버전 2→3, revision 3→4, `AVAILABLE` 유지. 반영 패키지와 결과는 `docs/reviews/2026-11-10-geochang-deadline/`에 보존한다.
- `SourceReviewVerifierTest` 22개 통과(추가 6개 포함). 프런트 `schedules.test.ts`, `noticeDetailDates.test.ts`, `calendar.test.ts` 3파일 25개 통과.
- 실행 중인 API 응답을 실제 `NoticeDetailOverview` 컴포넌트에 전달해 `서류 마감 / 11/13` 렌더를 확인했다. 기존 세 일정·질문·서류 일치, 전체 개인 준비 행의 전후 해시 일치를 확인했다. 실제 모바일 기기 또는 브라우저 화면 QA는 수행하지 않았다.

## 기여·한계·후속

Codex가 공식 자료 대조·누락 일정 추가·검증 경로 수정 및 회귀 검사를 수행했다. 사람 검토 완료나 기관 확인을 주장하지 않는다. 발표 설명은 “공식 자료에 있는 동시 제출일을 별도 일정으로 보존하고, 게시 원고 변경 시 원문 동일성을 재검증했다”로 한정한다. 로컬 작업만 반영했으며 push·배포는 하지 않았다.

다른 공고의 신청 마감일을 서류 마감일로 복사하는 자동 규칙은 추가하지 않았다. 개인 준비 타임라인의 고정 순서(결과→서류)와 결과 발표 제목 단순화는 별도 기존 한계로 확인했으며, 이번 상세 날짜 표시 범위에는 포함하지 않았다.
