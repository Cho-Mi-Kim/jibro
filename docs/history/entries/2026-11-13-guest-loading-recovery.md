# 비로그인 화면 로딩 복구

## 배경과 문제
2026-11-13 비로그인 홈·공고·내 준비 로딩이 지연된다는 제보를 재현했다. 프론트와 백엔드는 실행 중이었으나 로컬 PostgreSQL이 중단돼 health 및 인증·목록 조회가 연결을 기다렸다. DB 로그에서 비정상 종료와 복구 이력을 확인했으나 종료 주체와 직접 원인은 확인하지 못했다.

## 결정과 변경
DB 자료를 초기화하지 않고 정상 복구했다. 재시작 스크립트는 PostgreSQL을 숨겨진 별도 프로세스로 띄우고 준비 상태를 확인한다. 서버 DB 연결 대기 기본값을 5초로 설정하고, 프론트 GET 및 CSRF 조회는 8초 후 오류를 표시하도록 했다. 저장 요청과 refresh 토큰 회전 요청은 클라이언트 측 타임아웃으로 중단하지 않아 결과 불확실성과 세션 회전 손실을 줄인다. 기존 인증 및 비회원 접근 정책은 유지했다.

## 검증과 한계
DB를 정상 종료하고 수정된 재시작 스크립트로 시작한 후 실행 스크립트가 끝나도 DB가 유지됨을 확인했다. health/database UP, 공고 API HTTP 200, 브라우저 비로그인 홈과 공고 목록 63건, 내 준비 로그인 화면 및 임시 체험의 빈 준비 화면 확인. 프론트 전송 테스트 8개, 수정 파일 eslint, 프론트 build, 백엔드 관련 단위 테스트와 bootJar가 통과했다. 브라우저 시험과 실제 휴대폰 시험은 구분하며 실제 휴대폰과 장시간 안정성은 확인하지 않았다. 원격 배포·push는 하지 않았다.
