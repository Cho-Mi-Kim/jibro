# 준비 기록의 중복 보관과 복원 후 오래된 저장 방지

- 기록일: 2026-11-15 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 해결
- 관련 변경: GitHub PR #24, `2918a43`

이전 점검에서 서버와 체험 모드 모두 보관·복원 시 변경 번호가 그대로여서 오래된 요청을 구분하지 못했다. 사용자는 GitHub 수정과 같은 동작을 현재 로컬 코드에 적용하도록 요청했다.

서버의 기존 서비스·저장소 분리를 유지했다. ExperienceService는 소유자 행을 잠근 상태에서 보관 여부와 변경 번호를 확인한다. ExperienceRepository는 실제 상태 전환 시 DB 열과 준비 스냅샷의 변경 번호를 한 번에 갱신한다. demoMember도 같은 중복 거부와 복원 규칙을 적용한다.

기존에 실패한 GitHub 회귀 테스트를 로컬 테스트 모음에 포함했다. 별도 PostgreSQL 테스트 DB에서 MemberFeaturesIntegrationTest 6건, Vitest에서 demo.test.ts와 ArchivePage.test.tsx 12건이 통과했다. 이 중 4건이 중복 보관 거부와 복원 후 오래된 요청 차단을 두 환경에서 검증한다. 로컬 실행 파일을 빌드하고 교체한 뒤 5173에서 서버와 DB 정상 응답을 확인했다.

AI 보조로 로컬 이식과 자동 검증을 수행했다. 운영 배포와 실제 사용자 데이터에 대한 시험은 진행하지 않았다. 회귀 테스트는 이후 보관·복원 변경의 검증 대상으로 유지한다.

## 같은 PR의 로그인 흐름 테스트 안정화

후속 대조에서 로컬 앱 테스트가 시연 요청마다 180ms씩 기다리는 것을 확인했다. PR #24와 동일하게 이 지연을 `demoDelay.ts`로 분리하고 `App.test.tsx`에서만 즉시 완료하도록 했다. 로그인 복귀, 모름 응답 저장, 서류 저장 실패와 재시도를 검증하는 테스트가 개별 실행 3회 연속 통과했다. 같은 파일 전체 43건과 프론트 타입 검사도 통과했다.
