- 담당·검토: Codex가 원격·로컬 차이 대조와 충돌 해소를 수행. 인간 검토자 미확인.

## 배경·문제

시각화를 제외한 로컬 코드를 별도 검토 브랜치로 공유한 뒤 develop과 6개 파일·8개 구간에서 충돌했다. 사용자에게 각 충돌의 양쪽 변경을 설명했고, 1~3번은 제안한 방향, 4~6번 문서는 적절히 통합하도록 요청받았다. develop을 검토 브랜치에 반영하되 PR을 develop/main으로 병합하거나 운영에 배포하지 않는다.

## 고려한 선택지·결정

전체 파일을 어느 한쪽으로 일괄 선택하면 지역 약칭 개선이나 Linux CI 수정, 최근 운영·로그인 기록이 사라진다. 같은 책임의 현재 구현을 남기고 상대 브랜치의 유효한 수정만 통합한다. 과거 검증 수치·환경은 당시 기록으로 보존하며 이번 실행 결과와 섞지 않는다.

## 변경·해결 과정

1. `NoticePages.tsx`: `regionFilterLabel`을 사용하는 로컬 구현을 유지했다. develop의 같은 구간 변경은 줄바꿈뿐이었다. 지역 약칭·중복 제거는 기존 공통 모듈이 계속 소유한다.
2. `OfficialFileCollectionIntegrationTest`: 한국 시간의 기준 날짜 하나를 사용하고 DB 세션을 UTC로 설정한다. SQL `current_date` 대신 같은 기준에서 계산한 시작·마감일을 넣어 두 시간대의 날짜 경계 차이를 검증한다. 로컬 Java 서식은 유지한다.
3. `OcrTestWorker`: watchdog 검증 중 자식 프로세스 종료 직후 main이 정상 종료하는 경합을 제거한다. watchdog이 부모 JVM을 비정상 종료할 때까지 테스트 프로세스를 유지하며, 실패 시 예외를 낸다. 제품의 제한 시간·종료 로직은 바꾸지 않는다.
4. 프론트 계약: 소셜 복귀 경로·화면별 지연 로딩과 계정 연결·확인 링크·세션 만료 계약을 함께 보존했다.
5. 작업 이력: 양쪽 기록 파일을 유지하고 `project-history.mjs sync`로 목록을 다시 생성한다.
6. 검증 문서: 11월 22일 실제 로그인 기록과 11월 15일·10일 GitHub 검증·배포 기록을 날짜별로 보존한다.

자동으로 합쳐진 문서도 대조해 오래된 인수인계 문서가 최신 상태로 안내되지 않도록 날짜·연결을 정리했다. `.gitignore`의 중복 Python 캐시 규칙은 한 번만 남겼다. 발표 시각화와 실제 키·환경 파일은 포함하지 않는다.

## 추가·삭제·구조

- 추가: GitHub에서 확인된 시간대·프로세스 종료 테스트 수정과 누락된 계약·과거 이력.
- 삭제: 중복 제외 규칙, 오래된 기록을 최신으로 소개하는 문구, 충돌 표시.
- 제품 모듈·공개 API·DB 변경: 없음. 새 실행 경로·임시 제품 코드 없음.
- 의미 변경은 테스트 fixture의 시각 기준과 종료 동작에 한정한다. 단정 완화·skip 추가·제품 제한 시간 변경은 없다.
- 의미 지도에 새 모듈·책임·의존 관계를 추가할 변경은 없다.

## 검증·결과

- 프론트 `npm run ci`: 서식·lint·계층·검수 카탈로그·공개 페이지·타입, 109파일 887검사 및 일반 빌드 통과. `npm run build:pages`도 통과.
- 백엔드 `build integrationTest`: 단위 1,010개 중 1,009개 통과, 기존 공식 사이트 직접 접속 선택 검사 1개 미실행. PostgreSQL 통합 451개 전부 통과. 이번 변경 후 단위·통합 검사를 실제로 실행했다.
- 최초 전체 실행에서는 `OneTimeCheckIntegrationTest`의 실제 PDF·HWPX 연결 검사 1건이 `PARSER_WORKER_FAILED`로 실패했다. 같은 코드의 해당 클래스 재실행 및 전체 통합 재실행은 통과했다. 최초 작업 프로세스 종료 원인은 확정하지 않았고 제한 시간·단정·제품 코드를 바꾸지 않았다. 실패 로그도 `.tools/pr31-first-integration-failure.xml`에 보존했다.
- 변경 Java 두 파일은 실제 IntelliJ의 `spotlessCheck` 통과. 작업 기록 검사 7개 통과.
- 변경 파일의 충돌 표시 없음, `git diff --cached --check` 통과, 문서 내부 링크 누락 없음. 로컬 시작 커밋과 비교해 프론트 제품 코드·백엔드 실행 코드는 동일하며 테스트 두 파일만 동작 변경이 있다.

## 기여·한계·후속 작업

원격·로컬 변경을 현재 코드와 대조해 팀 검토 브랜치에 정리한 작업이다. 기존 누적 기능을 이번에 새로 구현한 것으로 보고하지 않는다. 실제 OAuth·메일·수집·운영 배포 재검증, UI 실기기 점검, 전체 구조 감사는 이번 범위에 포함하지 않는다.
