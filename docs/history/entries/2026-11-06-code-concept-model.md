# 실제 코드 기반 개념 모델 HTML

## 요청과 범위

사용자가 웹사이트의 핵심 개념을 UML·그래프 등 고전적 방법으로 모델링하여 별개 HTML로 보여 달라고 요청했다. 실제 개발 루트 `C:/Users/Administrator/Documents/jibro`, 작업 브랜치 `feature/local-mobile-screens-20261103`, 시작 HEAD `ebccaa7`과 현재 미커밋 변경을 기준으로 읽었다. 동기화 폴더의 과거 의미 지도는 코드 패키지와 구조가 달라 현행 구현 근거로 사용하지 않았다.

## 결정과 구현

논리 클래스와 물리 DB 구조를 혼합하지 않도록 다섯 관점을 분리했다: 핵심 개념 UML, 실제 저장 ER, 답변 저장 시퀀스, 상태와 결정 규칙, 구성요소 그래프. Preparation의 내부 답변 Map을 별도 Answer 테이블로 그리지 않았고, 보관함을 별도 엔티티로 만들지 않았다. 상태 변경을 무조건 선형 과정으로 그리지 않도록 서류 필요 여부와 준비 상태, 안내 검수와 접수 상태를 구분했다.

`docs/models/build_code_model.py`에 검토된 관계와 설명을 유지하고 `frontend/public/jibro-code-model.html`로 생성한다. SVG·스타일·설명·코드 근거를 파일 안에 포함하여 네트워크 라이브러리 없이 열 수 있다. 노드 선택 시 코드 근거 표시, 관점 전환, 확대, SVG 다운로드, 전체 인쇄 컨트롤을 제공한다. 제품 런타임 코드는 변경하지 않았다.

## 검증 및 한계

각 인용 파일 존재와 SVG 다섯 개의 XML 파싱을 확인했다. 브라우저에서 다섯 관점의 레이아웃, 노드 내부 텍스트 넘침 검사, 관점 전환, 노드 설명, 확대를 확인했다. 모바일 393px에서는 문서 자체의 가로 넘침 없이 그림 내부에서 가로 스크롤된다. 브라우저 오류 로그는 없었다. 상자·연결선의 시작점을 실제 크기에 맞춰 보정했고 시퀀스의 응답은 DB가 아닌 서비스에서 화면으로 반환되도록 정리했다.

전체 저장소의 자동 역공학, 실제 DB 데이터 및 API 실행, 외부 기관/발송 연동 검증은 수행하지 않았다. SVG 내보내기와 인쇄 컨트롤은 구현했지만 생성 다운로드 파일·인쇄 결과는 실검증하지 않았다. 코드 줄번호는 후속 수정 시 달라질 수 있다.

## 기여와 후속 작업

AI가 코드 정적 탐색·도메인 관계 검토·HTML 생성·브라우저 확인을 보조했다. 사용자가 모델을 검토·승인했다는 의미는 아니다. 발표에는 '구현 코드에 근거한 도메인·저장·흐름 분리'를 근거로 활용할 수 있으며, 후속 구현 변경 시 생성 파일이 아닌 모델 원본을 갱신한다.

## 리팩토링 이후 업데이트본

사용자가 최신 서버 재시작과 개념 모델 업데이트를 요청했다. 기존 모델의 코드 참조만 바꾸는 방식 대신, 실제로 바뀐 책임과 흐름을 다이어그램에 반영했다. 기존 다섯 관점과 설명/확대/저장 기능은 유지하고 ‘일정·탐색 경계’를 추가하여 6관점·33개 개념으로 구성했다.

- 답변 저장 시퀀스: Service와 순수 Rules를 별도 생명선으로 분리하고 계산 결과가 Service에 돌아온 뒤 저장되는 흐름을 표시했다. Rules를 별도 서버나 API로 그리지 않았다.
- 구성요소: 실제 서버의 저장·계산 책임과 정적 시연 경계를 분리하고, 같은 입력·독립 기대값을 사용하는 계약 사례 연결을 런타임 호출과 구별했다.
- 일정·탐색 경계: 공개 ScheduleTemplate과 개인 Schedule.recorded, 같은 version/ID/제목/날짜에서만 표시되는 기록, 조건 탭/독립 결과/질문 주소, 개요 신청 기록 팝업을 명시했다.
- 보관: ID별 미저장 메모와 제출 당시 명령 값을 구분했다. 보관의 revision 검증을 revision 증가로 일반화하지 않았고, 복원·메모 연결의 별도 입력을 설명했다.
- 모델 오류 교정: 이력 테이블 유일키를 실제 `UNIQUE(preparation_id, notice_version)`으로 고쳤다. 고정 줄번호 일부를 실제 심볼 위치 탐색으로 교체하여 생성 시 근거 누락을 확인한다.

구현 담당자와 다른 검토자가 모델/코드를 읽기 전용으로 대조했다. 위 다섯 경계·오류의 반영을 최종 생성 원본과 HTML에서 재확인했고, 검토 범위에서 추가 심각한 모델링 오류는 발견하지 않았다.

### 업데이트본 검증과 실행 결과

- 단일 HTML 84,985 bytes. SVG 6개 XML 파싱, 개념 33개의 근거 파일·줄 범위·주요 심볼의 유일 위치 확인. 외부 스크립트/스타일 의존성 없음.
- 브라우저 1440px: 6관점 전환, 각 상자 글자 넘침 없음, 구성요소의 정책 노드 선택과 근거 패널, 120% 확대와 맞춤 복원 확인. 시퀀스·구성요소·신규 경계 그림의 표시를 시각 확인했다.
- 브라우저 393×852: 문서 clientWidth/scrollWidth가 같고, 큰 그림은 내부 가로 스크롤로 탐색된다. 실제 휴대전화 검사와는 구분한다.
- SVG 저장 버튼으로 받은 `jibro-sequence.svg`를 XML 파싱하고 현재 HTML 시퀀스 SVG와 일치함을 확인했다. 인쇄/PDF 실출력은 하지 않았다. 브라우저 오류 로그 0.
- 기존 HTML 탭을 최신 파일로 새로고침해 핵심 개념 관점으로 열어두었다. 임시 화면 크기는 초기화했다.
- 서버 재시작: 기록된 프로세스의 실행 경로·시작 시각·명령을 대조해 기존 8080 백엔드만 종료하고, 기존 시작 도우미로 최신 bootJar를 실행했다. 5173 프론트와 DB는 유지했다. 새 프로세스 기동 로그, 5173 프록시 health의 status/database UP, 기존 준비 기록이 표시된 홈 화면을 확인했다. 과거 재시작 차단은 후속 사용자 명시 요청에 따라 해소되었다.

제품 소스·DB 스키마·개인 기록을 변경하는 작업은 하지 않았으며, 서버 런타임 교체와 모델 문서만 갱신했다. 이전 리팩토링에서 통과한 전체 테스트를 이 문서 변경 때문에 반복 실행하거나 이번 검증으로 재보고하지 않는다. 커밋·push·외부 배포는 하지 않았다.
