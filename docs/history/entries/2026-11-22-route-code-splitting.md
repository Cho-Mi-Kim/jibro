## 배경·문제

사용자가 화면별 코드를 필요할 때만 불러오도록 바꾸고 기존 기능을 유지하면서 큰 번들 경고를 없애 달라고 요청했다. 기존 `App.tsx`는 모든 화면을 정적으로 import하여 첫 JavaScript 파일이 810,971B였다. 검토 조건 원고는 이미 동적 로딩 중이므로 이번 원인은 화면 진입 경계였다.

## 고려한 선택지·결정

- 경고 한도 상향: 실제 다운로드를 줄이지 않으므로 사용하지 않았다.
- 임의의 vendor 묶음 분할: 첫 화면이 모두 요구하면 총 비용이 그대로여서 먼저 선택하지 않았다.
- 라우트 단위 지연 로딩: 실제 소비 시점인 App의 화면 진입점에서 코드 요청을 시작한다. 기존 URL·인증·세션·탐색 구조를 보존하기 위해 React.lazy를 사용했다. [React 공식 lazy 안내](https://react.dev/reference/react/lazy)와 [Suspense 안내](https://react.dev/reference/react/Suspense)를 확인했다.
- CSS 선행 로딩은 기존 화면별 스타일 적용 순서를 보호하므로 유지했다. CSS 최적화는 이번 JavaScript 분할과 구분한다.

## 변경·해결 과정

`App.tsx`의 29개 화면/준비 레이아웃 정적 import를 모듈 최상위 lazy 선언으로 대체했다. 실제 파일 기준 24개 화면 모듈이며 같은 파일의 복수 export는 함께 로드한다. 이전 정적 화면 경로를 병행해 남기지 않았다. 기존 33개 route와 `Protected`, `NoticeListLayout` 방문 Maps, 세션·접근성·QueryClient·Shell 위치는 보존했다.

추가한 `PageBoundary`는 화면 파일 다운로드의 대기·실패를 맡는다. 메뉴는 유지하고 실패하면 수동 새로고침·홈 복귀를 제공한다. 정상 이동마다 경계 key를 바꾸지 않으며 실패 상태에서 경로가 달라질 때만 복구한다. 자동 새로고침이나 무한 재시도는 없다.

실패 화면 버튼을 공통 UI 컴포넌트로 표시한 중간 변경에서 테스트 환경의 ResizeObserver 의존이 드러났다. 실패 안내는 추가 런타임 의존을 줄이도록 기본 버튼에 기존 버튼 스타일만 적용했다. 시험에 observer 대역을 더하거나 단정을 완화하지 않고 기존 검사로 재검증했다.

추가: `PageBoundary.tsx`, `PageBoundary.test.tsx`. 제거: 화면 전체를 초기 묶음으로 끌어오던 App의 정적 import. 업무 규칙·API·DB 변경 없음. 임시 제품 코드 없음.

동일 개발 환경의 운영 빌드 JavaScript 크기를 대조했다. CSS·이미지·API 데이터는 아래 값에 포함하지 않는다. 압축 전 크기는 빌드 산출 파일 기준이며 전송 시간 개선을 직접 측정한 값은 아니다.

- 최종 `npm run ci`: 서식·린트·계층검사 10개·102개 검토 원고/134개 출처·타입·90개 테스트 파일의 684개 검사·빌드 모두 통과. 로그 `.tools/qa/route-split-ci.log`.
- 기존 App 준비·복귀 흐름 68개 통과. 새 3개 검사는 실제 lazy Promise의 대기/실패, 메뉴 유지, 다른 화면 복구, 공유 상태 보존을 검증한다.
- 변이 검사: 경계에 경로별 key를 일부러 붙여 매번 재생성하면 선택 상태 보존 검사가 실패했다. 원본 바이트 복구 후 3개 재통과. `.tools/qa/page-boundary-mutation.log`. 테스트 skip·시간 제한 완화 없음.
- 독립 리뷰: 33개 경로·인증 우선·CSS 순서·세션/방문 기록·오류 복구·검사 경계를 읽기 전용 확인. 별도 새 3개 검사와 경계 검사를 실행했으며 잔여 차단 지적 없음.

## 기여·한계

로컬 구현·검사·브라우저 검증이며 운영 `jibro.live` 배포와 구분한다. 실제 휴대폰이나 제한 네트워크의 시간 측정, 실계정 OAuth 재인증은 수행하지 않았다. 백엔드·DB·자격 판단은 변경하지 않았다. 외부 Iron Laws 도구와 GPT Pro 검토는 연결되지 않아 미실행이며 독립 리뷰를 해당 검사의 실행으로 표기하지 않는다.

## 발표·포트폴리오 메모

전체 화면의 정적 의존을 실제 방문 시점으로 옮겨 메인 JavaScript를 약 51% 줄였다. 파일 하나의 크기뿐 아니라 홈의 공통 의존을 포함한 크기도 확인했고, 기존 준비 흐름과 실제 복귀 동작을 검증했다. 개인 기여는 담당자 확인 후 사용한다.
