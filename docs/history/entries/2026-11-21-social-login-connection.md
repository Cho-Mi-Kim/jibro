# Google·카카오 로컬 로그인 연결과 재시도 복귀

- 기록일: 2026-11-21 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 로컬 실연결 완료 — 2026-11-22 두 제공자 실제 로그인 검증, 운영 배포 별도
- 유형: 외부 연결 / 로그인 흐름 수정
- 담당·검토: Codex 구현·검증 보조, 사람 코드 검토자 미확인
- 관련 이슈·PR·커밋: 원격 게시 없음

## 배경·문제

사용자는 기존 Google·카카오 버튼의 구현과 실연결을 요청했고, 발급된 인증 정보가 없어 발급부터 돕도록 요청했다. 서버의 OAuth 등록·인가 코드·state/OIDC·갱신 쿠키·프런트 callback은 이미 구현돼 있었다. 현재5173·8080의 제공자 목록이 비어 있고 로컬 OAuth 인증 정보가 없는 것을 확인했다. 과거 실연결 성공 기록을 현재 설정의 성공으로 간주하지 않았다.

## 결정·구현

기존 OAuth 경로를 유지하고 누락된 설정을 연결한다. Google 프로젝트와 앱 브랜딩을 준비했으며 정책 동의와 두 제공자의 앱 생성은 사용자가 직접 완료했다. Git 제외 `.env`에 제공자 ID/Secret과 로컬 복귀 주소를 연결하며, 실제 키 값을 문서·프런트·Git에 남기지 않는다. [연결 절차](../../social-login-setup.md)에 공식 문서와 등록 주소를 정리했다.

프런트에서는 OAuth 실패 뒤 원래 경로가 `/my`로 덮이는 문제를 확인했다. `features/auth/socialLogin`에 안전한 복귀·시작 처리를 모으고 로그인 실패/콜백 재시도 링크에 원래 경로를 유지했다. 명시 query 우선과 외부 복귀 주소 차단을 유지하며, callback은 성공 후 경로를 지워도 중복 effect가 다른 화면으로 이동하지 않도록 최초 경로를 고정한다. 버튼 외형과 제공자별 활성 조건은 보존했다.

## 검증·진행 상태

- 기존 인증 관련과 신규 직접 화면/도우미 검사36개 통과. 전체 프런트 CI87파일673검사·서식·린트·계층·타입·빌드 통과. 기존 번들 크기 안내 유지.
- 백엔드 현행 OAuthEndpoints/OAuthFailureDiagnostics 7검사 통과. 백엔드 코드·DB 변경 없음.
- 2026-11-22 Google 인증 정보 연결 후 5173·8080 재시작. 두 포트의 제공자 목록에 Google 활성, 실제 데이터 모드와 서버·DB 정상 상태 확인. 사용자가 계정 선택·동의한 뒤 원래 `/preparations`로 복귀, 새로고침 후 로그인 유지, 마이 화면의 로그인 상태, 로그아웃 후 홈 복귀까지 실제 Opera에서 확인했다.
- 카카오 앱 아이콘 등록 후 사용자가 카카오비즈니스 약관·개인정보 확인을 완료했다. 개인 개발자 비즈 앱으로 전환하고 닉네임·이메일 필수 동의와 이메일 값이 없을 때 수집을 설정했다. 기존 카카오 로그인용 Secret과 REST 키를 사용했으며 OIDC는 기존대로 OFF다.
- 두 제공자 설정을 반영해 5173·8080을 재시작했다. 양쪽 제공자 목록에 Google·Kakao가 활성화됐고, 실제 데이터 모드·서버·DB 정상 상태와 각 로그인 시작 주소의 공식 인증 화면 이동을 확인했다.
- 사용자가 카카오 계정 정보 제공에 동의한 뒤 `/preparations` 복귀, 새로고침 후 유지, 마이 화면 로그인 상태, 로그아웃 후 홈 복귀를 실제 Opera에서 확인했다. Google과 Kakao 모두 동일 검증 완료. 실제 모바일 기기 검증이나 운영 도메인 배포를 뜻하지 않는다.
- `.env`는 Git 제외·미추적 상태다. 현재 Google·Kakao Secret 값과 추적 파일 및 Git에서 제외되지 않은 미추적 파일 1,480개를 대조해 일치 0건을 확인했다. 비밀값 자체는 출력하지 않았으며 전체 Git 이력 검사는 아니다.
- 결과 로그: `.tools/qa/social-login-connection/frontend-ci.log`. 비밀값·토큰·쿠키 로그 없음.

## 한계·후속

카카오 신규 가입의 검증된 이메일 정책과 기존 제공자 식별 규칙은 유지한다. 서로 다른 이메일의 테스트 계정을 자동 병합하지 않았다. 운영 도메인 공개·배포와 HTTPS 운영 복귀 주소 등록은 이번 로컬 연결 검증과 별개다.

공헌 설명은 기존 구현을 신규 개발로 과장하지 않고, 현재 설정 확인·실패 재시도 결함 수정·두 제공자 로컬 실연결로 구분한다. 코드 검사는 2026-11-21 실행 결과이며 11월 22일에는 설정 연결과 실제 브라우저 검증을 수행했다. 운영 배포는 미완료이며 사용자 사용성 개선율은 측정하지 않았다.
