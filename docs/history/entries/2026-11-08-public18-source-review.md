# 공개 보류 18건의 공고별 원문 대조와 준비 안내 반영

- 기록일: 2026-11-08 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 지정18건 검토·로컬 적용 완료 / 공식 충돌4건과 정정 전1건은 승인 보류
- 유형: 개발 / 문제 해결 / 검수
- 담당·검토: Codex 보조 구현·공식 원문 대조·자동 검사, 팀원 검토 미확인
- 기준: `feature/launch-integrations-20261107` / `e288a99`. 기존 변경 보존, 이번 작업의 커밋·push·배포 없음.

## 배경·문제

사용자가 지정한 기존 공개 보류 18건을 실제로 처리하도록 요청했다. [이전 검토](2026-11-08-typed-guidance-review.md)의 유형별 초안은 전체 안내 승인이 아니며, 범용 문자열 검사만 반복하면 PDF/HWPX 표 읽기 순서 차이·용량 오류와 실제 문서 충돌을 구분하기 어려웠다.

## 고려한 선택지

- 범용 자동 문법의 승인 기준을 완화: 빠르지만 미확인 문서·실제 충돌까지 공개될 수 있어 채택하지 않았다.
- 공고별 원문을 다시 읽은 검토 원고를 별도 감사 경로로 반영: 출처·원고·현재 버전의 일치와 개인 준비 기록 보존을 검사할 수 있어 채택했다.
- 읽기 실패 파일을 현재 자료에서 제외: 서울·경기 PDF가 공식 페이지에 여전히 연결돼 있음을 실시간 검증이 발견하여 기각했다. 두 PDF를 다시 내려받아 읽고 비교했으며, 제외 예외 코드는 제거했다.

## 결정·이유

확인된 공고별 안내만 반영하고, 운영기관 문서 충돌은 임의로 해소하지 않는다. 이 작업을 범용 무인 승인 성공이나 사람 관리자의 심사로 표시하지 않는다. 기존 개인 준비 snapshot과 이미 승인된 안내는 보호한다.

검토 패키지는 [2026-11-08-public18.json](../../reviews/2026-11-08-public18.json)에 공고별 질문·조건부 서류·일정·출처 해시·검토 사유를 기록한다. 일반 자동 검수 경로는 기존의 보류 기준을 유지한다.

## 변경·해결 과정

- `HwpxPackageReader`: 삽입 그림 때문에 압축 해제 전체 용량이 초과하던 HWPX에서 검증된 mimetype·section XML을 읽는다. XML 크기/CRC 제한을 유지한다.
- `PdfLayoutTextStripper`: embedded 폰트의 실제 빈 glyph로 입증된 NUL만 공백으로 복원한다. 불명확하거나 윤곽이 있는 문자는 실패를 유지한다.
- 공식 상세 추출에 접수처 자유문구를 포함해 구조화된 일정과의 충돌도 보존했다.
- `SourceReviewVerifier`: 최신 revision/발췌 지문, HTML 전체 문맥, 현재 첨부 목록, 저장된 첨부 SHA ↔ 검토 원고 SHA ↔ 실제 다운로드 SHA를 검증한다. 빠진 파일·새 파일·변경 파일은 차단한다.
- `SourceReviewPublicationService`: 외부에서 만들 수 없는 만료시간 있는 검증 결과를 받아 공고 잠금 안에서 다시 검사하고 반영한다. V27 `notice_source_review`에 `AI_ASSISTED_SOURCE_REVIEW`로 기록한다. 공개 HTTP API나 예약 호출은 추가하지 않았다.
- 신청 시작/마감은 canonical 일정 제목과 날짜를 확인해 원문의 16시·17시 경계가 일자만 저장되는 오류를 막았다. 순위별 접수와 이전 순위 마감 조건도 원고에 보존했다.
- 대용량 RITS ZIP은 별도 스트리밍 해시로 실제 검토한 파일과 일치시켰다. 자동 추출의 용량 초과 상태를 성공으로 바꾸지 않고 원본 해시만 기록했다. 내부 과거 팸플릿의 이전 자격 조건을 현 모집에 재사용하지 않았다.
- 다중선택의 `NONE`은 새 입력에서 다른 선택지와 함께 저장되지 않게 했다. 기존 snapshot의 표시·평가를 소급 변경하지 않는다.

## 기여·한계

AI 보조로 원문 검토 원고와 검증 경로를 작성했다. 기관 담당자의 유권해석이나 사용자의 최종 신청 자격을 판단한 것이 아니다. 문서별 PDF/HWPX 표 연결을 실제 대조했지만 모든 새로운 공고의 의미를 자동 해석하는 범용 기능이 완성됐다는 뜻은 아니다. 실기기 검증은 수행하지 않았다.

## 발표·포트폴리오 메모

추출 실패·표 읽기 순서 차이·기관 원문 충돌을 구분하고, 검토 원고와 실제 원문 버전을 묶어 적용했다. 승인 건수와 기술적 출처 검증 성공을 분리해 보고한다.

## 후속 작업

- 실제 원문 충돌은 공식 정정이나 기관 확인을 받은 뒤 해당 자료 버전으로 다시 검토한다.
- 추가 공고에 적용하려면 공고별 검토 패키지와 최신 원문 검증이 필요하다. 이번 18건 원고를 다른 공고에 일괄 복제하지 않는다.
