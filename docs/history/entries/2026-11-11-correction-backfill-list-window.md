# 기존 정정 공고 대조와 기본 목록 28일 범위

- 기록일: 2026-11-11 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 해결 (공식 연결 미확인 9건 보존)
- 유형: 개발 / 데이터 점검
- 담당·검토: AI 구현·로컬 검증, 팀 검토 미확인
- 관련 이슈·PR·커밋: 미등록, 기존 feature/launch-integrations-20261107 변경 보존

## 배경·문제

사용자는 현재 수집 공고도 접수 종료를 제외하고 정정 관계를 연결하고, 기본 목록과 건수를 접수 중·예정·일정 확인 필요·종료 28일 이내로 제한하도록 요청했다. 저장된 신청 날짜가 없는 과거 공고는 UNKNOWN으로 분류됐지만 공식 API에는 접수 마감 상태가 남아 있었다.

## 고려한 선택지

화면에서 항목만 숨기면 페이지와 개수가 어긋난다. 공고 게시일이나 API CLSG_DT를 신청 마감일로 추정하면 다른 날짜를 표시할 수 있다. 서버의 공통 조회 조건과 공식 명시 마감 상태를 사용하고 날짜는 새로 만들지 않았다.

## 결정·이유

기본(상태 미선택) 범위는 KST 달력 날짜로 계산한다. 정확한 마감 시각이 있으면 그 시각부터 CLOSED이며, 28일 전 날짜는 포함하고 29일 전은 제외한다. 날짜 없는 공식 마감은 28일 여부를 입증할 수 없어 기본 제외하고 명시 CLOSED 검색은 허용한다. 진짜 일정 미확인은 게시 연도가 오래됐다는 이유로 임의 제외하지 않는다.

## 변경·해결 과정

- DefaultNoticeScope의 공통 조건을 count/pagination 전에 적용했다.
- 공식 PAN_SS를 Item → importSource → V35 source_closed로 전달해 목록/상세/자동 검수/자동 정정 연결에서 같은 종료 상태를 사용한다. 보관 응답과 현재 수집 지문이 일치한 19,329건을 확인했고 그중 19,240건에 명시 마감 상태를 반영했다. 원고·일정·준비 기록은 수정하지 않았다.
- 정정 후보 3,362건을 대조했다. 624건은 현재 상세, 2,716건은 현재 지문과 일치한 보관 공식 응답의 마감 상태로 제외했다. LINKED 확인 13건 중 기존 관계 재확인을 제외하고 처음 10개 관계가 추가됐으나, 그중 공식 API에서 종료로 확인된 2025년 기존주택 전세임대 1쌍은 이번 작업 이전의 미연결 상태로 되돌렸다. 최종 신규 관계는 9개다.
- 공식 상세에서도 공고중·마감일 빈칸인 2012~2015년 공고 9건은 정정 연결 증명이 불충분해 그대로 뒀다. 제목만으로 합치거나 날짜로 종료를 추정하지 않았다. 상세 목록과 근거는 [실행 감사](../../reviews/2026-11-11-correction-backfill.json)에 있다.

## 검증·결과

- LhNoticeClientTest, OfficialCorrectionFamilyTest, AutomaticReviewEligibilityTest 단위 검사 통과.
- DefaultNoticeScopeIntegrationTest(28/29일·자정·시각·모든 정렬/페이지/개수·날짜 없는 공식 마감·재개), NoticeSortIntegrationTest, AutomaticCorrectionIntegrationTest(종료 원공고 제외 포함), NoticeCorrectionIntegrationTest, NoticeInitialSourceBindingIntegrationTest, CollectionIntegrationTest, AutomaticFollowupPublicationIntegrationTest 통과. 실제 외부 원문 재조회/기존 데이터 반영과 테스트 픽스처를 구분한다.
- bootJar 빌드 및 5173의 실제 API 확인: 기본 83건 = OPEN10 + UPCOMING9 + UNKNOWN55 + CLOSED9. 모든 CLOSED의 확인된 마감일이 28일 범위 안이다. 명시 CLOSED 검색 18,372건 유지. 조회 시점의 수치이며 새 수집·날짜 경과로 달라진다.
- 브라우저 레이아웃 변경 없음. 실제 모바일 기기 검증·원격 배포·push는 수행하지 않았다.

## 기여·한계

공식 관계로 입증된 중복만 연결한다. 9개 옛 공고의 연결 미확인은 남아 있으며, 공식 공고중 상태가 실제 현재 접수 중임을 보증하지 않는다. API 명시 마감 상태와 검증한 신청 날짜를 분리했다. 보관 응답·개별 실행 로그는 로컬 .tools/qa/correction-backfill에, 공유 가능한 결과는 위 감사 JSON에 기록했다.

## 발표·포트폴리오 메모

미확인 날짜를 추정하는 대신 공식 상태와 확인된 날짜를 분리하고, 동일 조회 조건으로 목록과 개수를 맞췄다. 신규 9개 정정 관계 연결을 실제 데이터로 확인했다. 팀·개인 기여 귀속은 별도 검토가 필요하다.

## 후속 작업

사용자의 보류 사유 질의에 따른 읽기 전용 재진단: 6건(서울등촌6·강원혁신B-2·평택소사벌B-2·평택소사벌B-5 2014.12/2014.07·충북혁신B-7)은 공식 이력에 원공고 링크가 존재한다. 다만 원공고 상세의 current/navigation이 자기 자신·일반공고로 남아 있어, 원공고가 최신 정정본을 가리켜야 한다는 현재 verifyFamilyHistory 조건에서 중단됐다. 공식 이력 근거 자체가 없는 경우와 구분한다. 나머지 3건(파주운정A23·충주안림·대구혁신B-3)은 공식 이력이 정정공고 한 행뿐이고 원공고 이동 ID도 없어 원공고 식별이 미확인이다. .tools/qa/correction-backfill/unresolved-diagnosis.txt에 재현했다. 이번 질의에서는 코드·연결 데이터를 변경하지 않았다.

- 미확인 9건은 공식 이력·원공고 식별 관계가 확인되면 다시 연결할 수 있다. 기존 종료 제외 정책 유지.
- 운영 배포 시 V35 적용과 공식 API 상태 수집 확인 필요.
