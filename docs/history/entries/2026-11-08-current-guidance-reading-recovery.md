# 읽기 실패 복구와 최신 공고 준비 안내 반영

- 기록일: 2026-11-08 (Asia/Seoul)
- 작업 상태: 구현·최신16건 원문 검토·실행 검증 완료. 과거 이미지 첨부18개 판독은 미완료.
- 유형: 문서 읽기 / 검수 / 공개 안내 / 회귀 보완
- 기준: `feature/launch-integrations-20261107` / `e288a99`. 기존 미커밋 변경을 보존했고 commit·push·배포는 하지 않았다.

## 요청과 범위

사용자가 읽지 못하거나 검수 중인 부분을 해결해 표시하도록 요청했다. 기존 원문 열람 기능에 그치지 않고, 최신 미시작 공고 16건의 실제 본문·첨부를 처리하고 안내 원고까지 대조했다. 예약 수집으로 계속 늘어나는 전체 과거 공고를 검수 완료했다고 해석하지 않는다.

## 변경

- XLS/XLSX를 기존 제한된 별도 문서 프로세스에서 읽는다. 시트·셀·병합·숨김·표시 날짜·저장된 수식 결과를 보존하며 매크로·수식 계산·외부 참조를 실행하지 않는다. 전체 압축 크기·CRC·항목 수와 행·열·셀·병합 수를 제한한다.
- 텍스트는 있지만 안내 키워드가 없는 주택 목록을 EMPTY로 오인하지 않는다. 읽힌 문맥과 선택 발췌가 없는 상태를 구분하며, 읽기 성공을 검수 승인으로 간주하지 않는다.
- 공개 보류 공고의 작업을 우선하고, 최근 30일 공고에 최대 24시간 우선권을 준다. 이어읽기는 최초 대기 순서를 유지하며 실제 재시도 가능 시각은 그대로 지킨다. 과거 작업이 무기한 밀리지 않는 것을 검증했다.
- 명시 날짜 뒤 쉼표와 시각, 단일 현장접수 표기를 처리한다. 모호한 연도·접수 채널·순위별 범위는 추정하지 않는다. 검수·분석 정책을 v6로 구분한다.
- 원문 검토 원고는 현재 revision·최신 추출 지문·공식 HTML 전체 문맥·모든 첨부 SHA를 다시 확인하고 AI 보조 검토 감사로 적용한다. 사람의 관리자 검수로 기록하지 않는다. 실제 상충 범위만 개별 질문·서류·일정의 확인 필요로 남긴다.
- 게시 직후 청주 후속 증빙의 조건 연결 오류를 확인했다. 태아·입양 재증명을 `household / ADOPTED,PREGNANT`에 연결하고 일반 출생 자녀는 제외했다. 이전 게시 지문·현재 내용 일치, 중간 편집·수동 검토 부재, 현재 revision 재발췌와 실제 원문 재검증을 요구하는 명시적 `amend` 경로를 사용했다. 원래 감사와 개인 스냅샷을 수정하지 않는다.
- LH 정정 탐색의 리터럴 분기 형식을 추가 지원한다. 실제 양방향 공고 ID·정정사유를 확인하며 원격 스크립트를 실행하지 않는다. 중복 함수, 뒤쪽 ID 재대입, 함수 덮어쓰기와 긴 문자열 처리도 검증했다.
- 날짜의 마침표 때문에 공고 요약이 날짜만 보이던 표시 오류를 수정했다.

## 실제 원문 검토 결과

최신 16건의 공식 자료 70개를 읽었다. 별도 재다운로드·동일 SHA 검증으로 기존 읽기 실패/EMPTY 30개 중 12개를 복구했다. 남은 18개는 과거 이미지 PDF·도면 등으로, 원문 텍스트가 없어 읽기 완료나 준비 안내 완료로 바꾸지 않았다. 실제 이미지 PDF의 페이지·이미지·폰트·텍스트 연산을 확인했다.

자동 v6로 현재 완료 발췌 369건을 재검수했지만 모두 HOLD였다. 아래 14건의 공개는 범용 자동 승인 실적이 아니라, 본문·Q&A·서식·다른 파일 형식을 모두 대조한 별도 원문 검토 결과다.

| 안내 상태 | 공고 |
| --- | --- |
| 준비 안내 제공 | 청주 다자녀, 거창 다자녀, 의령 다자녀, 인천·부천 정정 일반 매입임대 |
| 정상 부분 제공·쟁점만 확인 필요 | 김포·포천 청년, 창원 일반, 부산 일반, 군산 분양전환, 경남 분양전환 정정·비분양전환, 대구 분양전환 정정·비분양전환, 경기남부 정정 비분양전환, 제주 분양전환 |
| 확인된 정정본으로 연결 | 인천·부천 원본, 경남 분양전환 원본 |

각 지역 기준일·순위·세대 범위·예외·서류 면제·최초 신청과 후속 서류·분양전환 시점 검증을 구분했다. 2025년 예시 자산과 2026년 적용 자산을 충돌로 오인하지 않았고, HTML 계약 종료의 `9999.12.31` 같은 빈값 대체 날짜를 확정 일정에 넣지 않았다. 기관별 미기재 마감시각·결과발표일을 만들지 않았다.

## 최초 API 연결 회귀

최종 보존 검사에서 기존 청년 전세임대 원고 1건이 예약 수집 후 숨겨진 것을 발견했다. 백업·현재 내용은 바이트까지 같았고, 제목·공고일·기간·원문 URL도 같았다. 기존 지문과 수집시각이 null인 상태에서 첫 API 응답이 들어온 것이 원인이었다. API의 넓은 지역·유형 분류가 기존 상세 분류를 덮어썼다.

명확한 최초 연결·기존 공개 상태·자동 덮어쓰기 차단·정확한 원문/키/제목/공고일·유효 원고·기존 접수 경계 무충돌·감사 이력 일치 조건에서 지문/수집시각만 연결하도록 보완했다. 기존 지문이 있던 실제 변경은 여전히 재검토한다. 실제 기존 원고로 조건을 확인했고, 새 검수시각이나 관리자 이력을 만들지 않았다.

해당 한 건은 백업 메타와 현재 원문 해시·제목·기간·키·첫 API 지문·현재 HOLD 상태를 모두 잠금/조건 검사한 후 원래 공개 결정과 지역/유형을 복구했다. 본문과 기존 감사·개인 기록은 수정하지 않았다. 버전을 되돌리지 않고 4→5로 올렸으며 첫 수집 지문/시각은 보존했다. 기존 승인 18건의 본문·결정과 개인 준비 해시를 모두 대조했고, 이 한 건의 버전 증가만 별도 예외 기록으로 남겼다. 근거는 `cb715-source-fingerprint-investigation.json`, `cb715-binding-baseline.json`, `repaired-first-binding.json`이다.

- 공개 API에서 최신16건 모두 조회 성공. 안내14건(전체4/부분10), 정정본 연결2건. 질문·조건부서류·쟁점·근거·일정·canStart 관계 오류0. 접수 종료9건은 안내 열람만 가능하며 새 준비 시작을 허용하지 않는 기존 계약을 유지했다.
