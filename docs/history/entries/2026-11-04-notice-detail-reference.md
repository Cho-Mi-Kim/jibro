# 공고 상세 시안 반영과 표시 책임 분리

- 기록일: 2026-11-04 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 해결
- 유형: 개발 / 리팩토링 / 화면 QA
- 담당·검토: Codex 구현 및 별도 에이전트 읽기 검토·테스트 보조, 사용자 최종 시각 검토 미확인
- 관련 이슈·PR·커밋: 미등록. 기존 로컬 작업 브랜치에서 진행, 커밋·push 없음

## 배경·문제

사용자가 첨부한 공고 상세 시안을 이전 홈·공고 목록과 같은 기준으로 적용해 달라고 요청했다. 기존 상세는 정보와 행동이 큰 페이지에 섞이고 모바일 CSS가 여러 구간에 중복되어 있었다.

## 고려한 선택지

이미지의 네 칸 일정표·고정 날짜를 그대로 압축하는 대신 실제 공고와 GitHub 문서 글자 크기를 유지하는 반응형 배치를 택했다. 작은 글자 비교에서 사용자가 문서 기준을 선택한 기존 결정을 유지했다. 장문 요약 전체 상시 노출과 첫 문장+펼침을 비교해 전문을 보존하는 펼침을 사용했다.

## 결정·이유

393×852 모바일 중심으로 정보 카드 → 밑줄 탭 → 요약 카드 → 주요 행동 순서를 적용했다. 제목/본문 색상과 글자 기준은 `screen-spec.md` 3절·N02를 따른다. 시안의 가상 공고, D-5, 문서 쪽수, 준비 중 버튼을 복제하지 않고 실제 데이터·구현된 기능을 유지한다. 모바일 일정은 두 열로 읽고 768px부터 최대 네 열로 배치한다.

## 변경·해결 과정

페이지 조회/탐색과 Overview·Content·Actions를 분리했다. 날짜 가공과 탭 정의도 별도 모듈로 관리한다. 이전 상세 전용 CSS 39개 규칙을 삭제했다. 저장·공유·비교·홈 선택·첨부·캘린더 경로를 보존했다. 미검수 조건/서류와 상세 일정은 목록·요약·캘린더에서 일관되게 제한한다. 시작 의도는 클릭 시에만 생성하도록 회귀 테스트를 추가했다.

자동 검사에서 문구 변경에 따른 기대값과 과거 홈 제목 링크 변경에 뒤처진 테스트를 발견했다. 검수 차단 문구를 유지하고 홈 테스트는 현재 공고 제목 링크 및 선택 준비 건의 질문 경로를 함께 검증하도록 보완했다. 기존 파일 두 곳의 서식도 정리했다.

## 검증·결과

- `npm run ci`: 포맷·lint·타입·11개 파일 54개 테스트·빌드 통과.
- 상세 관련 새 테스트 3개 파일/14건: 실제 근거, 펼침, 조건/서류 이동, 미검수 상태, 날짜 누락/시각, 조회와 시작 의도 분리, 공식 원문 대체 행동.
- 브라우저 393×852 / 360×852: 가로 넘침 없음. 768×1024: 상단 메뉴 전환 및 네 칸 일정 확인. 키보드 오른쪽 화살표 탭 이동, 실제 조건/서류/일정 탭, 공유 창, 검색어 유지 목록 복귀, 검수 중 직접 탭 진입 확인.
- 최종 새로고침 뒤 새 콘솔 오류/경고 없음. 하단 주요 버튼과 고정 메뉴 겹침 없음. 저장·준비 시작 같은 사용자 기록 변경은 브라우저에서 실행하지 않고 테스트 데이터로 검증했다.
- 마지막 글자/터치 영역 및 보조 키 탐색 보완 후 lint·타입 포함 빌드 재통과. 실기기·모바일 글자 확대·운영 배포 검증은 수행하지 않았다.
- 캡처: `.tools/feature-qa/notice-detail-393-top.png`, `.tools/feature-qa/notice-detail-393-summary.png`.

## 기여·한계

화면 구현·코드 분리·자동 검사·브라우저 확인에 AI가 보조했다. 실제 담당자 개인 기여나 사용자 만족도 향상 수치는 확인하지 않았다. 안내 확인일은 현재 DTO에 없으므로 기본 정보 확인일과 안내 버전만 구분해 표시한다.

## 발표·포트폴리오 메모

시각 레퍼런스를 실제 공고 데이터와 제공 상태 규칙에 맞춰 적용하고, 화면 스타일 격리 및 회귀 테스트로 조회와 기록 행동을 분리했다.

## 후속 작업

### 2026-11-04 후속: 모바일 네 칸 일정 유지

사용자가 날짜가 없어도 시안의 배치를 우선해 달라고 요청하여 앞서 선택한 모바일 두 열을 네 칸 한 줄로 변경했다. 접수 기간·D-day·대상자 발표·서류 제출 마감의 자리와 구분선을 유지하며 후자의 날짜가 없으면 `확인 필요` 대신 공란으로 둔다. 미검수 일정 값은 여전히 노출하지 않는다. 같은 연도 기간은 MM.DD–MM.DD, 보조 날짜14px·D-day18px을 사용한다. 시작/마감 자체가 미확인인 기존 처리와 서버 데이터는 유지한다. 관련 날짜 테스트7건 및 빌드 통과, 393px에서 네 칸·빈 값·가로 넘침 없음 확인.

- 사용자가 실제 393×852 화면을 보고 요청하는 세부 여백 조정을 같은 작업 기록에 반영한다.
- 실기기와 글자 확대 검증은 별도 수행 가능하다.

### 2026-11-04 후속: 일정 박스 한 줄 표시에 대한 글자 크기 예외

사용자가 이 박스는 md 지침을 무시해서라도 글자를 줄이고 `일정 경과` 등 한 요소가 줄바꿈되지 않게 해 달라고 명시했다. 일정 영역에만 폭 기반 작은 글자와 nowrap을 적용했다. 모바일 설명 약10~11px, 마감 상태 약12~13px이며 다른 카드/본문은 변경하지 않았다. 데이터·준비 상태 계산은 그대로다. 연도 포함 긴 기간/글자 확대는 셀 사이 침범 대신 일정 박스 내부 가로 스크롤로 내용을 보존한다. 393×852 실제 종료 공고에서 상태/제목/기간 한 줄 및 날짜 공란 유지 확인, 빌드 통과.

## 변경 파일

### 글자 크기 시안 환산 후속

사용자가 같은 해상도에서 원본과 같은 글자 크기를 요청했다. 원본887×1774를393px 폭으로 환산한 시각 추정에 따라 일정명11px, 굵은 날짜14px, D-day16px, 보조 시각10.5px로 맞췄다. 원본 폰트 메타데이터가 없어 정확한 폰트 수치 복원으로 주장하지 않는다. 좁은 박스 폭에 비례해 지나치게 작아지던 값을 viewport 기준으로 변경했다. 393px 브라우저 계산값11/14/16/10.5px 확인, 한 줄 유지, 빌드 통과. 일반 기간의 미세한 가로 스크롤은 칸 여백을 줄여 정리했다.

후속 문구·색상 요청: 공고 상세 일정 칸의 `일정 경과` 표시만 `마감`으로 바꾸고 연한 강조 배경을 제거했다. 공통 날짜 계산 및 다른 화면의 마감 문구·색상은 변경하지 않았다.

후속 구분선 복원: 배경 제거 후에도 접수 기간과 마감 사이 세로선이 보이도록 두 번째 칸부터 모두 왼쪽 경계를 표시한다. 배경 없는 마감 칸의 불필요한 모서리 곡률도 제거해 선을 직선으로 유지했다.

## 2026-11-05 · 공고 상세 카드 정렬

Figma UI 디자인 원칙의 계층·근접성·정렬을 공고 개요 카드에 적용했다. 두 상태를 가까이 표시하고 제목·기관·공고일을 한 묶음으로 보인다. 신청 마감과 D-day는 일정표 위에서 읽도록 하고 접수 기간·결과 발표·서류 마감은 세 칸을 유지한다. 기간에 시간 줄이 추가되어도 세 라벨의 높이가 일치한다. 지역·유형은 하단 보조 정보로 분리하고 기본 정보 및 확인일은 상단 버튼으로 펼친다.

5173 실데이터 화면을 393·360·768px 브라우저에서 확인했다. 접수 종료 공고의 빈 날짜 두 칸과 접수 중 공고의 D-56, 18시까지 표시, 표·페이지 가로 넘침 없음 및 확인일 키보드 열기를 확인했다. 날짜·본문 테스트 13개와 lint/build가 통과했다. 증거는 `.tools/feature-qa/notice-overview-design-393.png`에 있다.

### 비교 시안 선택 · 일정 먼저

사용자가 ‘일정 먼저’를 선택했다. 공고일 아래에 신청 일정 제목과 마감 상태를 한 줄로 배치하고 그 아래 공식 일정 세 칸을 모았다. 구분선 아래에는 지역·주택 유형을 나란히 두었다. 날짜 공개 여부는 기존 검수 규칙을 따른다.

5173의 공고 세 건을 360·393·768px Chrome에서 확인했다. 신청 마감 및 D-day 표시, 빈 발표·서류 날짜 칸, 같은 너비의 두 칸과 가로 넘침 여부를 검증했다. 관련 테스트 15개, 프론트 빌드 및 lint가 통과했다. 393px 캡처는 `.tools/feature-qa/notice-schedule-first-393.png`에 있다.

### 준비 안내 확인 현황

공고 상세의 개요 카드와 정보 탭 사이에 처음에는 접힌 ‘준비 안내 확인 현황’을 추가했다. 펼치면 공고별 조건·서류 안내 상태와 확인 가능한 접수 일정을 보여준다. 공개된 질문·서류만 집계한다. 영역별 검수일이 따로 제공되지 않아 기본 정보의 근거 확인일만 한 번 표시한다.

360·393·768px 브라우저에서 검수 중 공고와 안내 제공 공고의 초기 상태, 열기·닫기, 위치 및 가로 넘침을 확인했다. Enter·Space로도 동작한다. 공고 상세 관련 테스트 21개와 빌드·lint가 통과했다.

사용자 후속 요청으로 현황을 개요 카드 안으로 합쳤다. 지역·주택 유형 아래의 ‘준비 안내 확인 현황’ 제목과 카드 우측 상단 화살표가 같은 펼침 영역을 조작한다. 펼치면 조건·서류·일정과 기존 버전·확인일이 함께 나타난다. 360·393·768px에서 공고 두 건의 기본 접힘, 두 클릭 위치, 키보드 열기·닫기와 가로 넘침을 확인했다. 관련 테스트 21개와 빌드가 통과했다.
