- 관련 이슈·PR·커밋: 이번 작업 원격 게시 없음

## 배경·문제

사용자는 가이드 하단의 사각 화살표와 현재 숫자 표시를 공고 목록 페이지 이동 UI와 같게 요청했다. 기존 가이드 응답에는 전체 페이지 수가 없어 전체 분량을 알기 어려웠다.

## 고려한 선택지·결정

기존 공고 CSS를 가이드에 복사하는 대신 `shared/ui/Pagination`으로 표시를 공유했다. 전체 페이지 수는 브라우저에서 전체 가이드를 추가 요청해 세지 않고 서버와 demo의 검색 결과에서 계산한다.

## 변경·해결 과정

공고와 가이드 모두 둥근 이전·다음 버튼, 상단 구분선, `현재 / 전체 페이지` 표시를 사용한다. 가이드 API에 `totalPages`를 추가하고 `hasMore`와 20개 단위 응답은 유지한다. 분류·검색 결과에 따라 페이지 수가 바뀐다. 각 화면의 URL·스크롤·검색 동작은 유지한다. 기존 개별 pagination CSS와 마크업은 제거했다.

## 검증·결과

- 프런트 기존 가이드 화면·demo 검사 9개, 타입·린트·계층 검사 10개·빌드 통과.
- 백엔드 기존 페이지 단위 4개·통합 2개, IntelliJ 서식·bootJar 통과.
- 5173 실행본 갱신·재시작 후 실제 가이드 1/2→2/2→1/2와 주제 선택 시1/1 확인.
- Edge 360/390/768px와360px 글자125%에서 공고와 가이드 버튼의 색·테두리·크기·여백 동일, 첫/끝 버튼 비활성화 및 가로 넘침 없음 확인. 실제 기기 검사는 아니다.
- 상세 로컬 기록: `.tools/qa/guide-pagination/`.

## 기여·한계 및 발표 메모

같은 역할의 UI를 공유하면서 서버 페이지 정보를 추가했다. 사람의 기여·사용성 만족도는 측정하지 않았으며 개선 수치를 주장하지 않는다. 공고 내용과 개인 기록은 수정하지 않았다.

## 후속 작업

추가 구현 없음. 향후 페이지 UI 변경은 공통 Pagination에서 적용한다.

## 변경 파일

`frontend/src/shared/ui/Pagination.tsx`, `Pagination.module.css`, `pages/GuidePage.tsx`, `pages/NoticePages.tsx`, 가이드 타입·demo·기존 검사·CSS, `backend/src/main/java/org/jibro/notice/GuideService.java`와 기존 페이지 검사.

## 후속 요청: 페이지 전환 시 질문 목록 상단으로 이동

사용자가 가이드 페이지 이동 시 질문 목록 위로 0.75초 스크롤을 요청했다. 기존 `window.scrollTo({top:0})`를 제거하고 클릭한 페이지가 렌더링된 뒤 질문 영역을 헤더 아래8px로 정렬한다. 공통 `animateScroll`의 750ms 토큰과 동작 줄이기 설정을 사용한다. 완료·취소 정리 콜백을 추가해 임시 높이를 해제한다.

느린 요청 중 목록 제거와 브라우저의 스크롤 앵커 추적으로 화면이 먼저 튀는 현상을 실제 재현했다. 전환 동안 목록 높이와 기존 하단 여백을 보존하고 해당 영역의 스크롤 앵커 추적만 잠시 중지해 해결했다. 첫 진입·자동 재조회에는 스크롤하지 않으며 검색 변경·이탈 시 예약된 이동을 정리한다.

기존 GuidePage 검사에 느린 응답·캐시·재조회·동작 줄이기 회귀를 추가했다. 실제5173의 Edge390/768px에서600ms 응답 지연과 이전·다음 이동을 확인했고 스크롤은754~761ms(화면 프레임 단위 측정), 질문 영역은 헤더 아래8px에 정렬됐다. 동작 줄이기는 한 번의 즉시 이동이었다. 전체 프런트 CI와 최종 관련 검사를 통과했다. 상세: `.tools/qa/guide-pagination-scroll`.
