## 배경·선택·결정

[리팩토링 지적 14건 수정](2026-11-24-refactoring-findings-fixed.md)을 사용자가 운영 사이트에 배포하도록 요청했다. 기존 Docker Compose·EC2·비공개 RDS 구성을 유지하고, 검증한 프런트와 새 bootJar만 패키징한다. 로컬 DB나 사용자 기록을 이관하지 않는다.

V47은 재인증 실패 기록을 공통 테이블로 옮긴 뒤 두 옛 테이블을 삭제하므로 이전 서버를 중지한 후 전환한다. 운영 설정과 JWT 서명은 그대로 유지한다. 전환 후 호환되지 않는 이전 백엔드를 자동 실행하거나 운영 DB 위에 덤프를 덮어쓰지 않는다. V47 적용 전 실패일 때만 스키마46을 확인하고 이전 서버를 다시 띄우도록 했다.

## 사전 확인·추가 수정

- 운영 시작 상태: `release-site-basics-google-tag-20261124`, 백엔드 healthy, Flyway46, DB 약2,282MiB, 공고19,406건. 개인정보는 집계만 확인하고 원문·비밀값을 출력하지 않았다.
- 패키지 `refactor-20261124-r2`의 258파일을 전송하고 파일 일치·운영 설정·Compose·Nginx 검사를 수행했다. runtime 설정은 서버 안에서 바이트 그대로 복사한다.
- 실제 이미지 검사에서 기존 `keepalive_timeout`이 기본 Nginx의 http 범위 설정과 중복돼 기동을 막았다. 전역1줄을 삭제하고 공개 HTTP/HTTPS 서버에 각각30초를 적용했다. 새 우회 경로 없이 해당 서버 책임에서 수정했다.
- 기존 `verify_edge.py`는 지역 변수 `http`가 모듈을 가려 실행되지 않았다. 연결 변수6참조를 `http_connection`으로 바꿨다. 검사 기준·예외 처리·요청은 유지한다.
- 추가·삭제: 위 설정 위치와 지역 변수만 변경. 새 제품 기능·미사용 wrapper·임시 제품 코드는 추가하지 않았다. `.tools/qa`의 작업용 배포 도구는 이번 스테이징/백업/전환에만 쓰며 상주 프로세스가 아니다.

## 검증

- 애플리케이션 검사는 직전 프런트887, 백엔드 단위1009, DB통합451 통과 결과를 재사용했다. 그 뒤 앱 소스는 변경하지 않았고 새 bootJar 빌드에 성공했다.
- 실제 서버에서 운영 이미지와 같은 파일을 사용한 격리 웹 검사7개 통과: HTTPS·뷰어 스크립트 해시, 내부 파일/잘못된 Host 차단, HTTP 인증서 갱신 경로, 전달IP 교체, 사람확인·메일·로그인 요청 제한, API 폭주 중 정적 화면, 컨테이너 권한/읽기전용 설정. 임시 인증서·가짜API·loopback 포트만 사용했다.
- 배포 중 바뀐 Python파일만 Iron Laws를1회 실행(앞선 전체 감사 반복 아님): 1파일/5지적, critical0/high0. 제한시간 내 기동 재시도는 끝까지 실패하면 예외를 내며, 고정 도메인·위조IP는 격리 입력이다. 함수 길이는 실제 시험 흐름으로 기각했다. 원본은 `.tools/qa/refactor-deploy-edge-iron-laws.json`에 남겼다.
- 독립 검토자는 Nginx 설정 책임과 Python 모듈 가림 수정·실제 CI 호출을 대조하고 추가 수정이 필요한 문제를 보고하지 않았다.

## 백업·전환 상태

DB 백업은 `/opt/jibro/backups/refactor-20261124/database.dump`(약1,270MiB)에 root 전용으로 저장했다. PostgreSQL17 임시 컨테이너에 실제 복원해 스키마46·테이블52개·공고19,406건·계정0·준비0을 확인했다. 컨테이너는 공개 포트 없음·메모리512MiB·초기CPU0.75로 제한했고 복원 막바지에 여유를 확인해 CPU1.25로 조정했다. 운영 연결은 TLS verify-full이며 백업·복원은 운영 원본에 쓰지 않았다. 임시 컨테이너/볼륨 및 자격 파일은 제거했고 백업은 보존했다.

이전 백엔드를 중지한 뒤 새 백엔드를 시작해 V47을 적용했다. 공통 `login_attempt` 유지와 옛 `account_connection_attempt`·`preparation_deletion_attempt` 제거를 확인했다. 이어 새 웹 이미지를 적용했고 `/opt/jibro/current`는 `release-refactor-20261124-r2`를 가리킨다. 운영 runtime 설정은 기존 파일과 바이트가 같으며 서명·메일·OAuth·Turnstile 값을 바꾸지 않았다.

최종 백엔드·웹 모두 healthy/재시작0. `production_doctor` 10검사 모두 통과했다. 공개 경로·보안 smoke 통과, 익명 공고 API는 기존 사람 확인 요구를 유지한다. 인증서87일·디스크 여유약7,270MiB·비밀 파일 권한·인증서 갱신 timer·보안 업데이트 service를 확인했다. 운영 공고19,406건은 유지됐으며 스키마 버전은47이다.

실제 Opera의 배포 전 목록116건 표시는 확인했다. 배포 후 새로고침은 브라우저 확장 UI 차단으로 실행하지 못했다. 이를 배포 후 공고 상세·로그인 UI 검증 완료로 계산하지 않는다. 공개 HTTP 검사와 서버 상태 검증은 완료했다. 실제 사용자 계정·메일 발송 시험은 수행하지 않았다.

로컬 실행 근거는 `.tools/qa/refactor-production-activation-result.json`, `refactor-production-restore-result.json`, `refactor-production-doctor-result.json`, `refactor-production-bootjar-20261124.log`다. 백업 본문·서버 비밀값은 로컬 산출물/Git에 포함하지 않았다.

## 기여·한계·후속

추가 AWS 자원·유료 플랜·DNS 변경은 없다. 실제 계정 OAuth 로그인 완료나 메일 발송을 배포 검증에 포함했다고 주장하지 않는다. 기존 GPT Pro 대화 연결은 사용할 수 없어 해당 리뷰는 미수행이다.

발표 메모: 실제 배포 이미지의 설정을 검증해 기존 기동 장애와 검사 도구 오류를 수정하고, 운영 DB의 실제 복원 성공을 확인한 후 스키마와 서버를 함께 전환했다. 운영 서버 검사 완료와 배포 후 브라우저 확인 제한을 구분했다.
