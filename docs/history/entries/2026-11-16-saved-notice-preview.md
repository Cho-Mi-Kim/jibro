# 관심 공고 카드 미리보기

- 기록일: 2026-11-16 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 해결
- 유형: 개발
- 담당·검토: Codex 구현·검증, 팀 검토 미확인

## 배경·문제

관심 공고의 제목을 누르면 바로 상세로 이동했다. 사용자는 저장한 여러 공고를 목록 안에서 먼저 살펴보기를 요청했다.

## 고려한 선택지

관심 공고 카드에 미리보기만 추가하거나 공고 목록의 카드 전체를 공유할 수 있었다.

## 결정·이유

같은 카드를 사용해 펼침, 스크롤, 상태 버튼과 상세 링크의 동작을 함께 관리한다. 접힌 관심 공고에는 기존 마감일과 남은 기한을 표시한다.

## 변경·해결 과정

관심 목록 화면을 저장·해제 기능에서 분리했다. SavedPage는 선택한 공고를 주소에 기록하고 NoticeCard에 전달한다. NoticePreview에서 상세로 이동하면 상세 상단의 돌아가기 링크가 해당 관심 공고를 다시 펼쳐 준다.

## 검증·결과

프론트엔드 빌드 및 테스트 435개 통과. 5173의 별도 체험 계정으로 Chrome 360·390·768px에서 펼침, 다른 카드 선택, 접기, 상세 진입·복귀와 가로 넘침 여부를 확인했다. 준비 안내 상태 버튼 및 관심 해제도 확인했다.

## 기여·한계

검증은 데스크톱 Chrome의 화면 크기를 조정해 진행했다.

## 발표·포트폴리오 메모

두 목록이 같은 카드와 공고 목록 데이터를 사용하므로 미리보기를 여는 동안 상세 자료를 추가로 요청하지 않는다.

## 후속 작업

팀 코드 검토.

## 상세에서 목록으로 돌아올 때 스크롤 복원

관심 공고 상세로 이동하면 이전 목록 컴포넌트의 위치 기록이 사라져, 복귀할 때 카드가 다시 상단으로 정렬됐다. 목록·비교·상세 경로가 같은 방문 위치를 공유하고, 미리보기의 상세 링크에서도 비교 링크와 동일하게 떠나는 순간의 위치를 보관하도록 변경했다. 복원 범위는 현재 방문이다.

5173의 Chrome 360·390·768px에서 일정 탭을 연 후 화면의 복귀 링크와 브라우저 뒤로 가기를 점검했다. 세 화면 모두 떠나기 전과 복귀 후 카드 위치 및 스크롤 좌표가 일치했다. 프론트엔드 빌드와 테스트 436개 통과.
