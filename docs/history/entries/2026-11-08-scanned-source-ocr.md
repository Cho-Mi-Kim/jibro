# 스캔 PDF와 도면의 원문 판독 복구

- 기록일: 2026-11-08 (Asia/Seoul)
- 기록 상태: 검증 결과 기록 완료
- 작업 상태: 구현·18개 원문 읽기 복구·실행 검증 완료
- 유형: 개발 / 문제 해결
- 담당·검토: Codex AI 보조 구현·교차 검증, 사람 검수 미실시
- 관련 이슈·PR·커밋: 미등록, 로컬 변경만 진행

## 배경·문제

이전 원문 복구에서 남은 18개는 PDF 17개(180쪽)와 HWP 평면도 1개(내포 이미지 5개)였다. PDF의 텍스트 레이어는 전부 비어 있었다. 사용자 요청에 따라 기존 문서의 OCR 미지원 범위를 확장한다. 읽기 복구와 조건·서류·일정의 검수 승인은 별개의 단계다.

## 고려한 선택지

- 같은 게시물의 HWP만 대체: 15개 공고에 읽힌 대체 표현이 있으나 다른 표현과 같다고 추정할 수 없고, 별도 도면·접수 마감 안내는 해결되지 않는다.
- 단일 OCR 결과나 평균 신뢰도만 채택: 실제 표의 전체 행·큰 평형 제목 누락, 숫자·알파벳 혼동을 발견해 완료·자격 승인 근거로 사용할 수 없다.
- 로컬 OCR의 페이지 전체 렌더와 분리된 보조 판독: 외부 모델로 원문을 보내지 않고 원문 위치·해시와 불확실성을 함께 보존할 수 있어 채택했다.

## 결정·이유

기존 native 텍스트 파서는 유지한다. 글자가 부족한 PDF 페이지와 HWP BinData만 별도 프로세스에서 읽는다. 조각 이미지·마스크를 쓰는 PDF는 페이지 전체를 합성하며 HWP 미리보기 썸네일은 읽지 않는다. 기본 판독과 표·희소문자 보조 판독은 별도 Part로 남기고 서로 합쳐 새로운 표 관계를 만들지 않는다.

OCR 결과에는 `[OCR · 원문 대조 필요]`를 보존한다. 조건·일정 컴파일러와 로컬 정량 사실 생성은 OCR만으로 확정하지 않는다. 공식 출처를 읽는 화면에는 판독문과 원문 링크를 제공하고 도면은 조건·서류·일정 대신 별도 참고 자료로 표시한다. 공개 원고와 개인 준비 기록은 변경하지 않는다.

## 변경·해결 과정

- 공식 Tesseract 5.5.3 Windows 배포와 고정 commit의 한국어·영어·OSD 모델을 검증하여 설치했다. 환경키는 OCR 프로세스에 상속하지 않는다.
- native 8초/128MiB, OCR 별도 300초/256MiB·1동시·40페이지/이미지·단일10MP/누적250MP·100만자 제한. 실제 실행에서 첫 20초 판독 제한이 부족해 45초로 조정하고, 단일 스캔 이미지의 불필요한 확대를 제거했다. 내부295초·부모300초·감시305초로 정리 여유를 둔다.
- 실제 내포 공고 8쪽에서 PSM3 지면분할 실패를 재현했다. 같은 정상 렌더에 PSM6을 적용하면 서류 표의 항목을 회복해 PDF의 기본 PSM1+보조 PSM6, HWP PSM3+보조 PSM11을 각각 저장한다.
- best 모델은 25쪽 공고를 두 방식으로 읽을 때 295초 한도에 도달했다. 같은 표에서 공식 fast 모델의 속도와 읽힌 항목을 대조하고 fast를 로컬 기본값으로 채택했다. 25쪽 최종 판독은 244.968초에 완료됐다. 철자·숫자 오독 가능성이 있으므로 자동 승인 경계는 유지했다.
- 청주·진천 공고 14쪽은 단일 평면도였다. 기본 판독은 비었지만 보조 판독에서 단지명·평형 제목을 읽었다. 두 호출이 정상 종료한 경우에만 빈 결과를 생략하고, 둘 다 비거나 호출 실패가 있으면 미판독 상태를 유지한다. 읽힌 도면 제목을 치수·구조의 완전한 해석으로 간주하지 않는다.
- 추출 실행 임대는 파일별 checkpoint와 10분 기준을 공유한다. 미판독 Part가 남으면 완료로 처리하지 않고 최대2회 재시도 후 부분 상태를 유지한다.
- 정확한 18개 manifest, 현재 revision·최신 추출 지문·원문 SHA·기존 실패 source를 대조해 복구한다. 새 자료로 바뀌면 이전 판독 결과를 적용하지 않는다.

## 검증·결과

- 원문18개 총73,105,412바이트를 공식 주소에서 받아 기존 SHA와 전부 일치 확인.
- 대표 PDF2페이지와 HWP5도면 시각 대조·판독 방식 비교. 김포 마감 안내의 인쇄된 합계 불일치, 도면의 평형/호수 오독과 누락을 임의 정정하지 않았다.
- 18개 첨부(공고17건)의 PDF180쪽·HWP5이미지에 모두 비어 있지 않은 판독 결과를 저장했다. 최종368개 판독 Part이며, 청주·진천 두 파일은 두 호출 모두 정상 종료한 뒤 빈 기본 판독1개씩만 제외됐다. 페이지/이미지 누락과 실패 표식은0개다. 이는 전체 글자의 정확한 전사를 검증했다는 뜻이 아니다.
- 최종17건 공개 API를 조회해18개 첨부 모두의 OCR 발췌가 화면에 제공됨을 확인했다(총103구간). 각 발췌의 위치·본문이 저장한 판독문과 정확히 일치한다. 공식 출처/현재 revision/원문 SHA/최신 추출 레코드도 대조했다.
- 대상17건의 `guideState=REVIEWING`, `canStart=false`를 유지했다. 판독 결과가 자격·서류·일정의 자동 승인으로 바뀌지 않았다. 기존 승인 원고32건의 버전·revision·결정·본문 해시와 개인 준비 기록(0건) digest가 작업 전후 일치한다.
- 최종 코드 단위441건, 변경 전후의 파서 경계34건 통과. 이번 빈 판독 처리 보완 직전 DB통합265건 통과(보완에서 DB 코드는 변경하지 않음). 실행 JAR 빌드 성공. 프런트 관련18건·lint·타입·build 통과, 기존 번들 크기 경고는 남는다.
- 393×852와360×800 브라우저에서 도면/스캔 원문 펼침, 공식 첨부 링크, 가로 넘침0, 콘솔 오류0을 확인했다. 실제 휴대전화 검증은 수행하지 않았다. 내부 판독 방식·HWP 저장 경로는 화면에서 읽기 쉬운 제목으로 표시하고 저장 원문은 변경하지 않는다.
- 최종 서버를 재시작해5173의 health200과 실행 JAR 일치를 확인했다. JAR SHA-256: `92f1d46cc2a9fa9cf561ebaf0316dd871ad0c186713aba3a2ff0616c31086804`.
- 근거: [실행·품질 검증 보고서](../../reviews/2026-11-08-ocr-source-recovery.json), `.tools/qa/ocr-recovery/`, `.tools/backups/before-ocr-recovery-20261108.dump` (QA 원문·로컬 백업은 Git 제외).

## 기여·한계

AI가 구현·실행·대표 시각 대조를 보조했다. 직접 시각 대조는 PDF5쪽과 HWP5이미지이며, 나머지는 페이지/출처 범위 검사와 native HWP15건의 대표 본문 대조다. 185개 페이지/도면의 모든 글자·표 셀에 대한 사람 검수나 완전한 도면 의미 해석은 수행하지 않았다. 실제로 일부 연도·자녀 수·소득 금액의 OCR 오독과 원문 자체의 연도·합계 모순이 확인됐으며, 값을 임의 수정하지 않았다. 높은 OCR 신뢰도와 텍스트량은 완독·원문 일치의 증명이 아니다. 실제 신청 판단은 공식 원문 확인이 필요하며, 이 작업은 안내의 일괄 승인이 아니다. Docker 배포 이미지에는 OCR 실행파일·모델이 아직 포함되지 않는다.

## 발표·포트폴리오 메모

텍스트가 없던 공식 자료를 읽는 경로를 추가하면서, 판독 성공과 업무상 승인을 분리했다. 대표 표 누락을 실제 재현하고 보조 판독과 출처 추적을 보완했다. 개인·팀 기여 귀속은 사람 확인 후 정리한다.

## 후속 작업

- 운영 환경은 Tesseract/모델 설치와 메모리·임시 저장소·실행 제한을 별도 검증한다.
- OCR의 수치·표 관계·도면 의미를 안내에 사용할 때는 원문 대조와 별도 검수를 수행한다.
