## 배경과 결정

사용자는 첫 질문에서 선택한 신청 유형에 맞춰 다음 질문 자체가 달라지기를 요청했다. 포항블루밸리의 청년은 주택 심사를 본인만 받지만 기존 입력은 모든 유형에 ‘내 신청 유형의 주택 보유 기준에 맞나요?’를 표시했다. 후속 요청으로 내 준비·일회성 확인에서 산업단지 근로자 등 다른 유형 전용 질문도 건너뛰도록 범위를 확장했다.

입력 제목만 집이 없는지 묻고 기존 MEETS를 무주택 답변으로 바꾸면 허용 주택 예외와 저장된 답변의 의미를 좁히게 된다. 기존 값은 ‘선택 유형의 기준에 맞음’으로 유지하면서 제목·도움말·선택지 설명을 함께 구체화했다. 새 질문 ID·자격 판정·공고 버전·서류 연결 변경은 필요하지 않았다.

## 후속 요청: 공통·선택 유형 질문만 표시

입력에서만 질문을 숨기는 대안은 채택하지 않았다. 산업근로자 질문에 모름·불충족으로 답한 뒤 청년으로 바꾸면 숨긴 질문이 결과와 서버 진행률에는 미완료로 남을 수 있기 때문이다. 기존 `preparationApplicability`의 전용 유형 판정을 입력·결과에서 공유하고 Java도 같은 계약으로 맞췄다. 공식 검수·실제 답변 모순을 먼저 보존한 뒤 확정된 다른 유형을 제외한다. 유형 미확정이나 유형이 혼합된 기준은 유지한다.

- `applicantInputQuestions`는 전체 질문·답변·검수 상태만 받고, 원래 입력 역할 분류와 조합한다. `matchesSelectedType`의 같은 판정을 결과에 재사용한다. 실제 ‘산업단지 근로자로’의 조사 인식 누락도 수정했다. 별도 전용 질문 목록·가짜 preparation 문서·화면별 필터를 만들지 않았다.
- 두 입력의 이전/다음·개수·미확인 큐를 같은 선별 목록으로 교체했다. 일회성은 숫자 위치 대신 현재 질문 ID를 유지하고, 내 준비는 저장 성공 후 새 목록으로 이동한다. 새로 나타난 질문은 미확인 전용 흐름에서도 다시 질문한다.
- 포항 청년은 6개, 산업근로자·유형 모름은 7개 입력 질문이다. 숨긴 질문의 답변을 지우거나 자동으로 비해당·긍정으로 저장하지 않는다. 결과·홈 진행률·다음 행동도 확정 비해당 질문을 미완료로 세지 않는다.
- 주택 선택지는 ‘없거나, 공고에서 허용하는 소형·저가주택 등이 있어요’로 변경했다. 공식 PDF 3쪽에는 소형·저가주택 외에 포항 밖 주택도 허용하므로 ‘소형’만으로 의미를 좁히지 않고 기존 참고 설명을 유지했다.
- 기존 work=NOT_MY_TYPE와 이후 INDUSTRIAL의 별도 모순 규칙을 새로 도입하는 것은 공고 질문 계약·버전 변경에 해당하므로 이번 범위에 넣지 않았다. 재노출된 질문에서 다시 확인할 수 있고 기존 답변을 자동 조작하지 않는다.

## 다른 공고까지 분기 확장

사용자는 다른 공고도 선택한 신청 유형에 따라 공통·해당 질문만 나오도록 요청했다. 같은 공통 selector가 이미 두 입력에 연결되어 있으나, 실제 공고의 MARRIED·PROPOSED·SENIOR·STUDENT·WORKER 등 선택값과 계층 표현을 기존 제한된 어휘가 놓치고 있었다. 춘천·철원 공고는 계층별 질문이 신청 유형 질문보다 앞에 있어, 필터 확대만으로는 신규 사용자가 무관한 질문을 먼저 답하게 된다.

기본 목록의 공개 상세 122건(준비 안내 제공 106건, 원본 질문 1,474개)을 읽기 전용으로 조사했다. 개인 준비 기록이나 접수 상태·공고 내용은 바꾸지 않는다. 공통 정책에서 선택지의 명시된 의미를 정규화하고 유형 선택을 전용 질문보다 먼저 배치한다. 가점과 공급형처럼 서로 다른 축, 신생아가구처럼 혼인 상태를 알 수 없는 선택, YES/NO만 있는 공고는 유형을 추정하지 않는다.

단순 접두부 확대와 모든 답변 의존성의 역해석은 기각했다. ‘신혼·한부모’ 제목에도 예비신혼이 포함될 수 있고, 답변 의존성은 필수 서류를 추가하는 단방향 관계이기 때문이다. 명확한 전용 제목에 대해 의존성은 대상 범위를 넓히는 용도로만 사용한다. 비해당 질문에 직접 연결된 서류는 같은 정책에서 제외해 미확인 서류로 진행률을 막지 않도록 하되, 공통 서류·공식 검수·실제 모순은 보존한다. 원래 답변·서류 메모·완료 상태는 수정하지 않는다.

기존 `preparationApplicability`가 입력·결과·서류의 범위를 계속 소유한다. Java `PreparationApplicability`와 `PreparationRules`의 서류 필터도 연결해 공통 계약을 유지한다. 새 공고별 화면·DB 필드·서버 API·자동 긍정 답변을 만들지 않았다. 제한된 선택값 판정과 기존 서버의 필요도 단독 서류 필터 두 곳을 교체했다. 다른 답변 때문에 필요한 서류는 기존 `AnswerDependencies`의 확정·미확정 필요도 계산을 재사용해 보존한다. 임시 실행 분기나 대체 구현을 남기지 않았다.
