- 관련 이슈·PR·커밋: 미등록; feature/launch-integrations-20261107 e288a99 기존 변경 보존

## 배경·문제

사용자가 앞서 원공고 연결을 조사한 두 정정본의 오래된 접수기간을 지적하고 종료 반영을 요청했다. LH 상세는 두 건 모두 공고중이고 마감일이 비어 있었다. DB start_date/end_date/application_start_at/application_end_at도 모두 NULL, 원문 상태 source_closed=false여서 UNKNOWN으로 기본 목록에 남았다. 앞선 정정 관계 조사에서 기간까지 바로잡지 못했다.

## 고려한 선택지

- 공고일이 오래됐다는 이유 또는 source_closed 플래그를 임의로 변경: 근거와 원천 의미를 훼손하므로 제외.
- 공식 첨부의 실제 신청기간을 확인해 기존 ApplicationPeriod 계산으로 CLOSED: 채택.

## 결정·이유

공식 상세와 첨부 PDF/HWP를 새로 읽고 양쪽 SHA가 직전 자료와 같음을 확인했다. 파주 정정 PDF는 전체7쪽 중3쪽만 담긴 발췌여서 전체 HWP도 함께 확인했다. 충주는 PDF2쪽의 신청일정 및 장소를 시각 대조했다.

## 변경·해결 과정

기존 NoticeRepository의 행잠금·revision/내용/지문 재확인, NoticeService.validateContent, ApplicationPeriod.resolve를 사용하는 일회성 자료 보완을 실행했다. 날짜·시각과 근거 있는 신청 시작/마감 일정 두 항목만 추가하고 각 revision2→3/version1→2로 갱신했다. SourceReviewRepository에 VERIFIED_HISTORICAL_APPLICATION_PERIOD 감사와 원문 SHA·변경 전 내용·변경 후 일정을 기록했다. 새 공개 API나 상태판정 규칙은 만들지 않았다.

원천 API 상태를 뜻하는 source_closed=false와 기본 PASS/준비안내 HOLD, 제목·기타 내용·정정 관계는 유지했다. 공고/첨부 재확인은 트랜잭션 밖에서, 두 자료 반영은 한 트랜잭션에서 수행했다. 개인 준비 테이블을 수정하지 않았다. 종료공고 전체 검수는 하지 않고 요청된 두 건만 처리했다.

## 검증·결과

- 5173 상세 API 두 건 CLOSED, 시작·종료 날짜와 16시(KST) 확인, nextChangeAt=null, canStart=false.
- 기본 목록 82→80, 두 ID 제외 확인. 기본 목록의 접수종료 후28일 규칙에 따라 제외되며 원본 상세는 남는다.
- 검수/원천 상태와 기존 정정 관계 전체 보존 확인. 감사 파일: `docs/reviews/2026-11-11-legacy-application-closure.json`.
- 앱 코드 변경이 없는 데이터 보완이라 새 빌드·재시작·전체 테스트는 수행하지 않았다. 실행 중인 서버에서 반영을 확인했다.

## 기여·한계

AI 자료 검토·실행이며 기관의 홈페이지 상태를 수정한 것은 아니다. 모든 과거 공고의 기간 누락을 해결했다고 주장하지 않는다. 접수기간과 무관한 준비 안내 검수는 그대로 보류다.

## 발표·포트폴리오 메모

공식 목록 상태가 낡은 자료에서 첨부의 정확한 접수기간을 출처와 함께 보완하고 기존 기한 판정으로 종료 처리했다.
