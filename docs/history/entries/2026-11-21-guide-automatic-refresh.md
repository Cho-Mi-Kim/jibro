# 공식 안내 변경에 따른 가이드 자동 재확인

- 기록일: 2026-11-21 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 해결
- 유형: 개발 / 문제 해결
- 담당·검토: Codex 구현·검사 보조, 사람 담당·검토자 미확인
- 관련 이슈·PR·커밋: 이번 작업의 원격 게시 없음

## 배경·문제

사용자는 LH·정부24 등 공식 안내가 바뀌면 가이드 내용과 출처 링크도 자동으로 확인하고 반영해 달라고 요청했다. 앞서 공식 자료로 검토한 36개 FAQ와 37개 출처가 정적 원고에만 있어 이후 변화를 추적하지 못했다.

## 고려한 선택지

- 화면을 열 때마다 외부 원문과 모델을 호출하는 방식: 화면 응답과 외부 사이트 상태가 결합되고 같은 자료를 반복 처리한다.
- 매일 서버에서 원문 변경을 확인하고 영향받은 FAQ만 검토하는 방식: 마지막 정상 안내를 유지하며 변경 이력·할당량·재시도를 관리할 수 있어 채택했다.
- 접속 성공만으로 확인일 갱신: 변경된 내용의 검증 여부를 알 수 없어 제외했다. 이전에 검토한 내용과 동일할 때만 분석을 생략한다.

## 결정·이유

서버가 실행 중일 때 매일 06:00 KST에 확인하고 놓친 일정은 재시작 후 처리한다. 확인된 내용 변경과 같은 기관의 유효한 링크 이동을 반영한다. 모호한 자격·예외 변경이나 접근 실패는 기존 안내와 재확인 상태를 유지한다. 공고 검수·개인 준비 데이터와 구분하며 서버 없는 demo는 마지막 배포 원고를 사용한다.

## 변경·해결 과정

`GuideSourceClient`가 허용된 공식 본문과 알려진 LH 첨부 PDF를 제한된 자원으로 읽고 정규화한다. 메뉴·방문자 수·요청 시각 변화는 제외한다. 서울주거포털에서 본문 없는 GET 요청에 붙은 헤더 때문에 오류 페이지로 이동하는 문제는 표준 GET으로 해결했다.

`GuideContentReviewPlan`은 이전·현재 자료의 관련 문단만 추려 기존 Gemini 전역 할당량으로 검토한다. 검증기는 실제 인용·수치·예외·대상과 출력 형식을 확인하고 모델이 링크나 질문 식별자를 만들지 못하게 한다. `GuideRefreshRepository`는 기준 원고와 출처 버전·수정 번호를 게시 직전에 대조하고 변경 전후 이력을 보존한다. 중단된 작업 잠금은 회수하고 진행 중에는 갱신한다.

`GuideFreshnessNotice`와 현재 페이지 재조회로 서버의 반영 결과를 표시한다. 내용 확인일과 재시도일을 구분하고 접속 실패가 내용 확인으로 처리되지 않게 했다. 기준 원고를 새로 배포하면 옛 원고에 대한 자동 변경을 적용하지 않는다.

## 검증·결과

- 실제 공식 출처 37개와 관련 LH 첨부 PDF 판독 성공.
- 현재 FAQ 36개의 관련 문단 패킷 생성 성공, 최대 4,017자(한도 18,000자).
- 실제 DB에 당일 검토 원고 36개와 공식 출처 37개 기준 등록. 즉시 재실행은 수집 0회·AI 호출 0회였고 다음 점검은 2026-11-22 06:00 KST로 저장됐다.
- 프런트 CI: 84개 파일·646개 테스트, 계층 검사 10개, 타입·린트·서식·빌드 통과.
- 백엔드 전체 단위 검사: 836개 통과, 외부 사이트를 실제 요청하는 명시 실행용 검사 1개는 일반 실행에서 제외. 가이드·샘플 숨김 통합 검사 22개(신규 자동 갱신 18개 포함) 통과. bootJar 빌드 성공.
- IntelliJ 서식 재적용 비교: 가이드 관련 Java 26개 모두 변화 없음.
- 5173 재시작 뒤 health/DB UP, 실제 API 36개 CURRENT, 자동 작업 실행 기록 확인. Edge 360/390/768px 및 360px 글자 125%에서 정상·재확인·접속 실패 표시 12조합 통과. 경고 상태는 응답을 격리해 재현했으며 실제 기기 검사는 아니다.
- 실제 Gemini 검수 요청은 전역 당일 할당량에서 `DEFERRED / GUIDE_AI_DAILY_LIMIT`로 차단. 추가 요청 0회·게시 변경 없음. 실제 제공자의 응답 스키마 검증은 미실행이며 로컬 계약 검사 결과와 구분한다.
- 근거: [검증 기록](../../reviews/2026-11-21-guide-auto-update/README.md).

## 기여·한계

AI 보조로 수집·검수·저장·표시를 분리하고 회귀 검사를 작성했다. 자동 게시 범위는 근거와 수치·예외 보존 검사로 확인된 변경이다. 출처 자체의 자격·예외 범위 변경이나 모순은 별도 검토가 필요하며, 알려지지 않은 대체 주소를 추측하지 않는다. 실제 미래의 공식 변경 사건은 아직 발생하지 않아 변경·장애·경합 시나리오는 통제된 테스트 자료로 검증한다. 서버가 꺼진 동안에는 점검이 실행되지 않는다.

## 발표·포트폴리오 메모

정적 FAQ의 유지보수 문제를 본문 변경 감지·출처별 재검토·검증 후 게시로 해결했다. 실제 외부 자료 판독, 재시작·재시도·동시 수정 방어를 나누어 검증했다. 개인 기여와 사용자 체감 효과 수치는 담당자 확인 후 사용한다.

## 후속 작업

- 실제 공식 변경이 발생하면 저장된 검수 이력과 재확인 항목을 운영자가 검토한다.
- 운영 서버에서 실행하면 같은 예약 기능을 사용한다. 클라우드 배포는 이번 작업에 포함하지 않는다.
