일정에도 마지막 완료 후 상단 이동 적용: 공고·개인 답변이 반영된 buildScheduleTimeline의 기록 가능한 일정이 저장 후 모두 완료인 경우 ScheduleRecordCard를 접고 준비 패널 또는 창을 top0으로 이동한다. 기존 animateScroll의750ms·동작 줄이기를 공유하며 실패/취소/중간 완료는 기존 동작을 보존한다. 마지막 완료·완료 취소·실패 재시도의 기존2검사를 보완해 통과했고 타입·변경 코드 lint도 통과했다. 5173 코드 반영, 실제 사용자 기록 변경이나 운영 배포 없음. 근거 .tools/qa/schedule-final-top-20261123.log.

최종 완료 후 상단 이동: 사용자가 모든 준비 대상 서류를 완료하면 페이지 최상단으로 이동하도록 요청했다. DocumentsPage의 완료 후 선택 경로에서 선택을 해제하고 렌더 반영 뒤 실제 준비 패널 또는 창을 기존 animateScroll로 top0 이동한다. 750ms·동작 줄이기 기준을 유지하고 이전 카드 스크롤과의 경합을 막았다. 기존 저장/취소 테스트를 마지막 대상까지 완료하는 흐름으로 보완하여 펼친 카드 없음과 top0 이동을 확인했다. 타입·변경 코드 lint 통과, 5173 반영. 실제 사용자 기록은 수정하지 않았다. 실행 근거: .tools/qa/document-all-ready-top-20261123.log.

## 후속: 준비 완료 후 다음 미완료 서류

완료 저장에 성공하면 DocumentsPage가 최신 응답의 최상단 공통/조건부 미완료 서류를 선택한다. 해당 DocumentEditor가 선택 반영 뒤 기존 750ms 상세 상단 스크롤을 수행한다. 실패 시 현재 서류를 유지하고, 완료 취소·일반 메모 저장은 기존 동작을 따른다. 남은 대상이 없으면 완료한 카드를 접는다. 공식 검수로 저장이 막힌 항목을 임의 선택하지 않는다.

## 배경·결정

PC에서 왼쪽 서류를 선택해도 오른쪽 상세 시작이 화면 상단에 맞춰지지 않았다. 기존 스크롤은 목록 행을 가리키지만 상세는 목록 전체 영역 상단에 별도로 배치된다. 기존 스크롤 경로에 실제 대상 선택만 추가하여 750ms 애니메이션·동작 줄이기·실제 스크롤 컨테이너 처리를 공유한다.

## 변경

`useScrollToCard`의 선택적 대상 resolver를 `usePreparationCardSelection`이 전달한다. `DocumentEditor`는 펼쳐진 상세가 실제 absolute 배치일 때 상세를 선택하고, 모바일 static 배치나 접힌 뒤에는 기존 행을 선택한다. CSS breakpoint를 복제하거나 별도의 스크롤 함수를 만들지 않는다. 서류 내용·저장·상태·메모 규칙은 유지한다.

## 검증·한계

관련 Vitest4파일9개, TypeScript, 변경3파일 ESLint·Prettier 및 공백 검사를 통과했다. 로컬5173의 1920px 브라우저에서 주민등록표등본 선택 및 다른 서류의 키보드 선택 후 오른쪽 상세가 준비 패널 상단12.375px에 정렬됐다. 모션 토큰750ms와 창 자체 스크롤0을 확인했다. 390px 키보드 선택은 기존 행 상단12.28125px·상세 static, 360/390px 가로 넘침0을 확인했다. 실제 모바일 기기·터치 검증과 구분한다. 기존 서버에 최신 프런트 코드를 반영했으며 운영 배포나 push는 하지 않았다.

## 후속: 목록 준비 상태와 미완료 우선 배치

사용자가 내 준비 서류 목록에서 펼치기 전에도 준비 상태를 보고, 미완료를 먼저 보도록 요청했다. 이 편집 목록은 기존의 서류명만 표시하는 접힌 상태 규칙을 개정한다. DocumentCard가 편집용 상태를 항상 표시하고 기존 DocumentStateBadge를 그대로 사용한다. 제목은 버튼 이름, 상태는 접근성 설명으로 분리하여 읽는다. 제출 대상·발급 방법은 계속 펼쳤을 때 표시한다.

DocumentsPage는 미완료 공통·조건부, 공식 확인 필요, 준비 완료 순서로 표시한다. 완료·취소가 저장되면 같은 규칙으로 다시 배치한다. 이전 그룹별 편집기 반복을 한 목록으로 교체하여 이동 중 편집기가 재생성되지 않고 저장 후 접힘·메모·스크롤 상태를 유지한다. 공식 확인 필요의 저장 차단과 해당 여부 불명 항목의 별도 안내는 유지한다.

관련3파일76검사, 완료/취소 정렬을 보완한 기존 저장 테스트1건 재실행, 타입·변경파일 ESLint/Prettier·공백 검사를 통과했다. 실제5173의 PC1920px에서 접힌 서류6개의 완료 표시를 확인했고 360/390px에서 상태와 버튼 가로 넘침0을 확인했다. 실제 기록은 조회만 했으며 완료·취소의 상태 전환과 정렬은 격리된 기존 테스트에서 확인했다. 브라우저 크기 검증과 실제 기기 터치를 구분한다. 화면과 실행 로그는 `.tools/qa/document-status-list-20261123/`, `.tools/qa/document-list-tests-20261123.log`, `.tools/qa/document-list-sort-20261123.log`에 보관했다. 5173 반영 완료, 운영 배포·push 없음.
