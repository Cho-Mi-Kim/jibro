## 배경·문제

76개 접수 중·예정 공고 중 서울 영구임대와 정정 수원당수1·2는 PDF·한글본 전체 문맥 대조가 끝나지 않아 준비 질문과 서류를 공개하지 못했다. 사용자가 두 공고의 자격·예외·서류를 항목별로 대조하고 확인된 내용을 내 준비·일회성 확인에 반영하도록 요청했다. 접수종료 공고는 제외했다.

## 고려한 선택지와 결정

자동 검수의 문서 일치 기준을 낮추지 않고 기존 수동 SourceReview 검수·게시 경로를 사용했다. 실제 공식 PDF, 동일 모집의 HWPX, 첨부 양식을 대조하여 기존 Content 계약의 questions/applicability/documents/conditionAnswerValues/schedules를 채웠다. 제품 코드·필터·새 게시 경로는 추가하지 않았다.

## 변경·해결 과정

- 서울: 2026.11.19 공고의 1순위 신청 자격 9종, 성년·미성년 세대주 예외, 무주택 세대 범위, 소득·자산과 자녀 가산, 분리 예정 세대, 공통·자격별 서류, 주민센터·대리신청을 구분했다. 15개 질문, 34개 서류 항목, 3개 일정으로 연결했다.
- 수원당수: 2026.11.18 공고 최신 정정본과 날짜·요일·최대전환 보증금 오기 정정 안내를 확인했다. 대학 재학·입학·복학·졸업 예정, 취업준비생, 청년·사회초년생, 주거급여 유형을 구분했다. 본인/세대 무주택 범위, 소득·총자산 배제와 자동차 기준, 경력 제외, 청약통장·계층별 서류, 온라인/현장 회차, 선계약 후검증 안내를 반영했다. 21개 질문, 38개 서류 항목, 8개 일정이다.
- 수원당수 주거급여 유형의 14형 선택은 기존 답변 모순 규칙으로 경고한다. 실제 자료에서 주거급여는 26형만 가능함을 확인했다.
- PDF 자격·서류 표를 이미지로 확인했다. 관련 40개 PDF 쪽의 긴 문장 1,126개를 HWPX와 대조했고 수원당수 20쪽의 열 연결 한 줄만 비연속 추출이었다. 자격·예외·서류 기준의 상충으로 취급하지 않았다. 문장 일치 검사는 표 의미의 시각 확인을 대체하지 않는다.
- 기존 SourceReviewVerifier가 게시 직전 상세 문맥·첨부 파일을 다시 확인했다. 현재 공식 상세 2개와 첨부 9개가 대조한 자료와 동일함을 확인했다. PDF 쪽수 근거와 공식 서식 링크를 연결했다.
- 신청 방식 질문이 기존 회차 필터의 `방법/방식` 계약과 맞지 않아 온라인 선택 후에도 현장 회차가 남는 것을 실제 소비 검사로 발견했다. 해당 질문을 “인터넷·현장 중 어떤 방식으로 신청하나요?”로 바로잡았다. 새 필터나 공고별 제품 분기를 추가하지 않았다.
- 재게시 전 추출 revision 불일치가 정상 차단됐다. 현재 revision으로 기존 추출기를 실행했고, QA 실행에 빠졌던 document-parser-worker.jar 설정을 명시해 READY로 완료한 다음 재검수했다. 검증기를 우회하거나 판독 실패를 성공으로 바꾸지 않았다.

## 검증·결과

- 두 공고 모두 접수 예정이고 canStart=true, guideState=AVAILABLE. 최종 로컬 버전은 두 공고 모두 v4다.
- 기존 게시 서비스의 트랜잭션 검증으로 개인 준비·보관 기록과 이전 게시본 불변 확인.
- 실제 NoticeService·PreparationSnapshots·OneTimeCheckService로 22가지 조합 검사: 신청 유형별 질문, 필요한 증빙, 온라인/현장 회차, 대리신청, 주거급여 14형 모순 안내 통과.
- 실제 프런트 preparationApplicability 모듈을 Vite로 로드한 같은 22가지 검사 통과. 내 준비/일회성 질문·서류·일정 표시와 서버 결과를 대조했다. 처음 Rolldown 단독 로드는 Vite glob을 처리하지 못해 실패했으며, 제품 실행 도구인 Vite로 검증했다.
- 5173 상세 조회 및 CSRF 포함 일회성 확인 POST 22가지 실제 요청 모두 200/no-store, 저장형과 같은 질문·서류 결과 확인.
- 원래 76개 공고의 공통 소비 경로 재검사: 76 PASS. 이는 76개 모두 모든 예외가 자동 확정됐다는 뜻이 아니라, 현재 공개 안내가 두 소비 경로에 연결됨을 확인한 수치다.
- 실제 사용자 준비를 새로 저장하거나 브라우저·실기기 화면을 조작하지 않았다. 제품 코드 변경이 없어 전체 CI는 재실행하지 않았다. AWS 배포·push 없음.

## 기여·한계와 발표 메모

자료의 판독과 검수·공개를 분리하고, 확인된 공식 기준을 하나의 질문·서류 계약으로 두 화면에 전달했다. 사용자 답변은 준비 범위를 고르는 용도이며 최종 입주 자격을 판정하지 않는다. 개인별 예외 증빙은 계속 추가 확인으로 표시한다. 별도 검토자의 원문 승인이나 실사용 만족도 측정은 수행하지 않았다.

## 후속 작업·근거

이번 두 공고의 요청 범위에서 보류된 안내는 없다. 추후 원문 변경은 기존 재검수 절차를 따른다. 임시 QA는 `.tools/qa/active-detached-20261123/last-two`에 있으며 제품·예약 실행 경로가 아니다. 검토 보존 필요가 끝나면 제거할 수 있다. 주요 결과는 initial-apply-results.json, apply-results.json, final-source-identity.json, consumer-cases.json, frontend-cases.json, live-cases.json과 상위 consumer-results.json에 있다.
