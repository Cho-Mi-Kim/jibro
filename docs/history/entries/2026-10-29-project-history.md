# 발표·포트폴리오에 활용할 프로젝트 기록 자동화

- 기록일: 2026-10-29 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 로컬 구현·검증 완료, 팀 적용 확인은 후속
- 유형: 협업 / 문서 / 개발 자동화
- 담당·검토: 사용자가 목적을 제시하고 Codex가 구현·기록을 지원. 팀원 검토 전
- 관련 이슈·PR: 미등록. 작업 브랜치는 `chore/docs-project-history`이며 사용자 요청에 따라 커밋·push한다. 실제 커밋은 이 파일의 Git 이력에서 확인

## 배경·문제

팀원이 변경사항을 이해하고 발표·포트폴리오에서 문제 해결 과정을 설명하려면 무엇을 바꿨는지뿐 아니라 왜 선택했는지, 어떻게 확인했는지, 누가 어떤 역할을 했는지가 필요하다. Git 변경 파일만으로는 당시의 고민·회의·검증 성공을 알 수 없다.

## 고려한 선택지

- 수동 양식만 두면 작성 부담으로 누락될 수 있다.
- Git 기록만 수집하면 변경 흔적은 남지만 판단 근거가 없는 내용까지 추정하기 쉽다.
- Codex가 관찰한 작업 맥락을 정리하고 Git hook을 누락 보완 수단으로 사용하면 두 종류의 정보를 구분할 수 있다.

## 결정·이유

Codex 작업 지침에 기록 갱신을 포함하고 Git 커밋 직전에는 stage된 변경 사실만 자동 수집하기로 했다. 충분한 작업 기록이 함께 stage되면 자동 초안을 중복 생성하지 않는다. 관찰하지 않은 이유·개인 기여·성공 수치는 ‘보완 필요’로 남긴다.

## 변경·해결 과정

- `AGENTS.md`에 의미 있는 작업 완료 시 기록 갱신·정확성·기여 구분 지침을 추가했다.
- 주제별 Markdown 기록, 공통 양식, 자동 목록과 초안 생성 도구를 만들었다.
- Git hook이 새 자동 기록과 목록만 stage하도록 제한했다. 코드의 미선택 수정이나 목록의 미선택 편집을 대신 stage하지 않도록 했다.
- hook 설치는 이 저장소의 로컬 설정만 바꾸며 기존 hook 설정을 덮어쓰지 않도록 했다. 자동 커밋·push·외부 서비스 호출은 하지 않는다.
- 기록 실패는 경고하고 작업 커밋을 막지 않는다. 다른 팀원은 clone 후 한 번 설치해야 한다.
- 이 작업은 이슈 번호가 미등록된 `chore/docs-project-history` 브랜치에서 준비했다. 사용자 요청에 따라 이 브랜치의 변경을 커밋·push하고 이후 코드 검토와 통합은 별도 진행한다.

## 검증·결과

`node --test scripts/project-history.test.mjs`의 7개 검사가 통과했다. 실제 작업 저장소 대신 `.tools/` 아래의 임시 Git 저장소를 사용하고 테스트 후 정리했다.

1. Asia/Seoul 날짜 경계가 올바르게 계산되는지 확인.
2. stage된 변경이 없으면 기록을 생성하지 않는지 확인.
3. 파일의 stage된 증감만 수집하고 미선택 수정을 stage하지 않으며 반복 실행 시 중복 생성하지 않는지 확인.
4. 상세 기록이 함께 stage되면 그 내용을 유지하고 자동 초안을 중복 생성하지 않는지 확인.
5. 목록에 미선택 수정이 있으면 덮어쓰거나 stage하지 않는지 확인.
6. 실제 임시 `git commit`에서 기록이 포함되고 추가 커밋을 재귀 생성하지 않는지 확인.
7. 기존 hook 경로 설정이 있으면 덮어쓰지 않는지 확인.

첫 실행에서는 6개가 통과하고 Windows 격리 환경에서 Git의 shell 실행 권한 제한으로 실제 hook 검사 1개가 실패했다. 승인된 일반 실행 환경에서 같은 검사를 다시 실행해 7개 모두 통과했다. 이를 제품 코드 오류로 오인하거나 검사 성공으로 생략하지 않았다. GitHub Actions에는 같은 테스트 job을 추가했으며 원격 실행은 아직 확인하지 않았다.

현재 저장소에는 로컬 hook을 설치했다. 실제 `git hook run pre-commit`에서도 stage된 변경이 없으면 기록을 생성하지 않고 끝나는 것을 확인했다. 기록 도구 자체는 커밋·push를 실행하지 않으며, 이후 사용자가 요청한 범위에서 작업 변경을 선택해 커밋·push한다.

## 기여·한계

AI가 관찰하지 않은 수동 작업·회의·다른 대화는 자동으로 복원할 수 없다. hook이 없는 clone, Node.js 미설치, `--no-verify` 등은 자동 수집을 보장하지 않는다. 상세 기록은 담당자가 검토해야 한다. 이 도구는 기록을 남기는 작업이며 제품 기능이나 런타임 성능을 개선했다고 주장하지 않는다.

## 발표·포트폴리오 메모

“변경 흔적과 판단 근거를 구분하는 기록 흐름을 설계했다. AI 작업에는 맥락 기록을 포함하고, 일반 커밋에는 변경 파일 자동 수집을 연결해 팀 공유와 회고 자료의 누락을 줄이는 구조를 마련했다.”

실제 누락 감소율·작성 시간 감소는 측정하지 않았으므로 성과 수치로 사용하지 않는다.

## 후속 작업

- 다른 팀원의 clone에서 한 번 설치하고 실제 작업 흐름에 적용 여부 확인.
- 실제 팀 작업에서 기록의 유용성·부담·누락 여부 확인.
- 팀원이 기록에 담당·검토·공개 가능 범위를 보완하고 발표 사례를 선정.
