- 날짜: 2026-11-10 (Asia/Seoul)

## 배경·결정

사용자가 거창 신원면 외 다른 미종료 공고에도 공식 원문상 서류마감 누락을 확인해 반영하도록 요청했다. 실제 공개 API의 status=OPEN,UPCOMING 전 페이지(22건)를 조회했고 그중 12건에서 서류마감 일정이 없었다. 처음 조회의 잘못된 statuses 매개변수는 발견 후 status로 수정했으며 전체/종료 공고는 작업 대상으로 삼지 않았다.

공고의 endDate를 일괄 복사하는 방안은 채택하지 않았다. 공식 신청기간과 신청 시 서류제출 조항을 함께 읽어 동시제출이 명시된 11건만 추가했다. 근거 URL·쪽수·확인일과 동시 제출 의미를 보존하고, 시각은 원문에 있는 값만 사용했다.

## 적용 경로·한계

10건은 이전 게시 원고에 대해 현재 공식 상태, 전체 HTML 문맥, 전체 첨부 원바이트 SHA, 새 extraction/revision, 이전 게시 지문을 확인하고 기존 SourceReviewPublicationService.amend로 반영했다. 버전 변경에 따라 동해·남원 정정 공고 연결 2건도 공식 양방향 근거를 다시 대조했다.

청년 전세임대 1순위는 기존 notice_source_review가 없는 옛 게시 데이터다. 전체 안내를 새로 승인한 것으로 꾸미지 않고, 명시적 일회성 일정 보완 명령 PatchLegacyDeadline으로 처리했다. 공식 상세와 수집 식별자·접수중 상태·수정 PDF 첨부 관계·재다운로드 SHA를 확인하고 PDF 3쪽 신청기간/신청시 스캔첨부 조항을 읽었다. 트랜잭션 잠금 아래 기존 revision/전체 내용이 같은 경우에만 서류마감 한 건을 추가했으며, 기존 안내 상태와 확인일은 보존했다. 감사 payload의 scope=SCHEDULE_ONLY_EXPLICIT_REPAIR, beforeContent/afterContent, SHA/확인시각으로 부분 보완임을 기록했다. 기존 source-review 원고와 같은 전출처 검증 완료를 주장하지 않으며 이를 자동 검수 원고로 등록하지 않았다. 컴파일 전 source-launcher의 package 접근 오류 및 공식 상태가 공고중 아닌 접수중인 경우를 바로잡은 뒤 재실행했다. 실패 시에는 반영되지 않았다.

## 검증·결과

- API 22건의 전후 질문·서류·요약·확인필요 이슈·신청기간 일치, 변경11건은 기존 모든 일정 보존+서류마감1개 추가/버전+1, 나머지11건은 일정·버전 동일 확인.
- 전체 개인 준비 행의 개수/내용 해시 동일 확인.
- 정정 연결2건 HTTP200 재확인. 실제 원문 검증과 반영 결과는 docs/reviews/2026-11-10-document-deadlines/에 보존.
- 제품 프런트/백엔드 소스 변경은 없다. 이번 턴에 단위테스트 전체 재실행·실기기/브라우저 화면 검사는 하지 않았다.

## 기여·후속

Codex가 원문 대조·범위 제한·반영·실행 검증을 수행했다. 사람의 검수 완료로 기록하지 않았다. 발표 설명은 ‘신청과 서류의 동시 제출 여부를 근거로 누락 일정을 추가하고 단지별 일정을 공통 기한으로 혼동하지 않았다’로 제한한다. 단지별 마감의 요약 표시 UI는 별도 과제다. 접수종료 공고는 수정하지 않았다.
