## 배경·결정

정정 공고는 원공고의 업데이트이므로 목록에 함께 보이지 않게 해 달라는 요청이다. 제목 유사성으로 중복을 제거하지 않고, 공식적으로 검증해 등록한 notice_correction 관계를 사용한다. 정정본이 목록 공개 조건을 만족하면 원공고를 검색·정렬·건수·필터 선택지에서 제외한다. 원공고의 상세와 개인 준비는 보존한다. 내용 revision 변경은 공식 공고 ID 관계를 해제하지 않으며 정정본 비공개 시 원공고를 다시 표시한다.

## 구현

NoticeQueryRepository가 읽기 전용 NoticeCorrectionEntity로 페이지 나누기 이전에 관계를 조회한다. 기존 작은 목록 응답을 유지한다. 관계 쓰기는 기존 NoticeCorrectionService/Repository에 남는다.

공공임대 시스템02/분류06/유형08에서 정정본에 역방향 ID가 없는 공식 형식을 보완했다. 기존 검증 실패 시에만 공식 공고이력조회 두 행과 양쪽 상세의 ID·제목·종류·날짜·정정사유를 대조한다. 알 수 없는 이력 형식은 거부한다. 이력 URL·SHA도 증거에 저장하며 기존 증거 JSON 호환성을 보존한다.

평택·안성 원공고 0db58df5-fe4f-4ded-a870-d1e7b14d74a8 → 정정본 32256ae8-29c9-409b-93b5-0f8ecb5ab8a5 관계를 이 검증으로 연결했다. 공식 panId 0000061201(11/5) → 0000061206(11/6), 정정사유는 첨부파일명으로 인한 모집공고일 오해 방지다.

## 한계·후속

새로운 정정 관계의 자동 발견·등록은 이번 범위에서 추가하지 않았다. 등록된 공식 관계는 이후 목록에 자동 적용되지만 미연결 공고는 제목만으로 숨기지 않는다. 기존 관계 등록 API의 다단계 정정 연결 제한도 유지한다. 신규 수집 전반의 자동 연결을 위해서는 공식 이력 형식별 검증과 다단계 관계 처리 확장이 별도로 필요하다.
