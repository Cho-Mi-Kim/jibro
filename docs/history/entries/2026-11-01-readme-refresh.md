## 배경·문제

루트 README가 초기 프로젝트 생성 안내에 머물러 로그인·업무 모델을 미구현으로 표시했다. 프론트엔드 README에도 업무 API가 없다는 문장과 실제 서버 연결 설명이 공존했다. 공개 Pages 시연을 팀원에게 안내할 진입점이 필요했다.

## 고려한 선택지

루트에 시연 링크만 추가하는 방법과 연결된 README의 상태·실행 절차도 함께 맞추는 방법을 검토했다. 서로 다른 안내로 팀원이 잘못된 모드를 실행할 수 있어 루트·프론트엔드·백엔드·문서 목록을 함께 갱신했다.

## 결정·이유

첫 방문자는 서비스 목적과 시연 링크를 먼저 보고, 개발자는 서버 없는 시연과 실제 API·DB 실행을 구분한다. 상세 계약은 기존 문서로 연결하고 README에 현재 구현 범위와 남은 기능을 요약한다.

## 변경·해결 과정

- 루트: 서비스 설명, 공개 시연·체험 순서, 주요 기능·기술, 저장소 구조, 실행·검사·배포·PR 규칙을 정리했다.
- 프론트엔드: API 미구현 설명 제거, 일반·개발 시연·Pages 모드 구분, Pages preview의 mode/base 일치 안내를 추가했다.
- 백엔드: DB 시작·환경 변수, 실제 저장용 샘플 프로필과 화면 전용 시연의 차이, 외부 연동·질문·서류 문서 연결을 보완했다.
- 문서 목록: 시연·기능별 계약·질문·서류·공식 공고 자료 링크를 추가했다.
- 실행 명령은 package.json, Gradle 설정, 실행 스크립트, 라우터, CI/Pages 워크플로와 대조했다. 제품 코드와 설정은 변경하지 않았다.
- 최초 README 커밋에서는 기존 미커밋 PR19 검토 기록과 Pages 배포 후 확인 기록을 제외했다. 이후 사용자 요청으로 같은 PR #22에 별도 기록 커밋으로 포함한다.

## PR #22 기록 보완·병합 검토

- 사용자가 미커밋 기록의 커밋·push와 검토 후 develop 병합을 요청했다.
- PR #19·#20·#21의 병합 상태와 head/merge 커밋을 GitHub에서 대조해 기록과 일치함을 확인했다. Pages 실행 `41301192885`의 build/deploy 성공도 확인했다.
- 기존 README 커밋 `9ae85b5`의 원격 project-history·frontend·backend는 모두 성공했다. 추가 기록 커밋의 검사 결과는 별도로 확인한 뒤 검토한 head를 지정해 병합한다.
- 변경은 README와 작업 기록뿐이며 제품 코드·환경 변수·배포 설정은 포함하지 않는다. 기존 외부 연동·브라우저 결과는 당시 확인 범위로 유지하며 이번 검토에서 재실행한 것으로 표현하지 않는다.
- 최종 병합 커밋과 최신 CI 결과는 [PR #22](https://github.com/Cho-Mi-Kim/jibro/pull/22)의 상태·Checks에서 확인한다. 병합 후 기록을 다시 미커밋 상태로 남기지 않도록 사후 결과는 PR 본문에 보완한다.
