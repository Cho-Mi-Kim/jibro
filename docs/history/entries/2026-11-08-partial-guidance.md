# 충돌 항목만 확인 필요로 분리한 준비 안내

## 배경·문제

사용자가 2026-11-08 “충돌하는 부분만 확인 필요로 표시하고, 나머지 조건이랑 서류는 준비 안내 제공”하도록 요청했다. 기존에는 공식 문서 불일치 하나가 남아도 해당 공고 전체를 HOLD로 유지했다. 남은 익산·충주·남동·경주 4건에 이 정책 개정을 적용했다. 인천논현 정정본 연결은 이전 작업 결과다.

## 검토한 선택지·결정

- 기존 전체 HOLD: 확인된 서류 준비까지 막으므로 이번 사용자 요청과 맞지 않는다.
- 충돌을 임의 정정해 전체 PASS: 기관의 상충 사실을 해결한 것처럼 보이므로 채택하지 않았다.
- 기존 AVAILABLE 접근 게이트와 별도의 항목별 확인 필요 목록: 정상 기능을 유지하면서 충돌 범위와 이유·공식 근거를 보존할 수 있어 채택했다. 감사 판정은 PARTIAL이며 완전 검토 PASS와 구분한다.

## 변경·해결

- `HousingModels.Content/Notice/Preparation.reviewIssues`, 질문·서류의 서버 계산 `reviewRequired`를 추가했다. `GuidanceIssues`가 ID·근거·영역을 검증하고 질문에 종속된 서류의 영향 범위를 투영한다.
- `PreparationSnapshots/Rules`, 일회 확인에 동일 정책을 적용했다. 정상 답변·서류 완료는 허용하고 공식 미확정 문항은 답변을 골라도 추가 확인, 관련 서류는 UNKNOWN으로 유지한다. 기존 답변·준비 메모·과거 스냅샷을 자동 교체하지 않는다. 명시적 안내 갱신 때 새 범위를 적용한다.
- `SourceReviewVerifier/PublicationService`에 PARTIAL을 추가했다. 미해결 finding과 항목별 issue가 정확히 대응해야 하며, 전체 현재 출처·첨부 SHA·revision·발췌 지문 검증은 유지했다. V29 감사 제약을 확장했다.
- `GuideService`는 충돌한 항목만 일반 FAQ에서 제외한다. 첨부 채택과 원고 복사에서 issues를 보존한다. V30은 새 공고 비교 이력에 확인 필요·근거를 남기며 과거 이력을 재작성하지 않는다.
- 프런트 공통 `ReviewIssues`와 selectors로 조건·서류·일정의 사유·근거를 표시한다. 정상 문항만 입력 순서에 포함하고, 공식 확인 대기 서류를 사용자의 미응답 서류와 구분한다. 확정하지 못한 일정은 캘린더·알림 대상에 넣지 않는다.
- 남동의 읽기 실패 첨부 69190889는 실제 공식 파일을 다시 다운로드하고 격리 파서로 12쪽을 발췌했다. 수동으로 해시만 채우거나 파일을 검토 대상에서 제외하지 않았다.
- 충주는 공식 PDF 35쪽을 읽어 신규 조건·서류 원고를 작성했다. 4건의 정상 항목과 충돌 적용 부분이 섞인 원고를 분리했다. 검토 패키지·영향표·실제 적용 결과는 `docs/reviews/2026-11-08-partial4-*.json`에 보존했다.

## 기여·한계

AI 보조로 공식 자료 비교, 항목 범위 분리, 코드·회귀 검증을 수행했다. 기관 담당자의 답변이나 사람이 승인한 감사 이력을 만들지 않았다. 범용 자동 검수에서 모든 미해석 공고를 부분 공개할 수 있게 된 것은 아니다. 출처 누락이나 충돌 영향 범위를 특정하지 못하면 기존 전체 HOLD를 유지한다.

## 발표·포트폴리오 메모

공고 전체의 공개 여부와 개별 정보의 확실성을 분리하고, 불확실한 조건이 준비 완료·일정 알림에 섞이지 않도록 데이터·화면·이력에 같은 정책을 적용했다. 실사용 개선 효과를 정량 측정한 것은 아니다.

## 후속 작업

기관의 공식 정정이나 답변이 확보되면 해당 8개 사안을 다시 원문 대조한다. 기존 사용자 기록을 자동 확정하거나 개인 자격을 추정하지 않는다. 원격 commit/push/배포는 수행하지 않았다.
