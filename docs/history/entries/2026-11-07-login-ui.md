# 로그인 입력과 보조 동작의 시각적 구분

- 기록일: 2026-11-07 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 사용자 요청으로 롤백 완료
- 유형: 개발 / 디자인
- 담당·검토: Codex가 구현·기준 검토·테스트를 보조했다. 인간 최종 검토자는 미확인이다.
- 관련 이슈·PR·커밋: 신규 등록 없음. `style/login-ui-20261107`에서 작업하며 선행 미커밋 변경은 보존했다.

## 배경·문제

사용자가 로그인 화면 UI 개선을 요청했다. 기존 화면은 입력 영역·소셜 로그인·회원가입과 재설정 링크의 우선순위가 약했고, 미연결 소셜 버튼도 크게 쌓여 있었다. 직전 요청으로 삭제한 로컬 예시 공고 배너는 다시 추가하지 않았다.

## 고려한 선택지와 결정·이유

인증 흐름 전체를 교체하는 대신 기존 세션 진입·복귀 처리를 유지하면서 전용 페이지 스타일과 공통 비밀번호 입력을 분리했다. 문서의 따뜻한 배경·흰 카드·짙은 회색 본문, 제목24px·입력/주요버튼16px·보조14px와 터치 영역 기준을 적용했다. 미연결 소셜 버튼은 작동하지 않는 상태를 명확히 표시한다.

## 변경·해결 과정

- 이메일·비밀번호·로그인 버튼을 하나의 정렬된 입력 카드로 묶고 재설정을 비밀번호 아래 우측에 배치했다.
- Google·카카오 버튼을 나란히 배치하고 제공자 연결 상태에 따른 비활성 처리를 유지했다. 기존 로고·활성 브랜드 색상은 보존했다.
- 회원가입 안내를 카드 밖 독립된 보조 행으로 분리했다.
- `PasswordField`가 표시/숨김, 고유 라벨, 자동완성·기존 입력 제약을 소유한다. 표시 버튼은 제출하지 않으며 로그인/가입 전환 시 입력 컴포넌트를 새로 만든다.
- 이메일 자동 대문자·맞춤법 검사를 끄고 입력 예시를 추가했다. `safeReturn`, OAuth 복귀, 가입 검증, 오류·진행 상태, 체험/시연 분기는 유지했다.

## 검증·결과

- TypeScript·ESLint 통과. 포맷 검사와 모듈 경계 검사(10개) 통과.
- `App.test.tsx` 기존 흐름 33개 통과. `PasswordField.test.tsx` 표시 전환·값 보존·제출 방지·가입 필드 독립 동작 2개 통과.
- 5173 실제 브라우저에서 360/393/768px, 앱 글자125% 확대 시 가로 넘침 없음. 입력·주요 버튼48px 이상, 보조 링크44px 확인. 768px 상단 탐색과 회원가입 복귀 주소 유지 확인.
- 실제 기기 키보드·외부 Google/카카오 인증 왕복은 이번 확인 범위가 아니다. 비밀값이나 실제 계정 정보를 제출하지 않았다.

## 기여·한계와 발표 메모

입력과 보조 동작의 우선순위를 스타일 범위 안에서 개선하고, 새 비밀번호 표시 동작은 별도 컴포넌트·회귀 검사로 검증했다. 실제 사용자 성과나 팀 기여 수치를 추정하지 않는다.
