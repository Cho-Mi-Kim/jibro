## 배경·문제

사용자는 준비 안내 검수 처리와 접수 종료 공고가 접수 중 공고보다 아래에 오는 기본 정렬을 요청했다. 예약 수집이 과거 공고까지 확장되고 있어 범위를 확인했고, 사용자는 기존 공개 보류18건 우선을 선택했다. 새로 수집되는 전체 공고의 검수 완료를 뜻하지 않는다.

같은 자료도 55분이 지나면 새 발췌 작업을 만들고 최신 완료 초안을 대기 상태로 대체했다. 과거 공고 대기열과 첨부 읽기 연속 작업이 섞여 공개 공고의 재검토가 지연됐다.

## 고려한 선택지

- 목록 한 페이지를 받은 뒤 정렬: 페이지 밖 접수 중 공고를 앞으로 가져올 수 없어 제외했다.
- 동일 자료를 반복 다운로드: 대기열과 재시도 예산을 늘려 완료 결과 재사용으로 변경했다.
- 부분 자료나 API의 충돌 없음 결과로 일괄 승인: 자료 완전성과 개인별 조건·서류 규칙을 보장하지 못하므로 채택하지 않았다.

## 결정·이유

서버에서 페이지를 나누기 전에 접수 중 → 예정 → 기간 미확인 → 종료·조기 마감·취소 순으로 정렬한다. 기존 마감순·최신순을 명시적으로 선택하면 해당 정렬을 유지한다. 시연 목록도 같은 상태 기준을 사용한다.

같은 revision·원문 fingerprint 완료 결과를 재사용하고, 지정 UUID만 처리하는 진입점을 추가했다. 기존 첨부 변경 감지·명시 재발췌·실패 최대2회 재시도·수동 원고 보호를 유지한다.

## 후속 질의: 과거 크롤링 방식과 보완 제안 (미구현)

사용자가 과거 크롤링에서는 잘 동작했다며 보완 방향을 물었다. 예전 작업 폴더 `Documents/Codex/2026-09-20/figma-plugin-figma-openai-curated-remote`의 `backend/EVIDENCE.md`, `docs/notice-documents.md`를 읽기 전용으로 확인했다. 과거 코드를 복사하거나 실행하지 않았다. 당시 정확한 배포판 v76과의 동일성은 확인하지 않았다.

- 과거 기록: PDF 우선·두 쪽 모아찍기 좌우 분리, 유형별 요약과 명시적으로 지원하는 소득표, 출처 해시별 저장 발췌를 사용했다. 항목이 미확인되면 그 항목을 생략/확인 필요로 표시했다. 85개 공고의 서류 후보 중 공통 제출 항목을 대조한 대표 공고는5개라고 기록되어 있어 전체85개 개인별 필수 규칙 검증과는 다르다.
- 현재 코드 확인: SourceCoveragePolicy의 PDF/HWPX 정규화 전문 동일성, EvidenceGuidanceCompiler의 서로 다른 governing 본문2개 이상 보류, 원문 구간별 질문 생성 후20문항 초과 보류가 겹친다. 세 판정의 구체 방식은 내부 구현이며 GitHub 문서가 해당 알고리즘·숫자를 요구한 것은 아니다.
- 제안: 문서 역할과 정정 관계를 구분하고, 표·행·열·각주와 예외 연결을 보존한 뒤 공고 유형별 조건/서류 규칙을 만든다. 변형본은 대응 구간의 대상·수치·부정·예외를 비교한다. 같은 조건의 중복 질문을 합치고 필요한 분기를 연결한다. 미해석과 실제 충돌은 별도로 남긴다.
- 제안: 로컬에서 충분한 근거 묶음을 만든 뒤 어려운 관계만 기존 예산·캐시 안에서 Gemini 보조 검토. 일부 충돌 없음 결과를 전체 안내 승인으로 사용하지 않는다.
- 첫 실증 표본 제안은 읽기READY인 익산한스빌 공고다. 원문과 대응하는 조건·예외·서류·일정을 먼저 대조하고, 실제 질문→답변→서류→저장 및 원문변경 재검수를 통과시켜야 한다. PASS 배지 하나를 성공 기준으로 삼지 않는다.
