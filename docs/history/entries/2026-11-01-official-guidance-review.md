# LH 원문 준비 안내 검수와 조건부 서류 연결

- 기록일: 2026-11-01 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 전세임대 반영 완료 / 매입임대 복합 규칙 검수 보류
- 유형: 기획 / 개발 / 검증
- 담당·검토: Codex 자료 대조·구현·테스트 보조. 별도 사람 검토자 미확인
- 관련 브랜치: `feature/official-guidance-review-20261101`

## 배경·문제

사용자가 실제 공고를 등록한 다음 준비 안내 검수를 요청했다. 기본 정보만 검수된 공고 3건은 질문·서류가 비어 있었다. 기존 질문 화면은 게시일을 ‘공고 기준일’로 표시하여 신청일 기준 전세임대와 혼동할 수 있었다.

## 고려한 선택지

세 공고의 공통 서류만 복사해 모두 공개하는 방식과, 원문 예외까지 대조한 공고부터 공개하는 방식을 비교했다. 매입임대는 순위·부모 범위·가점에 따른 복합 분기가 남아 일괄 통과시키지 않았다. 현재 단일 조건부 질문 모델을 유지하고 전세임대의 필요한 복합 조건은 질문에 명시했다.

## 결정·이유

전세임대 수정 PDF·Q&A·동의 양식을 대조해 질문 10개, 서류 항목 9개, 마감 일정 1개를 제공한다. 공고 정보와 준비 안내를 같은 검토 자료에 기록했다. 서울·경기는 기본 정보 PASS/안내 HOLD를 유지하며 PDF 근거와 정확한 발표 명칭을 보완했다.

## 변경·해결 과정

- 신청일/공고일과 서류 발급 유효 기준을 분리했다.
- 본인 명의 증명서의 부모 서류 면제, 부모·형제자매 명의 예외, 연령 밖 대학생·취업준비생 증빙을 반영했다.
- 서류 목록은 공통·해당자 항목을 함께 표시함을 명시했다. 질문 화면 날짜는 ‘공고 게시일’로 고쳤다.
- 적용 스크립트는 로컬 Docker를 한정하고 초기 자료·버전·리비전 충돌을 검사한다. 공개 공고 백업 후 원자적으로 반영하며, 같은 결과의 재실행은 건너뛴다. 사용자 계정·준비 스냅샷에는 쓰지 않는다.
- 사람 검수자를 사칭하는 관리자 감사 행을 생성하지 않는다. Codex 검수 사유와 버전 관리 문서·데이터·로컬 결과로 추적한다.

## 검증·결과

- 프론트엔드 `npm run ci`: 포맷·린트·타입·테스트 20개·빌드 통과.
- 백엔드 `gradlew.bat --no-daemon test integrationTest`: 단위 10개, 통합 14개 통과. 원문 자료 전체 구조와 조건부 서류 YES/NO/UNKNOWN 전환, 완료 서류 RECHECK를 검증했다.
- 첫 Gradle 실행은 로컬 연결 제한으로 실패했다. 실행 환경을 조정한 뒤 UTF-8 강제 설정에서 테스트 실행기 클래스를 찾지 못했고, 강제 옵션을 제거해 Windows 기본 인코딩으로 재실행하여 통과했다. 프로젝트 설정은 변경하지 않았다.
- 로컬 적용 및 재실행: 세 공고 version/revision 2 유지. 공고 282건·기존 준비 기록 6건 유지.
- 브라우저에서 전세임대 ‘준비 안내 제공 중’, 조건 10개·근거 링크, 서류 9개, ‘내 조건 확인하기’ 활성화를 확인했다. 실제 사용자의 자격 질문을 임의로 답변하지 않았다.
- 제출서류의 공통·해당자 구분 설명을 추가한 뒤 프론트엔드 CI 20개 테스트와 빌드를 다시 통과했다. 최종 문구는 브라우저로 확인했으며 화면 증거는 `.tools/redesign-review/official-guidance-reviewed.png`에 보관했다.

## 기여·한계

공식 원문 대조와 구현은 AI 보조 작업이다. 사람 검토나 사용자 효과 검증을 완료한 것으로 표현하지 않는다. 준비 안내는 신청 자격·주택 권리분석 판정이 아니다. 서울·경기의 복합 분기와 주택 목록 검수는 남아 있다. 현 모델의 모순 응답 자동 검증, 마감 시각·조기 종료 자동 감지는 미구현이다.

## 발표·포트폴리오 메모

공고별 기준일과 명의 예외가 다른 문제를 확인하고, 공식 근거를 연결한 질문·조건부 서류와 검수 공개 상태로 반영했다. 공개 전·후 버전 확인과 반복 적용, 별도 테스트 DB를 통한 조건 변경 검증을 수행했다. 개인 기여는 담당자 확인 후 사용한다.
