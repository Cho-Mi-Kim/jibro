## 배경·검토한 선택지
사용자가 앞서 결정한 대구경북 분양전환형 해석을 바탕으로, 최근 접수 종료 일부 확인 필요 7건을 해결하도록 명시했다. 기존 접수종료 자동 처리 제외 원칙의 이번 7건 한정 예외이다. 단순히 확인 필요 표시를 지우는 대신 질문·답변의 후속 확인 여부·서류 조건·요약까지 함께 정리하고, 개인 상황을 모르는 경우의 확인은 유지했다. 일반 Q&A의 전역 규칙을 그대로 적용하는 방법과 공고별 명시 예외를 구분하는 방법을 비교하여 후자를 선택했다.

## 원문 대조·결정
- 7개 공식 상세와 각 첨부 4개, 총35개 출처를 검증했다. 쟁점 본문 PDF7개와 Q&A를 재독해하고 가점/계약/신청수정/부모 추가서류 표를 렌더링하여 적용 대상을 확인했다. 첨부 SHA는 기존 검토본과 모두 같았으며 상세 본문은 현재 추출과 새 조회가 일치했다.
- 든든전세: 구체 선정기준의 가점순→동점 추첨→당첨자 동호 추첨을 구분. 온라인 신청기간 중 수정·삭제 가능, 마감 후 변경 불가로 사용자 결정을 적용. 모집단위 변경·제출한 서류 변경 금지 및 타 공고 신청을 위한 서류제출기간 종료 전 취소는 별도 안내.
- 미성년 형제자매 부양은 본문이 명시한 등본·직계존속 부재·증빙 요건을 적용. 일반 Q&A 생략을 금지로 해석하지 않음.
- 군산·제주·경남 분양전환형은 이번 공고의 명시된 모집권역 제한 완화를 적용. 경남 비분양전환형의 부산·울산·경남 제한과 경기남부 수도권 제한은 유지.

- 청년 선착순: 본인 소득 4,576,036원 이하(그 외 유형), 자산·부모 소득 미적용, 서류 완비 현장접수순 및 오전10시 전 2명 이상 대기자 추첨을 적용. 부모 주택 소유 허용 및 부모 증명 사용 때만 추가서류를 요구하는 본문 기준을 적용. 같은 공고일 중복제한과 Q&A의 서류제출 후 타 공고 신청제한은 서로 다른 범위의 보완 규칙으로 설명. 상세의 계약 운영기간과 본문의 순번 도래 시 개인 계약 안내를 구분하며 개인 계약일을 생성하지 않음.
- 개인정보 필수 수집·제공/선택 민감정보·홍보를 분리. 금융정보 제공과 미통보 선택을 구분하며 동의서 공통 제출은 유지. 제주 금융 문서의 미통보 의무 서명 표현도 함께 정리.
- 대구경북 비분양전환형의 최초 우편 날짜 오기는 임의 수정하지 않고 사용자가 지정한 온라인 안내 범위에 맞춰 POSTAL 선택지·paper_application만 제외. 공식 제도 폐지나 오기 자체의 해결로 기록하지 않는다. 서류대상자 후속 우편 제출은 유지.

## 추출 경로 복구
경남2건의 content.evidence가 PDF로 되어 있어 공식 상세 HTML 재발췌가 실패했다. 새 재시도에서도 동일 실패를 확인한 뒤, 기존 검토이력의 공식 상세 URL과 수집 source_key가 일치하는지 확인하여 실제 상세를 다시 읽었다. ExtractionStore의 새 작업·claim·finish 경로로 검증 가능한 발췌를 만들고, 개정 원고의 대표 근거를 동일 공고의 공식 상세로 복구했다. 조항별 PDF 근거는 유지한다. 검증 우회나 직접 SQL 게시 변경은 하지 않았다. 런타임 코드 변경 없이 이2건의 잘못 지정된 대표 출처를 정리한 데이터 수정이다.

- API7건 모두 AVAILABLE, reviewIssues 31→0, CLOSED/canStart=false. 목록의 partialGuidance=false, 기본 목록62건, 현재 목록의 종료 일부 확인 필요0건.
- 모든 기존 날짜·일정·applicationTiming이 이전 API와 동일. 질문 ID 보존 및 조건부 문서 참조 유효성 확인. 원고 질문이 실제 API와 일치하고 문서 개수 일치.
- preparation/preparation_history와 대상 외 notice의 전체 상태 해시를 전후 비교하여 모두 불변 확인. 개인정보 내용은 산출물에 기록하지 않음.
- 복구용 임시 Java의 첫 실행은 패키지 접근/소스 실행 클래스 로더 제약으로 실패했고 데이터 변경 없이 종료. 같은 클래스 경로에서 컴파일·실행해 성공. QA 스크립트는 기존 nullable 조건값을 처리하지 못해 처음 실패했으며 보완 후7건 통과.
- UI 구조 변경이 없어 브라우저 시각 QA·전체 빌드 테스트는 하지 않음. 실제5173 API로 게시 상태와 내용을 검증함.
