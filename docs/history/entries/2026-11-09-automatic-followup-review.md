# 신규 공고의 정정·후속 공식 자료 자동 대조

## 배경·문제

사용자는 앞으로 수집되는 공고에도 정정본·후속 공식 자료 자동 대조를 적용해 기관 확인이 필요한 항목만 확인 필요로 남기도록 요청했다. 전 작업은 12개 공고의 수동 원문 검토 패키지를 적용한 것이며 일반 자동 수집은 후속 공지의 발견·주기적 재검토를 하지 않았다. 이번 명시적 요청에 따라 자동 범위를 확장하되 기존 검수 안내와 개인 준비 스냅샷은 보호한다.

## 고려한 선택지

- 과거 검토 패키지 재실행: 특정 공고의 답안을 새 공고에 일반화하므로 제외했다.
- 검색 최신 자료나 제목 유사도로 덮어쓰기: 모집·단계가 다른 자료가 섞일 수 있어 제외했다.
- 공식 모집 연결, 원문 전체 확인, 항목별 비교, 별도 게시 경계: 적용 전후 근거와 실패 원인을 보존할 수 있어 채택했다.

## 결정·이유

`OfficialFollowupDiscovery`가 공식 정정 양방향 ID와 LH 공지 본문의 모집 관계를 확인한다. `OfficialFollowupComparison`은 명시적 전후 변경 또는 후속 일정을 순수 함수로 대조한다. `AutomaticFollowupService`는 네트워크 읽기·재검증을 조정하고, `AutomaticFollowupPublicationService`만 잠금·현재 지문·유효기간 확인 후 게시한다. 기존 원문 전용 GUIDANCE 작업은 이 기능이 켜져 있으면 별도로 게시하지 않는다.

실제 충돌은 해당 항목의 `reviewIssues`로 남긴다. 다운로드 실패·검색 한도·미지원 문장은 기관 확인 사유를 만들지 않고 재검토 대기로 분리한다. 확정되지 않은 날짜를 채우거나 AI 응답만으로 승인하지 않는다. 별도 외부 모델 호출은 추가하지 않았다.

## 변경·해결 과정

1. 발견·HTML 구조·모집 관계, 변경 비교·문장 해석, 큐·감사·게시를 각각 분리했다. V33이 작업 임대와 자료 묶음·적용 전후 증거를 보존한다.
2. 원공고 발췌가 같아도 후속 자료가 바뀌면 다시 대조한다. 재확인한 동일 묶음은 버전 증가 없이 확인 이력만 남긴다.
3. 독립 검토에서 검색 누락으로 정정 전 값이 복원될 위험을 찾아, 이미 반영하거나 철회 근거가 된 후속 자료 의존성을 새 발췌 이후에도 보호했다.
4. 검증된 완전 정정본에 미해석 변경 조항이 있으면 예전 안내를 계속 확정적으로 제공하지 않도록 별도 무효 근거를 저장한다. 단순 읽기 실패와 구분한다.
5. 소개·제목에 포함된 일정 변경 문장을 생략하지 않게 했으며, 미리보기도 후속 첨부가 섞이지 않은 원본 자료를 사용한다.
6. 실제 LH 검색에서 원모집일이 제목에 명시된 후보를 먼저 읽도록 보완했다. 후보 한도 이후를 확인하지 못했다면 완료로 가장하지 않는다.

## 검증·결과

- `gradlew test integrationTest bootJar`: 단위 555개 + 별도 PostgreSQL 테스트 DB 통합 306개, 총 861개 통과. 실패·오류·건너뜀 0.
- 새 범위 82개에는 관계·원문·첨부 변경, 조건·서류·일정 충돌, 이웃 예외 보존, 재검토 무변경, 임대·revision·해시·유효시간, 수동 원고 보호, 개인 기록 유지, 검색 누락 회귀가 포함된다.
- 실제 화성 병점 공식 후속 공지 3개와 XLSX 첨부를 자동 발견·판독했다. 장기 검색의 12개 후보 한도 초과는 재검토 대기로 남았다. helper의 최초 XLSX 실패는 worker 경로 누락이었으며 실제 worker 경로로 재실행해 해소했다.
- 실제 2026년 청년 전세임대 1순위 공고의 후속 검색은 제한 내 완료됐고 관련 자료 0건이었다. 이는 검색 확인이며 전체 준비 안내 승인 의미가 아니다.
- DB 백업 후 로컬 5173 재시작, V33 적용 및 health/DB UP 확인. 기존 보호 공고 50건과 준비 기록의 비교값 동일, 기존 공개 공고 17건의 질문 249개·서류 312개·확인 필요 표시 6개 및 일정 동일.
- 실제 예약 작업이 인천 일반 매입임대 공고에서 정정 자료 1건과 무효 근거 1개를 기록했다. 미해석 문구·변형 자료 미확인으로 `REVIEW_REQUIRED` 처리했으며 기관 확인 이슈를 만들어 승인하지 않았다. 이전 질문·서류는 각 0개였다. 다음 공고의 자동 작업 진입도 확인했다. 실제 새 준비 안내 PASS가 관찰된 것으로 표현하지 않는다.
- 프런트 제품 코드·레이아웃 변경 없음. 이번 작업에서 별도 모바일 시각 검사를 다시 수행하지 않았다.

## 기여·한계

구현과 교차 검토·검사는 Codex 보조로 수행했다. 실제 기관 답변이나 모든 자연어 공고의 자동 해석을 구현한 것은 아니다. 시작·마감 경계가 불명확하거나 미지원 예외가 남으면 자동 게시하지 않는다. 기존 수동 검수 안내는 후속 자동 작업 대상에서 제외한다. 외부 운영 서버 배포는 하지 않았다.

## 발표·포트폴리오 메모

원문만 검수하던 자동 경로에 공식 후속 관계와 항목별 변경 비교를 추가했다. 검색 누락에 의한 역행과 미해석 정정에 의한 오래된 안내 유지를 회귀 검사로 막고, 게시 직전 원격 근거와 DB 지문을 각각 검증했다. 개인 기여 표기는 담당자 확인 후 사용한다.

## 후속 작업

- 운영에서 쌓이는 재검토 사유를 바탕으로 지원 문장과 검색 이어읽기 범위를 확장한다. 한도·미해석을 기관 충돌로 바꾸지 않는다.
- 범위·설정·동작 계약은 [자동 대조 계약](../../contracts/automatic-followup-review.md), 실제 검증 증거는 [검증 기록](../../reviews/2026-11-09-automatic-followup-verification.json)을 따른다.
