# GitHub Pages 팀 화면 테스트용 시연 배포

- 기록일: 2026-11-01 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 진행 중
- 유형: 개발 / 의사결정 / 협업
- 담당·검토: 사용자 시연 방식 선택, Codex 구현·검증 보조. 팀원 사용성 검토 미실시.
- 관련 PR: 생성 예정

## 배경·문제

개발 환경을 설치하지 않는 팀원도 링크로 화면과 준비 과정을 테스트할 필요가 있다. GitHub Pages에서는 Spring Boot를 실행할 수 없으며 기존 개발 시연 어댑터는 DEV에서만 활성화되었다.

## 고려한 선택지

- 외부 백엔드와 실제 로그인 연결: 서버 배포와 OAuth 도메인 설정이 추가로 필요하다.
- 독립 정적 시연: 기존 가상 데이터로 화면 흐름을 체험하지만 실제 인증·저장을 검증하지 못한다.

## 결정·이유

사용자가 화면 테스트용 시연을 선택했다. `pages-demo` 빌드에서만 운영 환경의 가상 API를 허용한다. 일반 운영 빌드는 기존 서버 모드를 유지한다. `/jibro/` base와 HashRouter로 정적 호스팅의 하위 경로 새로고침 문제를 피한다.

## 변경·해결 과정

- Pages 빌드·라우터, 시연 시작 UI, 명확한 초기화 안내를 추가했다. 실제 이메일·비밀번호 입력과 소셜 로그인은 공개 시연에서 숨긴다.
- 본문 바로가기 링크가 해시 라우터 주소를 바꾸지 않도록 포커스 이동으로 처리했다.
- 공개 시연의 서버 연결 진단 화면은 제외했다.
- main의 프론트엔드 변경 후 검사·시연 빌드·배포하는 Actions와 PR의 Pages 빌드 검사를 추가한다.
- 기존 Pages 설정과 main의 사용자 CNAME 변경 이력은 보존한다. 기존 PR19 검토 기록의 미커밋 변경은 이 작업에 포함하지 않는다.

## 검증·결과

- `npm --prefix frontend run ci`: 포맷·린트·타입·25개 테스트·일반 운영 빌드 통과.
- `npm --prefix frontend run build:pages`: 통과. 결과 HTML의 스크립트·스타일 경로가 `/jibro/assets/`임을 확인했다.
- 새 테스트에서 DEV=false인 시연의 로그인·공고·준비 생성·로그아웃은 실제 fetch를 호출하지 않음을 확인했다. 일반 production은 demo 환경 변수가 있어도 서버 모드를 유지한다.
- 로컬 정적 미리보기는 `--mode pages-demo`를 함께 지정해야 base가 일치한다. 최초 미리보기의 잘못된 모드를 수정했고 목록 로딩을 확인 중이다.
- 원격 CI·배포·실제 공유 주소 확인은 후속 기록에 결과를 갱신한다.

## 기여·한계

AI가 코드·배포 문서·검증을 보조했다. 가상 데이터는 메모리에서만 유지되며 새로고침 시 초기화한다. 실제 OAuth·LH·DB 연동 성공의 증거로 사용하지 않는다.

## 발표·포트폴리오 메모

서버 없이 공유할 수 있는 명시적 시연 빌드를 분리하고 정적 배포의 경로·라우팅 제약을 처리했다. 운영과 시연의 분리를 자동 테스트로 확인했다.

## 후속 작업

- 브랜치별 PR·CI 검토 후 배포 및 공유 링크 동작을 확인한다.
- 팀원 피드백은 `docs/github-pages-demo.md`의 테스트 순서·기록 기준을 사용한다.

## 배포 자동화 추가

- PR 검사에 Pages 빌드를 추가하고 main 반영 후 시연 아티팩트만 배포하는 워크플로를 구성했다.
- 현재 Pages는 Actions 방식이며 main·develop 배포가 허용되어 있다. 접근 정책은 변경하지 않았다.
- 로컬 정적 사이트에서 공고 목록 → 공고 상세 → 개인정보 입력 없는 시연 시작 → 질문 페이지 이동을 확인했다.
