# PC 공고 정렬 메뉴가 카드 뒤에 가려지는 문제 수정

- 기록일: 2026-11-24 (Asia/Seoul)
- 기록 상태: 검토 완료
- 작업 상태: 해결
- 유형: 문제 해결
- 담당·검토: Codex 구현 및 브라우저 확인, 외부 리뷰 미실행
- 관련 이슈·PR·커밋: [PR #31](https://github.com/Cho-Mi-Kim/jibro/pull/31)

## 배경·문제

PC 공고 목록에서 정렬 메뉴가 공고 카드 뒤에 표시됐다. 운영 Opera 1920px에서 재현했고, 메뉴 가운데의 실제 클릭 대상도 정렬 항목이 아닌 공고 제목이었다.

## 고려한 선택지

메뉴 자체의 z-index를 더 높이는 대신 PC에서 표시 영역이 사라지는 `display: contents` 부모와 실제 도구 모음의 겹침 책임을 정리했다. 별도 포털이나 메뉴 복제는 필요하지 않았다.

## 결정·이유

모바일에서는 기존 sticky 검색 영역이 겹침 순서를 담당하고, 1024px 이상 PC에서는 실제 박스를 가진 도구 모음이 카드보다 앞에 표시되게 한다. 기존 페이지 CSS가 화면 배치와 표시 순서를 계속 소유한다.

## 변경·해결 과정

`NoticeList.module.css`의 PC 규칙에서 `controls`에 남아 있던 sticky 위치와 z-index를 해제하고 `toolbar`에 상대 위치와 기존 레벨 10을 적용했다. 추가한 것은 PC 표시 순서 선언, 제거한 것은 PC의 박스 없는 부모가 모바일 겹침 속성을 유지하던 동작이다. 메뉴·정렬·닫기 로직과 750ms 애니메이션은 유지했다. 새 경로·의존성·임시 제품 코드는 없다.

## 검증·결과

- Prettier 검사, NoticePages 기존 테스트 3개, TypeScript 및 운영 빌드 통과.
- 로컬 Opera 1920px: 메뉴 3개 항목 전부 카드 앞에서 클릭 가능, 마감순 선택 후 URL과 메뉴 닫힘 확인. 바깥 클릭 닫힘 확인.
- 로컬 브라우저 390px·360px: 모든 항목이 화면 안에 있고 실제 클릭 대상이 메뉴임을 확인. Esc 닫힘·초점 복귀 확인. 크기 재설정 완료.
- 로컬 백엔드가 정지되어 있어 기존 재시작 스크립트로 5173/8080을 복구한 뒤 화면을 확인했다.
- 운영 `/opt/jibro/release-notice-sort-20261124` 웹 반영. 패키지 258파일 검증, Nginx 설정·공개 페이지·404·방문자 보호 검사 통과. 백엔드 컨테이너와 운영 설정 유지.
- 실제 jibro.live PC에서 메뉴 가림 해소를 화면과 클릭 대상으로 확인. 최신순 선택 후 `sort=newest` 및 메뉴 닫힘 확인.

## 기여·한계

브라우저 실제 배치 확인으로 수정 효과를 검증했다. 모바일은 브라우저 크기 검증이며 실물 기기 검증은 아니다. CSS 배치 수정으로 백엔드 전체 검사·구조 지도 재생성·별도 반복 테스트 추가는 하지 않았다. 후속 사용자 요청으로 기존 PR #31의 검토 브랜치에 이 수정과 기록을 올리고, PR 설명은 컴퓨터 유즈로 갱신한다. 초안·미병합 상태를 유지한다.

## 발표·포트폴리오 메모

같은 메뉴라도 반응형 부모의 표시 방식이 바뀌면 겹침 순서가 달라진다. 실제 박스가 존재하는 요소에 화면별 배치 책임을 두어 해결했다.
