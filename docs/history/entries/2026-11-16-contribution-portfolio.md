## 배경·문제

사용자가 자신의 담당 범위를 구체화하고 이력서·포트폴리오로 재사용할 문서를 요청했다. 팀 전체 구현, 사용자 결정·직접 확인, AI 구현·검증, 다른 계정의 후속 기능 확장을 구분할 필요가 있었다.

## 고려한 선택지

- Git 작성자나 PR 수만으로 개인 개발 실적을 집계하면 AI 보조와 팀원 확장을 개인 수작업으로 잘못 표현할 수 있다.
- 작업 기록의 담당·검토 및 사용자 발언을 PR 메타데이터·후속 코멘트·선택한 패치와 대조해 문안을 작성한다.

후자를 적용했다. 코딩 기여율·사용자 효과·전체 활동 기간은 임의 추정하지 않았다.

## 결정·이유

- 역할을 팀장·서비스 기획·AI 보조 풀스택 개발·통합 관리로 정리했다.
- 바로 사용할 이력서 문안, 소개 문장, 사례 4개와 면접 준비를 본문에 배치했다.

- 검증 수치는 해당 일자의 실행 범위로만 인용하고 이번 조사에서 새로 통과한 결과로 쓰지 않았다.

## 기여·한계

문서 작성과 근거 대조는 AI 보조이며 개인의 직접 코드 작성 기능을 새로 인증하지 않는다. Notion 회의록, 별도 사용자 인터뷰, 팀원별 수작업 비율, 실제 인쇄·외부 제출은 확인하지 않았다. 전체 PR 변경 파일을 새로 코드 리뷰하거나 CI를 재실행한 작업이 아니다.

## 발표·포트폴리오 메모

사용자 조건을 준비 행동으로 연결하는 기획·UX 판단과 실제 인증 설정·확인, AI 보조 개발 및 팀원 변경 통합을 사례로 설명할 수 있다. 팀 결과와 개인 역할을 함께 드러내되 미측정 성과를 넣지 않는다.
