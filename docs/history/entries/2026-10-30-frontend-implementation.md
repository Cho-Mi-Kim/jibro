# 프론트엔드 전반 구현과 기능 계약 구체화

- 기록일: 2026-10-30 (Asia/Seoul)
- 기록 상태: 근거 정리·담당자 검토 전
- 작업 상태: 진행 중
- 유형: 개발 / 설계 / 검증
- 담당·검토: 사용자 요청에 따라 Codex 구현, 팀 검토 미실시
- 관련 이슈·PR·커밋: 작업 단위 커밋으로 기록. 이슈 번호는 임의 생성하지 않음

## 배경·문제

사용자는 역할 분담 검토를 제외하고 미확정 기능 계약을 자율 판단하여 별도 Markdown에 기록하며 프론트엔드 전반을 개발하고 단계별 커밋·push·브랜치 분기를 요청했다.

## 고려한 선택지

실제 API만 기다리면 업무 흐름 검증이 불가능하므로, 실제 서버를 기본으로 하고 개발 환경에서 명시적으로 활성화하는 메모리 시연 어댑터를 선택했다. 운영에서 서버 실패를 시연 성공으로 대체하지 않는다.

## 결정·이유

[프론트엔드 계약](../../architecture/frontend-contracts.md)에 DTO, 인증·쿠키 연동 대상, 준비도 초안, 상태 전이, 검수·공개 분리와 후속 서버 구현 범위를 기록했다. 실제 기관 데이터가 없는 상황에서 가상 공고를 공식 정책으로 표시하지 않는다. 준비도 계산은 서버 응답 계약이며 시연 계산만 개발 어댑터에 둔다.

## 변경·해결 과정

- 기반 브랜치: feature/frontend-foundation. 타입·API 어댑터·SEED ActionButton·공통 UI·인증 조회 기반 구성.
- 후속 화면은 기반 커밋에서 분기하여 사용자 흐름 단위로 커밋한다. develop/main 병합은 이번 요청에 포함되지 않아 작업 브랜치를 push한다.
- SEED 공식 React 수동 설치·Theming·ActionButton 문서와 설치 패키지 타입을 확인했다. 공통 디자인 문서 2개는 웹 도구 오류로 열리지 않아 기존 화면설계서와 읽을 수 있는 React 문서를 적용했다.

## 검증·결과

- SEED 패키지 설치: 취약점 0건. TypeScript 검사 통과(초기 버튼 HTML color 타입 충돌은 공개 컴포넌트 타입과 맞춰 해결).
- 실제 업무 API·소셜 제공자·수집 서버는 미구현으로 실제 연동 완료를 주장하지 않는다.
- 사용자 화면·보조 계정·관리자 화면 연결 후 npm run ci 통과: 포맷·린트·타입·테스트 12건·운영 빌드. 저장 실패 후 재시도, 미검수 차단, 중복 생성 방지, 오래된 revision 충돌, 권한, 토큰 재발급을 검증했다.
- 브라우저에서 로그인 복귀 시 QueryClient.clear가 활성 session observer를 끊는 문제를 발견했다. session query를 유지한 채 계정 캐시를 갱신·정리하도록 수정하고 흐름 테스트로 확인했다.
- Vitest에서 SEED 외부 CSS를 처리하도록 의존성을 inline하고 jsdom에 없는 ResizeObserver·dialog를 테스트 환경에서 보완했다. 실제 브라우저에서는 네이티브 동작을 사용한다.
- CSS Modules로 제품 스타일을 분리하고 전역에는 기반 스타일·SEED CSS만 둔다.

## 기여·한계

Codex가 구현·계약 초안을 작성했다. 실제 사용성 조사·팀원별 기여·공고 정확성 검증·운영 배포는 수행하지 않았다.

## 발표·포트폴리오 메모

미구현 서버와의 계약을 문서화하고 같은 인터페이스의 개발 어댑터로 화면 흐름을 검증한다. 모의 저장과 실제 계정 저장을 구분하고 미검수 정보 노출·가짜 완료 처리를 방지한다.

## 후속 작업

- 실제 백엔드 계약 구현, 공식 공고 데이터 검수, 소셜 앱 설정 후 연동 검증.
- 실제 사용자와 준비도·집 표현 이해도 확인.
