## 배경·문제

사용자는 파주운정 A4처럼 다른 공고도 처음부터 자신의 구체적 상황을 선택하고 해당 질문·필요 서류로 이어지기를 요청했다. 현재 기본 목록 122건 중 준비 안내를 제공하는 106건(접수 중11·예정55·종료36·일정 확인4), 질문1,487개를 전수 검토했다. 검수 중16건을 새 승인하거나 접수 종료 공고를 다시 수집하는 작업은 아니다.

## 고려한 선택지와 결정

화면에서 제목만 바꾸거나 모든 공고에 같은 미성년·가족 기준을 복사하는 방법은 선택하지 않았다. 공고별 공식 원문과 기존 질문 계약을 비교하고, 기존 `Question.applicability`·`answerDependencies`·문서 조건 연결을 수정했다. 원문에 없는 유형을 추정하지 않고 공식 기준일 충돌은 확인 필요로 유지한다.

내 준비·일회성 입력은 같은 `applicantInputQuestions`를 소비한다. 문서 필요도는 기존 Java `PreparationRules`와 시연용 `demoPreparationRules`에서 계산한다. 미정 선택이 `UNKNOWN` 문자열이 아니라 `NONE`/`OTHER`일 때 서류가 사라지던 원인은 이 소유 위치에서 고쳤다. 모든 호출자가 질문 계약을 함께 전달하고 호환 오버로드·화면별 별도 필터를 추가하지 않았다.

## 변경·해결 과정

- 국민임대47·영구/매입35·기타24건을 나누어 원문, 첫 실제 입력 순서, 유형별 질문, 서류 연결과 답변 모순을 검토했다. 원고는 `data/notices/all-applicant-situations-20261122/batch-a.json`, `batch-b.json`, `batch-c.json`이다.
- 성년·미성년 예외를 구체적으로 선택하고 형제자매 부양 사유나 외국인 부모 관련 후속으로 이어지도록 했다. 행복주택은 본인·현 세대·결혼 후 세대의 주택 확인 범위를 별도 질문으로 구분하고 학생에게 청년 전용 근로·청약 질문을 묻지 않는다.
- 혼인/미혼 답변이 달라 필수 가족관계증명서나 예비신혼 서식이 빠지는 경우를 보완했다. 기존 문서 ID와 공통 서류는 유지한다.
- 대체한 혼합 질문은 제거하고 고정 의미의 질문 ID로 교체했다. 질문 계약 전체가 달라지면 기존 새 안내 적용 경로에서 재질문하며, 기존 답변은 이전 기록에 보존한다. 문서 메모와 보관 이력을 직접 수정하지 않는다.

## 독립 검토 처분

- A 세 공고의 혼합 가족 질문을 단순 YES/NO로 되돌린 초안 문제: 원래 질문 계약을 복원했다.
- 정선사북의 학생에게 청약/근무 질문 노출 및 예비신혼 가족 서류 누락: 명시 유형 연결과 필수 서류를 보완했다.
- 완주·평창·전주의 미혼 유형이 가족 증명서를 비해당 처리할 수 있던 문제: 답변 모순 연결을 보완했다. 공고별 생략 예외는 유지했다.
- 추가 확인 선택으로 서류가 제외되는 공통 문제: 서버·시연의 기존 필요도 계산을 수정했다.
- 정읍수성1 원고 교체로 공식 확인 이슈가 없는 질문 ID를 참조한 문제: 기존 이슈와 해당 질문 ID를 유지했다.
- 김제검산1의 첫 질문이 일반 안내 확인으로 남은 문제: 기준일 충돌과 분리한 가족 상황 선택 및 외국인 배우자 후속을 보완했다. 예비신혼의 필수 신청 서식을 비해당 답변으로 숨기지 않도록 했다.
- 정읍수성1의 기존 검수 중 질문을 읽기 쉽게 바꾼 원고는 게시 경계에서 거절됐다. 해당 질문 전체와 연결 서류 조건을 원형 보존하고, 새 첫 상황·후속만 반영했다. 검수 기준을 완화하지 않았다.
- 태백궁전의 기존 전환이율 근거는 모집 첨부 외 LH 본사 공지와 PDF였다. 기존 일회성 게시 도구에 추가 공식 자료 전달을 연결하여 같은 `SupplementalSourceVerifier`의 본문·첨부 연결·새 지문 검사를 통과시켰다. 공식 근거를 삭제하거나 무검증으로 유지하지 않았다.
