# 작업·문제 해결 제목

- 기록일: YYYY-MM-DD (Asia/Seoul)
- 기록 상태: 작성 중 / 근거 정리·담당자 검토 전 / 맥락 보완 필요 / 검토 완료
- 작업 상태: 해결 / 진행 중 / 보류
- 유형: 개발 / 문제 해결 / 의사결정 / 기획 / 협업 / 문서
- 담당·검토: 확인한 역할만 기재. 미확인은 미확인으로 표시
- 관련 이슈·PR·커밋: 실제 링크 또는 미등록

## 배경·문제

사용자 문제·기술 제약·기대한 동작과 실제 현상을 기록합니다.

## 고려한 선택지

실제로 검토한 대안과 장단점을 기록합니다. 당시 검토하지 않은 사후 비교는 구분합니다.

## 결정·이유

선택한 방식과 사용자 가치·일정·기술·운영 부담 등의 근거를 적습니다.

## 변경·해결 과정

수정한 내용과 원인 확인·해결 순서를 적습니다. 재현 근거와 관련 파일을 연결합니다.

## 검증·결과

실행한 명령·확인 환경·통과/실패·미실행 범위를 기록합니다. 근거가 없는 개선 수치를 넣지 않습니다.

## 기여·한계

개인·팀 기여, AI 보조 범위, 확인하지 못한 항목과 남은 제약을 구분합니다.

## 발표·포트폴리오 메모

문제 → 선택 이유 → 실행 → 확인된 결과를 요약합니다. 개인 기여는 담당자 확인 후 사용합니다.

## 후속 작업

- 다음 확인·구현·검토 항목과 담당자가 정해졌다면 담당자를 적습니다.

## 변경 파일

관련 파일을 저장소 루트 기준으로 기록합니다. Git 자동 수집 시 이 절은 stage된 파일·증감을 바탕으로 채웁니다.
