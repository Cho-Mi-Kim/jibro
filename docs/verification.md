## 외부 실서비스 확인 — 2026-10-31

- LH 인증키의 이중 인코딩을 교정하고 최근 3개월 검색 필드를 수정했다. 실제 관리자 수집 API 2회 성공, 276건 저장·재수집 후 276건 유지·전건 HOLD/HOLD를 확인했다.
- 수집 클라이언트 테스트 4건 포함 백엔드 단위 테스트 10건·JAR 빌드 성공. 프론트엔드 CI(포맷·린트·타입·테스트 15건·빌드) 및 별도 PostgreSQL 테스트 DB의 통합 테스트 11건 성공.
- Google은 앞선 계정 선택 화면 정체 이후 사용자가 실제 로그인 성공을 보고했다. DB에서도 Google 연결 계정 1건과 갱신 토큰 발급 이력 2건을 확인했다. 이 최초 조회 당시 미폐기·미만료 갱신 토큰은 0건이었다. 이후 새로고침·로그아웃 추가 검증 결과는 아래에 구분했다. 앞선 정체의 원인은 확정하지 않았다.
- 카카오는 호출 허용 IP에 사설 IP를 등록한 것이 원인이었다. 사용자가 공인 IPv4로 변경한 뒤 실제 로그인 정상 동작을 보고했다. DB에서도 카카오 연결 계정 1건과 갱신 토큰 발급 이력 2건을 확인했다. 이 최초 조회 시 두 갱신 토큰은 모두 폐기 상태였다. 이후 새로고침·로그아웃 추가 검증 결과는 아래에 구분했다.
- 자세한 근거와 한계는 [외부 연동 검증 기록](history/entries/2026-10-31-external-integration-verification.md)에 기록했다.

| 대상 | 새로고침 후 로그인 유지 | 로그아웃·새로고침 후 내 준비 접근 | 확인 방식 |
| --- | --- | --- | --- |
| Google / Edge | 유지 | 로그인 화면 이동 | 사용자 직접 확인 + 서버 DB 집계 |
| 카카오 / Chrome | 유지 | 로그인 화면 이동 | Codex 브라우저 직접 조작 + 서버 DB 집계 |

- 새로고침 후 두 제공자 모두 미폐기·미만료 갱신 토큰 1건. 로그아웃 후 Google은 발급 이력 6건 전부 폐기, 카카오는 5건 전부 폐기되어 유효 토큰은 각각 0건이었다. 계정·토큰 값은 수집 결과에 출력하지 않았다.
- 인증 관련 기존 테스트를 재실행했다. 백엔드 AuthIntegrationTest 2건(갱신·이전 토큰 재사용 거부·로그아웃 후 갱신 거부·CSRF), 프론트엔드 transport.test.ts 5건 통과.
- Google 계정 선택 후 Chrome에서 정체되는 현상은 재현되었다. Edge 성공은 사용자 확인이며 Chrome 정체의 원인은 아직 확정하지 않았다. Edge는 자동 제어 대상에 없어 사용자 화면 확인과 서버 집계를 결합했다.
- 이번 검증은 집으로의 브라우저 로그인 상태와 갱신 토큰 폐기 범위다. Google·카카오 자체 서비스 로그아웃, 다른 기기 전체 로그아웃, 이미 발급된 접근 토큰의 즉시 무효화까지 검증한 것은 아니다.
