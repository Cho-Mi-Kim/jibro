## 검증과 적용 방식

- 대상 12건의 최신 상세 및 기존 첨부 32개를 다시 확인했다. 기존 첨부 SHA는 모두 같았다. 원본의 현재 revision에 맞춘 새 발췌를 기록하고 과거 발췌를 보존했다.
- 추가 자료는 별도 `SupplementalSourceVerifier`로 허용 경로, 제목·본문·직접 첨부 목록 지문, 선택 첨부의 실제 연결과 바이트 SHA를 검사했다. 일반 수집·자동 공개 허용 범위를 넓히지 않았다.
- 종료 조건이 명시된 공고는 `confirmedOpenEndedPeriod`로 설명한다. 공식 종료 상태가 확인된 경우 `applicationClosure`로 공개 상태·정렬·시작 가능 여부를 일치시키되 종료 날짜를 만들지 않는다.
- 이전 게시 원고 지문을 요구하는 `amend`로 12건을 적용했다. 기존 청주·성남 정정 연결 2쌍도 최신 양방향 공식 근거로 재검증하고 이전 근거를 보존했다. 내포는 역방향 근거가 없으므로 자동 정정 연결을 만들지 않았다.
- backend 단위 499개 + 별도 테스트 DB 통합 280개, frontend 관련 5파일 37개 검사 통과. 공개 API 17건의 질문·서류·이슈·일정을 최종 패키지와 대조했다.
- 브라우저 393×852 및 360×800에서 실제 접수 종료, 확인된 일정, 정정 연결, 항목별 확인 필요 표시를 확인했다. 가로 넘침·콘솔 오류 0. 실제 휴대전화 검증과 구분한다.
- 변경 대상 밖의 데이터 보존 비교와 실행 JAR 지문은 실행 기록에 별도로 남겼다. 원격 배포·push는 수행하지 않았다.
