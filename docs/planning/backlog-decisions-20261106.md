## 10번 구현 기준

| 결정할 내용 | 적용할 기준 |
| --- | --- |
| 확인 대상 | 공고에 등록된 공식 첨부 주소. 첨부를 임의 추측하여 찾거나 사용자 증빙을 받지 않는다. |
| 변경 판정 | 파일을 읽어 SHA-256을 계산한다. 주소·ETag·수정 시각이 같더라도 파일 내용이 다르면 변경 후보로 처리한다. |
| 최초 확인 | 처음 성공한 파일 해시는 비교 기준으로 등록한다. 비교할 과거 파일이 없다는 이유로 변경됐다고 표시하지 않는다. |
| 실행 진입점 | 관리자 확인과 기존 공고 수집 흐름에 연결한다. 정기 실행은 7번의 별도 구현 범위다. |
| 요청 한도 | 파일 하나당 20 MiB, 요청당 15초, 한 실행에서 최대 10개 확인. 실행 시작 후 45초가 지나면 새 요청을 시작하지 않는다. 이미 시작한 요청의 종료까지 전체 실행 시간이 45초를 넘을 수 있다. |
| 실패 처리 | 통신 오류·시간 초과·허용 범위 초과는 확인 실패로 기록한다. 기존 해시와 공고를 유지하며 삭제 또는 변경으로 단정하지 않는다. |
| 변경 이후 | 기존 공고 버전·검수 전환 계약을 따른다. 새 내용은 검수 없이 공개하지 않고 기존 개인 준비 스냅샷을 보존한다. |
| 보관 | 해시와 확인 결과·시각 등 비교 기록을 보존한다. PDF 파일 자체는 상시 저장하지 않는다. 이전 PDF 재열람이나 본문 전후 비교까지 구현한 것으로 표현하지 않는다. |

이 한도는 초기 운영 기본값이다. 공식 출처의 이용 조건·실제 파일 크기·처리 시간을 확인해 조정할 수 있으며, 모든 공고와 모든 파일을 한 번에 확인했다는 의미가 아니다. 미확인·실패·한도 도달 상태를 성공 확인과 구분한다.

## 운영 37~43번의 기준과 실제 지정 사항

| 번호 | 항목 | 유지·채택할 기준 | 아직 실제 값·환경 확인이 필요한 부분 |

25~36번의 자료 검수·사용자 조사·외부 연동·실제 기기 확인과 44~48번의 개발 관리·문서·출력 검증은 이번 결정만으로 완료되지 않는다. 담당자와 실제 실행 증거가 필요한 작업으로 남긴다.

## 문서와 현재 구현의 구분

- [기획안의 개인정보 기준](project-proposal.md#개인정보): 최소 입력과 민감 답변 저장 선택을 유지한다.
- [질문·서류 계약](../contracts/question-options-and-documents.md): 현재 입력형과 개인 준비 스냅샷을 변경할 때의 기준이다.
- [코딩 기준](../conventions/coding-conventions.md)의 수집과 규칙 관리, 인증, AWS 구성: 원문 비교·재시도·검수 분리와 초기 운영 구조의 근거다.
- [백엔드 계약](../architecture/backend-contracts.md): 실제 수집과 검수·버전 전환 흐름을 확인한다. 과거 미구현 문구와 새 기능의 구현 결과는 해당 작업 기록·현재 코드로 대조한다.
- 15·19·22번은 2026-11-07 현재 코드와 자동 검사로 구현을 확인했다. 여전히 설계만 채택한 항목, 실제 외부 수집·SMTP·Web Push·운영 배포 완료와 구분한다.
- [배포 구성·복구 도구](../../deploy/README.md)는 로컬 준비 범위에서 구현했다. 실제 PostgreSQL 논리 백업을 새 임시 DB로 복구해 29개 테이블을 확인했지만 운영 RDS 복구는 아니다. Nginx는 설정 문법만 확인했고 실제 HTTPS 프록시 실행은 자동 승인 정책 차단으로 미검증, Docker 이미지 빌드는 엔진 부재로 미검증이다. 운영 서버·외부 키·도메인 적용이나 commit/push는 수행하지 않았다.
- 실제 운영 계정·비용·기간·담당자·비밀값은 확인 또는 지정이 필요하다. 이 표는 임의의 계정 생성·비용 지출·배포·대량 삭제를 실행하지 않는다.
