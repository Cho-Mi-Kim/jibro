# 공고 확인 시각 계약

기본 정보의 검수, 준비 안내의 검수, 자동 수집을 서로 다른 기록으로 취급한다. 출처의 `evidence.checkedAt`은 해당 근거 자료의 확인일이며 공고 전체의 검수 시각으로 대신하지 않는다.

| 필드 | 의미 | 값이 없는 경우 |
| --- | --- | --- |
| `basicCheckedAt` | 현재 공고 내용의 기본 정보 검수 PASS 시각 | 확인 기록 없음 |
| `guideCheckedAt` | 현재 공고 내용의 준비 안내 검수 PASS 시각 | 확인 기록 없음 |
| `collectedAt` | 공식 목록에서 해당 공고를 마지막으로 수집한 시각 | 확인 기록 없음 |

- 기본 정보만 PASS이고 준비 안내는 HOLD/UNSUPPORTED이면 안내 검수 시각은 비어 있다. 자료가 자동 수집됐거나 샘플 공개 상태라는 이유만으로 검수 시각을 만들지 않는다.
- 같은 내용의 재수집은 `collectedAt`만 갱신하고 기존 검수 시각과 버전을 보존한다.
- 공식 목록 내용, 관리자 원문 초안, 같은 주소의 첨부 내용이 변경되면 양쪽 검수 시각을 비우고 재검수 상태로 전환한다. 관리자가 내용을 수정하거나 첨부 변경을 확인한 시각을 자동 수집 시각으로 기록하지 않는다.
- PASS 검수를 다시 저장하면 해당 검수 시각을 새로 기록한다. HOLD/UNSUPPORTED 전환 시 해당 PASS 시각은 비운다. 과거 판정은 `review_audit`에 남는다.
- 기존 자료의 시각은 현재 revision에 대응하는 검수 감사 기록이 있는 경우에만 이관한다. 과거 revision의 검수 또는 출처 확인일을 현재 검수로 추정하지 않는다.
- 화면은 서버의 시각을 한국 표준시로 표시한다. 누락·잘못된 값은 다른 필드로 대체하지 않는다.

검증 대상은 `NoticeReviewTimesIntegrationTest`의 실제 DB 저장·재조회, `NoticeGuidanceStatus.test.tsx`의 세 종류 시각 표시와 누락 표시다. 실제 운영자의 원문 검수가 이루어졌다는 의미와 구현 테스트 통과는 구분한다.
