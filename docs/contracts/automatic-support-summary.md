# 공고 지원 내용 자동 요약

- 사용자 확정: 2026-11-10. 앞으로 수집되는 공고의 ‘어떤 지원인가요?’를 지원 대상과 받을 수 있는 지원 중심 2~3문장으로 작성한다. 접수종료 공고는 제외한다.
- 표현 개정(2026-11-11): 요약에서는 긴 행정 용어를 짧고 익숙한 표현으로 쓴다. 사용자 지정 예시인 ‘미성년 직계비속(태아 포함) 2명 이상을 양육’은 ‘2자녀 이상’으로 줄인다. 이는 요약용 표현이며 미성년·태아 등 정확한 조건 및 공식 근거를 수정하는 정책이 아니다.
- 같은 날 지원 내용도 짧게 쓰기로 했다. ‘거창군 신원면의 다자녀 매입임대주택을 자격에 따라 시중시세의 30~40% 수준의 임대료로 공급합니다.’는 ‘거창군 신원면의 다자녀 매입임대주택을 시세의 30~40% 수준의 임대료로 공급합니다.’로 표시한다. 지역·주택·비율은 그대로 두고 ‘거주할 수 있도록 공급’ 같은 중복 표현도 줄인다. 보증금·월 임대료·별도 부담 및 예외는 지우지 않는다.
- N02의 준비 안내 검수 경계를 유지한다. 목록 제목·주택 유형만으로 대상이나 지원 금액을 만들지 않는다. 기본 정보만 검수된 자료에 미검수 조건 해석을 공개하지 않는다.

## 연결과 책임

`GuidanceReviewCompiler.assess`가 원문 범위·조건·서류·일정을 검증한 후 `collection/review/summary/SupportSummaryCompiler`를 호출한다. 일반 자동 검수와 `OfficialFollowupComparison`을 거치는 예약 후속 검수에 같은 조립 경로를 사용한다. 준비 안내 전체가 게시 가능한 경우에만 요약 후보를 만든다.

- `SupportSummarySource`: 완전한 원문 문맥, 모집 제목, 실제 신청/입주 자격 절의 도입부를 읽는다. 본문 뒤의 다른 제도 언급이나 목록 메타데이터만으로 공급 유형을 정하지 않는다. 미완료 자료·길이 제한·미대조 OCR·신청서 등 보조 양식을 요약 근거로 사용하지 않는다.
- `SupportSummaryRules`: 원문에 확인된 프로그램 정의와 대상 문구를 짧은 표현으로 바꾼다. 전세임대의 LH 계약·재임대, 매입임대의 매입 주택 공급, 국민/영구/행복/공공/통합공공임대의 보증금·월 임대료 방식에 대응한다. 세부 유형을 확인하지 못한 명시적 ‘임대주택’은 더 구체적인 유형으로 추측하지 않는다.
- `SupportSummaryCompiler`: 대상 1문장 + 지원 방식 1문장 + 원문에서 확인한 예비입주 대기 설명 최대 1문장으로 구성한다. 최대 280자. 기존 질문·서류·일정·근거·확인 항목은 그대로 둔다. 금액·시세 비율·최대 거주기간을 관행이나 유형에서 추론하지 않는다.

외부 AI 요청, 추가 수집 요청, 독립 예약 작업, 새 DB 테이블은 없다. 이미 수집·검수하는 원문을 로컬 순수 함수로 읽는다. 원문의 명령문을 실행하거나 모델 지시로 전달하지 않는다.

`NoticeSummary.concise`가 명시적으로 승인된 대상·지원 표현을 줄인다. 기존 공개 요약 읽기와 미래 자동 요약 생성에 같은 함수를 사용해 화면마다 별도로 치환하지 않는다. 자녀 수·이상/이하·부정문·금액 및 비율을 추정하거나 바꾸지 않는다. ‘임대조건’을 임의로 ‘임대료’로 바꾸지 않으며 각 표현의 범위를 보존한다. 출처의 정확한 조건을 확인하는 검수 규칙은 유지하며, 관리자 원고·접수종료 공고 및 개인 준비 데이터는 기존대로 보존한다.

## 제외·보존

- 예약 후보 선택과 자동 게시 서비스의 기존 접수종료 차단을 유지한다. 요약 조립 시에도 공식 조기종료와 신청 마감 일시를 재검사하며, 처리 도중 종료되는 경우 최종 게시가 거부된다.
- 불완전/미대조 OCR, 확인되지 않은 대상·지원 방식, 서로 다른 모집 설명, 대상·서류 관련 확인 필요 항목은 기존 요약을 유지한다. 요약을 못 만들었다고 나머지 검증된 안내를 임의로 승인하거나 철회하지 않는다.
- 후속 정정이 자격·서류 규칙을 교체한 경우 옛 원문으로 요약하지 않는다. 해당 조립에서는 기존 원고를 유지하고, 새 원문 전체가 검증된 모집 자료로 들어오면 다시 요약한다. 일정만 변경된 후속 자료는 기존 모집 설명의 요약을 사용할 수 있다.
- 수동 편집/공식 자료 대조로 보호된 현재 공고와 개인 준비 스냅샷은 자동으로 덮어쓰지 않는다. 기존 게시 서비스가 최신 revision·발췌 지문·잠금·이력을 소유한다.
- 검수 정책 키는 `source-review-v10` / `official-rules-v10`으로 올려 예전 결과와 구분한다.

## 현재 수집 공고의 요약 단독 검토

2026-11-10 사용자 확정: **공식 원문으로 확인한 요약만 공개하고 나머지 준비 안내는 검수 중 유지한다.** 이는 현재 수집 공고의 공식 자료 대조에 따른 명시적 요약 편집이며, 자동 검수의 전체 승인 기준을 낮추는 규칙이 아니다.

- `notice_source_review.payload.scope=VERIFIED_SUMMARY_ONLY`로 출처·전후 요약·보존한 검수 상태를 기록한다. disposition은 기존 guide_review 값을 보존하므로 공고 전체가 승인된 것으로 해석하지 않는다.

## 자격과 선정 순위 요약 (2026-11-11)

- 공개 `Notice.qualificationSummary`는 검수 완료된 현재 공고의 읽기 전용 요약이다. `NoticeQualificationSummary`가 기존 검수된 대상 문장과 질문 근거를 사용한다. 개인 답변·자격·점수·당첨 가능성을 계산하지 않는다.
- 응답은 `eligibility`, `selection`, `detail`, `evidence`, `reviewRequired`다. 신청 자격과 선정 순위는 기본 표시하며, 정확한 예외·원문 출처·조건 탭 이동은 펼침 안에 둔다.
- 순위 배정·같은 순위의 경합·명시된 접수 순번 등 완결된 문장만 요약한다. 소득표의 ‘장애인 1·2순위’ 같은 분류명이나 계약 이후 추첨 언급을 선정 방식으로 오인하지 않는다. 긴 표·불명확한 형식·출처 없는 내용은 상세 기준 확인으로 안내한다.
- 질문의 확인 필요 상태는 제외한다. 공개 준비 안내 검수 중·변경 검수 중·접수 종료·관리자 원고에는 새 요약을 생성하지 않는다. 기존 DB 원고와 검수 상태, 준비 스냅샷을 수정하지 않는다.

## 공고별 핵심 서류 요약 (2026-11-11)

- `Notice.documentSummary`는 검수된 서류 목록의 읽기 전용 투영이다. `NoticeDocumentSummary.from(Content)`가 공통/조건부 목록을 구분하며, 개인 답변을 받거나 필요 여부를 판정하지 않는다.
- 각 그룹은 `items: {id,title,evidence}[]`, `remainingCount`를 가진다. 최대3개를 표시하고 나머지 개수를 함께 전달한다. 공통은 기본 신원·가족 증빙과 신청/동의 양식, 해당자는 자격 증빙을 먼저 표시하되 동급 항목은 기존 원고 순서를 유지한다. 원래 목록을 삭제하거나 순서를 변경하지 않는다.
- 표시명에서 개인정보 동의서/주민등록등본·초본만 짧게 표현하며 분리배우자·자녀 등 주체, 상세·전부표기, 또는 조건은 보존한다. 개인별 준비 서류와 공식 원고는 그대로다.
- 충돌 서류/연결 조건의 확인 필요/누락된 조건 연결/출처 없음은 확정 목록에서 제외하고 `reviewRequiredCount`로 별도 안내한다. 기존 GuidanceIssues의 질문→서류 의존 처리를 재사용한다.
- 준비 안내 미검수·접수종료·관리자 응답에는 요약을 생성하지 않는다. 과거/미지원 응답의 요약 필드가 없을 때 프런트는 서류명을 추정하지 않고 전체 제출 기준 확인으로 안내한다.
- 공통 `NoticeSummaryCard`에 공통 서류/해당 시 추가를 표시하고, 출처 및 전체 제출서류 이동은 우상단 펼침 안에 둔다. 일정 우선 배치는 유지한다.

## 신규 수집 자격·순위·서류 요약의 자동 연결 검증

- 사용자 확정(2026-11-11): 앞으로 수집되는 공고에도 위 두 요약을 자동 적용하되 접수종료는 제외한다. 별도 요약 저장이나 예약 작업을 추가하지 않고, 기존 자동/후속 검수 게시 후 `NoticeService.view`에서 최신 검수 원고를 같은 순수 함수로 읽는다.
- 마감 전 공개한 지원 대상·내용, 자격·순위, 서류 요약은 접수가 끝난 뒤에도 조회할 수 있다. 최초 종료 확인 시각과 예정 마감 중 이른 쪽을 기준으로 한다. LH 조기 마감, 종료 통보가 반복된 경우, 마감일이 정해지지 않은 모집에도 적용한다. 재검수로 검수일이 바뀌면 같은 공고·공식 원문의 마감 전 승인 이력을 확인해 현재 승인본을 표시한다. 모집 취소, 서비스 제외, 변경 검수 중에는 요약을 공개하지 않는다. 종료 공고의 신규 자동 검수는 중단한다.
- 자동 발췌의 `5. 선정기준` 같은 절 제목 때문에 완결된 선정 문장이 누락되던 경우를 보완했다. 정해진 선정 절 제목 한 줄만 제거하고 문장을 해석하며, 표의 행이나 조건부 머리말은 임의로 합치거나 제거하지 않는다. 상세 원문과 출처는 보존한다.
- PostgreSQL 통합 검증에서 수집 등록→기본 공개→원문 발췌→자동 검수→공개 요약을 확인했다. 충돌 서류는 요약 확정 목록에서 제외하고 추가 확인 개수로 남긴다. 미검수/지난 기한/반복 검수 보호도 유지한다. 테스트 fixture는 별도 test DB 트랜잭션에만 생성했다.
- 실제 미래 신규 공고 유입을 기다려 관찰한 결과와는 구분한다. 미지원 문장·불완전한 근거는 기존 상세 기준 확인 안내를 유지한다.
