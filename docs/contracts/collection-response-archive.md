# 공식 API 원본 응답 기록

2026-11-07 사용자 승인 보완: 목록 수집 시 공식 JSON 응답을 보존한다. 기존 항목 정규화·변경 해시·검수 원고를 원본 응답 보관의 대체물로 취급하지 않는다.

## 보관 단위

- `collection_response_attempt`: 실행 ID, 실행 회차, 내부 lease, 조회 기준일, 분류 코드, 게시일 검색 범위, 페이지, 요청/수신/완료 시각, HTTP 상태, 본문 상태, 검증 결과를 기록한다. 전체 요청 URL·요청 헤더·API 키는 기록하지 않는다. V20부터 응답 DTO에 `categoryCode`, `publishedFrom`, `publishedThrough`를 추가하고 기존 필드는 유지한다. 같은 실행에서 분류 06의 1페이지와 분류 13의 1페이지를 별도 요청으로 기록한다.
- `collection_response_payload`: 인증 정보를 제거한 원본 JSON의 전체 필드와 SHA-256, 최초 수신 시각을 저장한다. 알 수 없는 공식 응답 필드도 남긴다. JSON의 공백·표현 형식은 다시 직렬화되므로 바이트 단위 원문 보존은 아니다. 해시는 실제 저장한 UTF-8 JSON 기준이다.
- 동일 JSON 해시는 payload 하나를 공유하고, 각 페이지·재시도마다 별도의 요청 이력을 남긴다. JSON 해시가 달라져도 기존 항목 fingerprint 규칙을 유지하므로 응답 시각·순번 변경만으로 공고 버전이 증가하지 않는다.
- 오류 HTTP의 유효 JSON, 공식 오류 코드 JSON, 페이지 수 불일치 JSON도 보관한다. 응답 검증 통과는 공고 공개 검수 통과를 뜻하지 않는다. 실패 응답으로 기존 공고를 지우지 않는다.
- 비JSON·JSON 스칼라·5 MB 초과 응답은 본문을 저장하지 않고 상태만 남긴다. HTTP 수신 중 5 MB를 넘으면 바로 중단해 무한 응답을 메모리에 담지 않는다. 전송 실패에는 응답이 없다는 사실을 남긴다.
- 요청 직후 서버가 중단된 이력은 `REQUESTED`로 남는다. 이를 응답 성공으로 간주하지 않는다. 기존 lease 복구가 새 회차에서 같은 페이지·조회 기준일로 재시도한다. 429/5xx/전송 오류의 재시도·공식 서버 Retry-After 대기 계약은 유지한다.

## 인증 정보와 공개 경계

설정된 서비스 키(원문·URL 인코딩 값), 인증 관련 JSON 필드와 URL 쿼리 값을 저장 전에 제거한다. 삭제 여부를 이력에 표시하며 JSON 본문·외부 예외 메시지는 애플리케이션 로그에 쓰지 않는다. 관리자 원본 조회도 마스킹된 본문만 반환한다.

- `GET /api/v1/admin/collections/{runId}/responses`: 이력 목록, 본문 제외.
- `GET /api/v1/admin/collections/{runId}/responses/{responseId}`: 해당 실행에 속한 이력과 보관된 본문. 다른 실행의 ID 조합은 404.
- 기존 관리자 권한 정책을 적용한다. 일반 사용자·비로그인 사용자는 읽을 수 없고 공개 공고 API와 개인 준비 스냅샷에 포함하지 않는다.
- `/admin` → 수집 실행 이력 → **수집 원본 응답**. 응답 본문은 추가로 **원본 JSON 보기**를 눌렀을 때만 가져온다. 코드·HTML은 실행하지 않고 텍스트로 표시한다.

## 운영과 검증

V19 migration은 기존 수집 이력과 공고를 보존한 채 테이블만 추가한다. 과거에 저장하지 않았던 응답을 만들어 채우지 않는다. 자동 삭제 기한은 두지 않는다. 동일 응답은 중복 저장하지 않지만 변경된 JSON은 계속 쌓이므로 DB 용량·백업에 포함한다. 이력 삭제 시 참조가 끊긴 payload 정리는 별도 운영 작업으로 다루고 자동으로 삭제하지 않는다.

V20은 기존 요청의 분류 06·조회 기준일 이전 3개월 범위를 당시 구현 계약에서 복원하고, 새 요청은 실행에 고정된 범위를 기록한다. 내용이 없는 과거 응답 본문을 생성하지 않는다. 이력 목록 상한은 두 분류의 페이지·재시도를 고려해 4,000건이다. 반복 페이지나 전체 건수·페이지 크기 불일치 응답은 JSON을 보존하되 `REJECTED`로 남긴다.

테스트에서는 JSON 보존·키 제거·중복 해시·실패/재시도·조회 기준일·잘못된 페이지·관리자 접근 제한, HTTP body 제한을 확인한다. 실제 LH 키를 등록한 운영 수집 완료 여부는 로컬 가짜 응답으로 검증한 구현과 구분해서 보고한다.
