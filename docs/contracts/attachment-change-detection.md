# 공식 PDF·첨부 내용 변경 감지

기준일: 2026-11-06. 사용자 후속 목록 10번을 구현한다. [수집 기준](../conventions/coding-conventions.md)의 같은 주소 첨부 해시 비교·변경 후 재검수·기존 개인 기록 보존 정책을 따른다.

## 대상과 실행

- 관리자가 등록한 `Content.attachments`의 URL을 검사한다. `#page=` 등 fragment는 제외하여 중복 요청을 막는다. 원문 HTML의 첨부 자동 발견·본문 추출은 이번 범위가 아니다.
- 관리자 검수 작업실의 **첨부 변경 확인**으로 한 공고를 점검한다. LH API 키가 없어도 등록된 첨부는 확인할 수 있다.
- 기존 목록 수집 실행은 처리한 공고의 등록 첨부도 검사한다. 목록 필드가 같아도 첨부 검사는 수행한다. 정해진 시각의 예약 수집·자동 재시도는 별도 후속 설계다.
- `GET /api/v1/admin/reviews/{id}/attachment-checks`: 최근 20개 실행과 파일별 결과. `POST` 같은 주소: 검사 실행. ADMIN 권한·CSRF 필요. 클라이언트에서 임의 다운로드 URL을 받지 않는다.

## 네트워크와 저장

- 기본 허용 도메인은 `apply.lh.or.kr`, `www.lh.or.kr`이며 `app.collection.attachment-hosts` 설정은 정확한 공식 호스트만 추가한다. HTTPS·기본 포트만 허용하고 사용자정보 포함 주소·리다이렉트는 거부한다.
- DNS 결과의 로컬·사설 주소를 사전 차단한다. 이는 연결 IP 고정이 아니며, 공식 호스트 허용 목록과 기본 TLS 검증을 유지한다.
- 파일당 최대 **20MiB**, DNS·응답 본문을 포함한 총 **15초**, 연결 **5초**다. 실제 본문을 스트리밍하며 SHA-256을 계산한다. 본문 전체를 메모리나 디스크에 저장하지 않는다.
- PDF·OLE(HWP 등)·ZIP(HWPX 등)의 선두 서명을 검사한다. 문서 내용·압축파일을 해석하지 않는다. HTML 오류 페이지·빈 응답·HTTP 실패·과대 파일을 내용 변경으로 인정하지 않는다. ETag·수정 시각만으로 동일성을 판단하지 않는다.
- 한 공고 검사 및 한 번의 전체 수집에서 최대 10개 파일 요청, 45초가 지나면 새 요청을 시작하지 않는다. 시작된 요청의 15초 상한을 포함해 다운로드 단계는 최대 약 60초다. 파일별 미처리 사유를 남기며 다음 점검에서 미검사/오래된 검사부터 처리한다.
- V11 테이블 `attachment_fingerprint`는 마지막 성공 해시·크기·형식·성공/시도 시각을 보존한다. `attachment_check_run/result`는 실행자·시각·결과·이전/현재 해시를 보존한다. 원본 PDF 재열람·파일 상시 보관은 제공하지 않는다.

## 판정과 경합

| 결과 | 처리 |
| --- | --- |
| BASELINE | 최초 성공 기준 등록. 비교할 과거 기준이 없으므로 변경 없음이라고 표시하지 않음 |
| UNCHANGED | 마지막 성공 해시와 같음. 공고 버전/검수 상태 유지 |
| CHANGED | 다른 해시. 한 검사에서 여러 파일이 바뀌어도 공고 version/revision은 한 번 증가, 기본·안내 HOLD 및 CHANGE_REVIEW |
| FAILED | 실패 사유 기록. 마지막 성공 기준과 공개·준비 기록은 유지 |
| DEFERRED | 실행 한도로 미처리. 이전 기준 유지, 후속 점검 가능 |
| SUPERSEDED(실행) | 다운로드 중 공고 revision 변경. 어떤 해시도 현재 기준에 반영하지 않고 다시 점검 |

기존 개인 준비 스냅샷은 수정하지 않는다. 현재 공고와 버전이 다르면 기존 준비 서비스가 재확인을 안내하며, 새 안내는 사람의 검수를 거쳐야 공개된다. 첫 기준 등록 전에 발생한 변경이나 아직 등록하지 않은 첨부는 감지할 수 없다.

네트워크 요청 전에 짧은 트랜잭션으로 공고 revision과 실행 소유권을 기록한다. 다운로드 동안 DB 잠금을 유지하지 않고, 반영 시 공고를 잠가 revision을 재검증한다. 공고당 실행 하나만 허용한다. 중단되어 5분이 지난 실행은 재시도할 수 있으며 늦게 돌아온 이전 실행 결과는 적용하지 않는다.

## 검증 경계

`AttachmentFingerprintClientTest`는 네트워크 경계·스트리밍·용량·취소를, `AttachmentCheckIntegrationTest`는 실제 PostgreSQL의 기준 등록·변경·실패·버전·공개 차단·권한·개인 기록 보존을 검증한다. 실제 외부 파일 확인과 동시 요청 검증은 [작업 기록](../history/entries/2026-11-06-attachment-change-detection.md)에 구분한다. 해시 차이는 바이트 변경의 증거이며 정책이나 자격 조건이 바뀌었다는 자동 판정은 아니다.
