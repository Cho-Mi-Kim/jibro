# 질문별 선택지와 준비 대상 서류 계약

적용일: 2026-11-01. 사용자 요청에 따라 일괄 YES/NO/UNKNOWN 문구를 질문별 의미 있는 선택지로 바꾼다. 현재 검수 공고의 질문은 모두 단일 선택으로 답할 수 있어 자유 입력으로 개인정보를 추가 수집하지 않는다. 숫자·날짜·다중 선택 입력은 실제 질문이 필요할 때 별도 계약으로 확장한다.

## 질문·답변

- `Question.options`: `{ value, label, requiresFollowUp? }[]`. 선택지 코드는 대문자·숫자·밑줄 1~50자이며 질문 안에서 고유하다. 2~20개, UNKNOWN 필수.
- `value`가 서버 저장값, `label`이 질문과 결과 화면에 보이는 답변이다. 결과 화면에서 모든 응답을 ‘해당 없음’으로 재해석하지 않는다.
- `requiresFollowUp=true`는 ‘아직 확인할 내용이 남음’, ‘추가 문의 필요’ 같은 답변이다. 모름·미응답과 함께 추가 확인으로 남기며 준비도에서 확인 완료로 계산하지 않는다. 이는 자격 탈락/승인 자동 판정이 아니다.
- `PUT /api/v1/preparations/{id}/answers`: `revision`, `answers: Record<questionId, optionValue>`의 전체 응답 맵을 보낸다. 서버는 스냅샷에 없는 질문 ID·선택값·null을 거절한다.
- 구버전 질문에 options가 없으면 기존 YES/NO/UNKNOWN 계약을 읽는다. 새 안내의 질문별 선택지는 구버전의 응답을 임의 변환하지 않는다.

## 전세임대 안내 v3

기존 검수 근거는 유지하고 중복된 유형 확인을 합쳐 7개 질문으로 구성했다.

| 질문 | 선택지 예 |
| --- | --- |
| 주택 소유 | 소유한 주택 없음 / 있음 / 모름 |
| 혼인 상태 | 현재 혼인 중 아님 / 혼인 중 / 모름 |
| 신청 유형 | 19~39세 / 범위 밖 대학생 / 범위 밖 취업준비생 / 해당 유형 없음 / 모름 |
| 1순위 증명서 명의 | 본인 / 부모 / 공식 예외에 해당하는 형제자매 / 증명서 없음 / 모름 |
| 부모 초본 조건 | 세 조건 모두 해당 / 하나 이상 해당 안 함 / 모름 |
| 제출 규격 확인 | 모두 확인 / 확인할 내용 남음 / 모름 |
| 후속 절차 이해 | 이해함 / 문의·설명 필요 / 모름 |

`data/notices/question-options-20261101.json`이 실제 데이터다. 신청 유형별 학교 인정·지역 제한과 명의 예외는 앞선 검수 원문을 그대로 따른다. 신청인의 자격을 판정하지 않는다.

## 조건부 서류

- `DocumentTemplate.conditionQuestionId`와 `conditionAnswerValues`로 필요한 선택값을 지정한다. 구버전은 `['YES']`를 기본으로 읽는다.
- 문항 미응답/UNKNOWN → UNKNOWN, 지정값 → CONDITIONAL, 그 밖의 답변 → NOT_APPLICABLE.
- 조건이 없으면 REQUIRED다. 일치값은 해당 질문에 존재해야 하며 UNKNOWN을 필요 조건으로 지정하지 못한다.
- 준비 스냅샷은 `rules`와 `ruleValues`를 보관하여 원본 공고의 후속 편집과 분리한다.
- 실제 준비 목록과 선택된 서류 상세는 REQUIRED/CONDITIONAL만 렌더링한다. 준비 완료한 대상 서류도 진행 기록으로 계속 표시한다.
- UNKNOWN은 별도의 ‘해당 여부 추가 확인’ 안내에 모아 조건 답변 링크를 제공한다. NOT_APPLICABLE은 목록에서 숨긴다. 데이터 자체는 삭제하지 않아 답변 변경 시 다시 표시할 수 있다.
- 선택했던 서류가 더 이상 대상이 아니면 첫 준비 대상 서류로 선택을 옮긴다. 대상이 0개이면 빈 목록 안내를 표시한다.
- 이미 완료한 서류의 조건이 바뀌면 RECHECK로 전환하며, 모름/해당 없음 상태에서는 완료 저장을 차단한다.

## 기존 준비 기록의 새 안내 적용

`POST /api/v1/preparations/{id}/refresh`는 `{ revision, version }`을 받는다. 소유자·현재 리비전·최신 안내 버전·안내 공개 상태를 확인한다. 화면에서 사용자가 ‘새 안내로 질문 다시 확인하기’를 눌렀을 때만 수행한다.

1. 이전 전체 스냅샷을 `preparation_history`에 보관한다(V5 마이그레이션).
2. 질문 계약 전체가 동일한 답변만 이어받는다. 바뀐 질문은 미응답으로 둔다.
3. 같은 서류 ID의 메모는 유지한다. 완료 상태는 재확인으로 돌린다.
4. ID·제목·날짜가 동일한 일정 기록만 유지한다.
5. 같은 준비 ID를 유지하고 버전·리비전을 갱신한다. 트랜잭션 실패 시 보관과 갱신 모두 취소한다.

아카이브는 해당 준비 기록의 소유 관계를 따른다. 공개 API로 노출하지 않으며 로그나 Git에 개인 답변을 남기지 않는다. 보관 기록 조회 UI는 이번 범위에 포함하지 않는다.

## 로컬 적용

백엔드 새 빌드와 V5 적용 후 다음 명령으로 v2 원문 검수 자료가 일치하는 전세임대 1건만 v3로 바꾼다. 기존 준비 기록은 자동 변경하지 않는다.

```powershell
node scripts/apply-guidance-review.mjs --question-options
node scripts/apply-guidance-review.mjs --question-options --apply
```

최초 검수와 동일하게 충돌 시 중단, 동일 결과 재실행 시 건너뛰기, 공개 공고 적용 전후 로컬 백업을 적용한다.
