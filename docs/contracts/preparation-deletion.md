# 준비 기록 영구 삭제

2026-11-06 사용자 요청 20번. 준비 기록 보관·복원과 별도로 명시적인 영구 삭제를 제공한다.

## 사용자 흐름

- 내 준비 개요와 완료 여정 보관함의 `준비 기록 삭제`에서 대화상자를 연다. 서버에서 삭제 대상 제목과 최신 revision을 다시 읽는다.
- `준비 삭제` 문구를 직접 입력한다. 일반 회원은 현재 비밀번호 또는 가입 이메일로 받은 삭제 전용 확인 코드를 함께 입력한다. 서버 체험 계정은 유효한 자기 세션과 명시 확인으로 삭제한다.
- 삭제하면 해당 준비의 답변, 서류 상태·메모, 신청 기록, 보관 메모, 이전 버전 기록, 다른 준비에 연결했던 경험 참조를 영구 삭제한다. 공개 공고·다른 준비·관심 공고는 유지한다. 삭제 이전 상태로 복구하지 않는다.
- 성공 시 선택 준비 값, 준비 목록·보관 목록·상세·이전 기록·경험 참조 캐시를 정리한다. 개요에서 삭제하면 내 준비 목록으로 이동한다. 실패·충돌에는 데이터와 창을 유지하고 다시 확인할 수 있게 한다.
- 서버 없는 공개 데모에는 삭제 버튼을 비활성화하고 서버 연결이 필요하다고 안내한다. 데모 화면이 서버 영구 삭제를 수행한 것처럼 표시하지 않는다.

## API·검증

| API | 역할 |
| --- | --- |
| GET `/api/v1/preparations/{id}/deletion` | 자기 준비의 제목·revision·인증 방법 조회, 보관 건도 허용 |
| POST `/api/v1/preparations/{id}/deletion-proof` | `{revision}`에 대한 삭제 전용 코드 발급 |
| DELETE `/api/v1/preparations/{id}` | `{revision, confirmation, password? , code?}` 확인 후 삭제 |

- 소유자와 준비 건을 순서대로 잠근다. 없는 준비와 다른 사용자의 준비는 동일한 404다. revision이 바뀌었으면 409이며 자동 재시도로 삭제하지 않는다.
- 메일 코드는 준비 ID·소유자·revision·계정 security_version에 묶인 10분 일회성 값이다. 32바이트 난수의 해시만 저장하며 탈퇴·로그인 연결·이메일 인증 코드는 받지 않는다. 메일 발송은 사용자당 1분 간격이다. 설정이 없거나 발송에 실패하면 성공으로 표시하지 않는다.
- 재인증 실패는 사용자당 15분에 5회 제한한다. 실패 트랜잭션도 횟수가 보존된다. 새 메일 요청은 실패 한도를 초기화하지 않는다.
- 본인 확인과 데이터 삭제는 같은 잠금·트랜잭션에서 실행한다. 이중 클릭·동시 삭제는 최초 한 건만 성공한다. 기존 Bearer API 인증과 요청 위조 방어를 사용하며 쿠키만으로 준비 데이터를 삭제할 수 없다.
- DB의 preparation_history 및 experience_reference 외래키가 해당 준비 삭제 시 함께 지운다. 공개 공고와 개인 준비의 삭제 방향을 역전하지 않는다.

## 검증

- 프런트 `PreparationDeleteDialog.test.tsx` 5건: 명시 확인·비밀번호 필수, 취소 후 인증값 제거, 메일 경로, 충돌 시 보존, 체험 명시 확인 및 캐시 정리.
- 백엔드 `PreparationDeletionIntegrationTest` 6건: 보관·이전 기록 CASCADE와 공개 데이터 보존, 소유권·revision·확인 문구, 코드 바인딩·일회성, 실패 횟수 커밋·만료, 체험 인증 경로, 동시 삭제.
- SMTP 실발송과 실제 모바일 기기는 별도 외부 환경 검증 대상이다. 자동 검사 실행 결과는 이번 작업 기록에 별도로 남긴다.
