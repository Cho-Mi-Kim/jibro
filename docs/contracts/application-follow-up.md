# 신청 후 개인 진행 기록

2026-11-23 사용자 요청으로 홈·내 준비·이전 기록·보관함에 신청 후 진행을 연결한다. 공고 검수의 후속 공식 자료 수집과는 별개인 사용자의 준비 기록이다.

## 저장과 책임

- `Preparation.followUp`은 선택적 필드다. 기존 기록의 필드 부재는 미기록이며, UI의 결과 대기는 기관에서 확인된 결과가 아니다.
- `result`: WAITING(결과 대기), SELECTED(선정), WAITLIST(예비 입주), NOT_SELECTED(미선정).
- `waitlistNumber`: WAITLIST일 때만 1~999999의 정수 또는 null. 결과 변경 시 화면에서 순번을 비운다.
- `documentsSubmitted`, `contractCompleted`, `movedIn`: 사용자가 직접 확인한 완료 여부. 선계약 후 검증이 있으므로 계약 완료와 선정 결과를 일방적으로 서로 바꾸지 않는다.
- `PUT /api/v1/preparations/{id}/follow-up`: revision과 위 필드를 받는다. 소유자·활성 기록·낙관적 동시 수정 검사를 거쳐 기존 JSON snapshot에 저장한다. 보관 기록은 직접 수정할 수 없다.
- 공고 정정·마감 뒤에도 개인 결과는 기록할 수 있다. 기존 자격 답변·서류·일정의 변경 제한은 그대로 유지한다. 준비도, 질문 답변, 서류 상태, 일정 확인 표시를 후속 기록에서 변경하지 않는다.
- 안내 새 버전으로 갱신할 때 개인 기록을 유지하고, 과거 snapshot은 당시 값만 보존한다. 보관·복원도 같은 값을 유지한다. 체험 모드도 같은 입력·revision 계약을 따른다.

## 화면

- `housing/followUp.ts`: 결과 문구·우선 표시와 공식 일정의 단계 분류를 관리한다.
- `FollowUpSummary`: 홈, 내 준비 개요와 신청 후 화면, 이전 기록, 보관함의 표시를 공유한다. 기존 데이터에는 당시 후속 기록을 만들지 않는다.
- 내 준비의 `신청 후` 탭에서 결과·예비 순번·서류 제출·계약·입주를 기록한다. 신청 완료로 기록한 뒤에만 탭과 일정 탭의 후속 진입을 표시한다. 그 전에는 개요·조건·서류·일정 4개 탭이며, 신청 후 직접 주소 접근은 개요로 돌려보낸다. 준비 단계의 후속 절차는 신청 전에는 신청 여부 기록으로, 신청 후에는 결과 기록으로 연결한다.
- 공식 일정은 `snapshotPreparationScheduleSource`의 해당 버전·개인화된 내용을 사용하고 `ScheduleCard`로 표시한다. 공고에 명시된 단계와 이미 저장한 완료 기록만 노출한다. 날짜가 없다는 이유로 개별 안내나 임의 날짜를 생성하지 않는다.
- 서류 제출 대상자 발표·예비입주자 발표를 자동으로 최종 선정이나 입주일로 해석하지 않는다. 공식 검수 필요 항목은 별도로 표시한다.
- 홈·개요 요약도 신청 완료 기록이 있을 때만 보여준다. 탭/진입/요약의 기준은 `showFollowUp`이며 준비도 100%나 기존 후속 기록만으로 노출하지 않는다. 신청 후 화면에서 선택한 준비 건은 홈에서도 유지한다.
- 사용자 수정(2026-11-23): `journeyStage`는 신청 완료로 기록하면 네 단계를 완료하고 후속 절차를 진행 중으로, WAITING 이외의 선정·예비·미선정 결과를 저장하면 다섯 단계 전체 완료로 표시한다. 대기 저장만으로 완료하지 않는다. 이 단계 완료는 사용자의 기록 완료이며 계약/입주 사실이나 별도의 준비도(%)를 변경하지 않는다. 신청 완료 취소 시 4개 탭과 이전 진행 단계로 돌아가지만 후속 기록은 삭제하지 않는다.
- 저장 실패 시 입력을 유지한다. revision 충돌은 기존 기록을 덮지 않고 사용자에게 최신 기록을 다시 불러오는 선택을 제공한다. 이 선택은 현재 입력을 취소한다는 설명을 표시한다.
- 내 준비/일정 카드의 기존 750ms 펼침·스크롤을 공유하며 모바일 4개/5개 탭은 같은 너비로 나누고 44px 이상의 터치 높이를 유지한다.

## 검증 경계

`PreparationFollowUpIntegrationTest`는 실제 테스트 DB와 HTTP 권한·입력·동시 수정·보관·복원·정정 이력을 검사한다. `app/FollowUpFlow.test.tsx`는 실제 화면/체험 저장을 연결해 실패·재시도·취소·홈·개요·보관·복원·과거 기록·동시 수정 복구를 검사한다. `followUp.test.ts`는 발표와 제출/입주 단계 혼동 및 날짜 생성 방지를 검사한다.

개인의 실제 선정 결과를 기관에서 자동 조회하거나 확인하는 기능은 아니다. 일정과 기관 원문 링크를 제공하고 사용자가 직접 결과를 기록한다.

## 접수 일정과 개인 신청 기록 (2026-11-23)

신청 여부는 applicationRecordSchedule이 고른 한 일정의 recorded를 공유한다. 기존 별도 공식 신청 기록을 우선 유지하고, 없으면 대표 접수 마감을 사용한다. 신청 여부는 개요의 ApplicationRecordDialog에서 저장한다. 사용자 후속 요청으로 일정 화면은 접힘·펼침 모두 완료·취소 버튼과 개인 완료 배지를 표시하지 않는다. 기존 저장값과 서버 기록 계약은 보존한다. 일정 하단의 중복 후속 기록 링크도 표시하지 않는다.

접수 시작·회차·단순 접수 안내 및 대표 기록 외 마감은 완료 버튼·배지를 표시하지 않고 진행률에서 제외한다. schedules.canRecordSchedule과 서버 PreparationSchedules.canRecord를 체험/실제 저장·진행률·일정 표시가 공유한다. 기존 저장값·보관 당시 진행률은 재작성하지 않는다. 서류 마감·발표 등 다른 일정 기록은 유지한다.
