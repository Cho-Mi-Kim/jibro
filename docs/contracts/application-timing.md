# 접수 상태와 확인된 시각

기준: 2026-11-07. 사용자 출시 준비 체크리스트 2번. 기본 접수일·공식 일정·안내 검수·공식 취소/조기 종료·개인 준비 기록은 별개로 유지한다.

## 서버 책임

- `ApplicationPeriod`는 검수 원고의 기본 신청 시작/마감 일정 중 기본 날짜와 한국 날짜가 같은 시각만 해석한다. ISO 날짜, 한국 현지 ISO 시각, offset 시각과 제목의 단일 HH:mm/한국어 시각(오전·오후 포함)을 지원한다.
- 지역별·서류·결과 발표 일정은 전체 접수 시각으로 전용하지 않는다. 단일 시각을 확정할 수 없는 범위·상충 값은 null이다. 날짜만 있을 때 18시를 추정하지 않는다.
- 확인된 시작 시각부터 OPEN, 마감 시각과 같거나 이후에는 CLOSED다. 시각이 없으면 기존 한국 날짜 단위 상태를 유지하고 다음 날짜부터 마감 처리한다. 이 내부 경계를 공식 마감 시각으로 노출하지 않는다.
- `NoticeService`가 원고/기본 날짜 변경 시 파생 시각을 갱신한다. `NoticeQueryRepository`가 같은 현재 시각으로 상태 필터와 페이지 수를 계산한다. Service/Controller 안에 SQL을 넣지 않는다.
- V21은 검색용 `notice.application_start_at`, `application_end_at`만 추가·보완한다. 현재 DTO/파서에 의존하지 않는 동결된 마이그레이션이며 원고, 검수 결과, version, 개인 스냅샷은 변경하지 않는다.

## API

Notice 응답에 `applicationTiming`을 추가한다. 기존 응답 필드는 유지한다.

```json
{
  "applicationTiming": {
    "startsAt": null,
    "endsAt": "2026-12-31T09:00:00Z",
    "nextChangeAt": "2026-12-31T09:00:00Z"
  }
}
```

- startsAt/endsAt: 근거에서 확정한 UTC 시각 또는 null.
- nextChangeAt: 응답 상태가 다음에 바뀌는 시점 또는 null. 날짜 전용의 다음 날 경계도 포함하므로 공고 마감 시각 표시에 사용하지 않는다.
- 관리자 원고 schedule.date는 날짜와 ISO 시각을 허용한다. 기존 날짜 전용 입력/스냅샷은 호환한다.

## 화면·알림·캘린더

- 화면은 서버 상태와 applicationTiming을 사용한다. 마감 이후 신청 기한/D-day와 다음 일정이 남는 경로를 정리했다. 미확인 시각을 제목에서 다시 복원하지 않는다.
- 상세는 nextChangeAt에 재조회한다. 검색 목록은 반환된 공고 전환 시각과 최대 60초 주기로 빈 OPEN 결과에도 새 접수를 반영한다. 보이지 않는 탭의 주기 실행은 Query 기본 정책을 따른다.
- `NoticeSchedules.reminders(notice, now)`는 지나간 기한과 마감 후 신청 행동을 제외한다. 뒤에 남은 서류/결과 일정, 기존 읽음 키는 유지한다.
- 캘린더는 같은 확정 시각을 UTC로 내보내고 날짜만 있으면 종일 일정으로 내보낸다. 개인 신청 기록/준비도는 시각 경과로 자동 완료하지 않는다.

## 검증 경계

마감 1ms 전/정각/이후, 한국 날짜 경계, offset, 오전/오후, 상충 시각, 지역·서류 일정, DB 검색/응답 일치, 원고 수정 후 재계산, 화면·캘린더를 검사한다. 실행 결과는 작업 기록을 따른다. 공식 시각 자체의 적합성은 사람 검수로 확인한다.
