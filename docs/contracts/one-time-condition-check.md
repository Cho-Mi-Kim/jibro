# 저장하지 않고 이번만 확인

## 결정과 범위

- 근거: 기획 문서의 민감 답변 저장 선택과 `docs/planning/backlog-decisions-20261106.md` 19번. 이번 구현은 사용자 요청으로 저장 경로와 미저장 경로를 분리한다.
- 공개 공고의 조건 확인을 시작할 때 `저장하고 이어하기`와 `저장하지 않고 이번만 확인`을 선택한다. 저장 경로는 기존 로그인·준비 생성·답변 저장·새 버전 재확인 계약을 유지한다.
- 이번만 확인은 로그인 없이 이용한다. 로그인된 사용자도 기존 준비 기록을 읽거나 덮어쓰지 않고 독립적으로 확인한다. 이미 준비 중인 공고는 기존 `준비 이어하기`를 유지하고 공고 보조 기능에서 이번만 확인을 열 수 있다.
- 기본 정보·준비 안내 검수가 통과된 현재 버전이고 `canStart=true`인 공고만 평가한다. 접수 마감·공식 조기 마감·취소·미검수·수정 재검수·비공개 공고는 신규 미저장 평가를 시작하지 않는다. 공개 원문과 일정 조회는 별도 기능이다.
- 이 결과는 입력 답변과 필요 서류에 대한 안내이며 최종 신청 자격이나 선정 가능성 판정이 아니다. 준비도, 공식 신청 상태, 알림, 메모 또는 내 준비 목록에 반영하지 않는다.

## 화면과 수명

| 경로 | 역할 |
| --- | --- |
| `/notices/:noticeId/check?version=N` | 저장 여부 선택. `view=home`은 저장 선택 후 기존 홈 복귀 목적을 보존한다. |
| `/notices/:noticeId/check/once?version=N` | 해당 공개 버전의 질문과 미저장 결과. |
| `/notices/:noticeId/start` | 기존 저장 경로. 이번만 확인의 답변을 자동 이관하지 않는다. |

질문 입력·정규화·서류 해당 여부는 저장 경로의 공통 규칙을 재사용한다. 단일 선택은 다음 질문으로 넘어가고, 여러 항목·숫자·날짜 입력은 다음 버튼으로 이동한다. 마지막 답변 후 서버에서 결과를 계산한다. 실패 시 현재 화면의 답변을 유지하여 재시도할 수 있다.

개인 답변과 파생 결과는 해당 화면의 React 상태에만 둔다. TanStack Query·Mutation 캐시, localStorage, sessionStorage, URL·라우터 state, 서버 DB·개인 이력에 기록하지 않는다. 공고 자체의 공개 데이터만 기존 공개 조회 캐시에 둔다. 화면 이탈·새로고침·브라우저 페이지 캐시 복귀 시 개인 상태를 지우고 늦게 도착한 응답도 폐기한다. `답변과 결과 지우기`로 현재 화면에서 즉시 초기화할 수 있다. 원문 링크는 새 창으로 열므로 확인 화면을 유지한다.

## API

`POST /api/v1/notices/{noticeId}/check-once`

- 익명 허용, CSRF 토큰 필수. 요청: `{ "version": 1, "answers": { "question-id": "YES" } }`.
- 질문 ID·형식·옵션·범위는 기존 `QuestionAnswers`로 검증한다. 잘못된 답변은 400, 비공개 공고는 404, 최신 버전 불일치나 시작 불가 상태는 409다.
- 응답: `noticeId`, `title`, `version`, `questions`, `answers`, `documents`, `warnings`. 저장 기록 ID나 준비도·다음 작업을 반환하지 않는다. 응답에 `Cache-Control: no-store`를 지정한다.
- 읽기 전용 REPEATABLE_READ 트랜잭션에서 같은 공개 버전의 공고·내용을 읽고 평가한다. `PreparationSnapshots`의 생성·답변 반영·평가를 저장 경로와 공유하며 개인 저장소, 계정 생성, 이력 작성 호출은 하지 않는다.
- 준비 ID·소유자·revision 입력을 받지 않는다. 미저장 결과를 저장으로 바꾸는 암묵적 업그레이드 경로는 없다.
- 기존 시연 모드도 같은 흐름을 제공하지만 가상 데이터임을 기존 안내로 구분한다. 실제 API는 검수된 공고 내용으로 평가한다.
