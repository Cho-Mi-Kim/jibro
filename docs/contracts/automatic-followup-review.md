# 정정·후속 공식 자료 자동 대조

2026-11-09 사용자는 앞으로 수집되는 공고에도 정정본·후속 공식 자료 대조를 적용하도록 요청했다. 기존 명시적 원문 검토 패키지를 예약 실행하는 방식이 아니라 별도의 자동 발견·비교·게시 경로로 구현한다. 수동 검수 원고와 개인 준비 스냅샷은 자동으로 변경하지 않는다.

## 처리 순서

1. 기존 LH 목록 수집·기본 검수·원문 발췌 뒤 `AutomaticFollowupService`가 자동 검수 대상의 작업을 가져온다. 이 기능이 켜져 있으면 기존 원문 전용 GUIDANCE worker가 먼저 게시하지 않는다.
2. `OfficialFollowupDiscovery`가 현재 원문 문맥을 확인하고 정정 연결 및 LH 공식 공지 검색을 조회한다. 모집 식별 관계와 추가 원문·첨부 지문을 함께 저장한다.
3. `OfficialFollowupComparison`은 원공고 전체 자료의 완전성을 검사하고, 명시적 변경 전후 또는 같은 모집의 명확한 후속 발표 일정을 대조한다. 바뀐 항목만 교체하며 원문·구값·신값·각 근거 위치를 보존한다.
4. 게시 직전 관련 자료 묶음을 다시 읽고 `FollowupPrimaryVerifier`로 원공고 본문·현재 첨부 목록·모든 첨부 SHA를 다시 대조한다.
5. `AutomaticFollowupPublicationService`는 공고 잠금 안에서 작업 임대, 현재 revision·목록/내용 지문·발췌 지문·120초 검증 유효시간을 확인한다. 저장된 원고와 증거만 게시하고 네트워크 요청은 트랜잭션 밖에서 처리한다.

## 관계와 적용 범위

- 정정 관계는 기존 `OfficialCorrectionLink`의 공식 양방향 ID·공급 유형·정정 사유 검증을 그대로 사용한다. 단방향 링크나 제목 유사도만으로 자동 적용하지 않는다.
- 후속 공지는 본문에 같은 공식 모집 ID가 연결되어 있거나, 같은 원모집 공고일과 단지·블록·유형·대상이 원문에서 직접 함께 지칭되는 경우에만 비교한다. 여러 모집의 날짜·행을 합쳐 하나의 모집 근거로 만들지 않는다.
- 검색 후보의 날짜가 최신이라는 이유만으로 우선하지 않는다. 여러 후속 자료가 서로 다르면 명시적인 변경 관계가 입증된 항목만 대체한다.
- 제목에 원모집 공고일이 명시된 검색 후보부터 읽되 이는 조회 우선순위일 뿐 관계 승인 근거가 아니다. 이후 후보를 한도 때문에 읽지 못했다면 검색 완료로 처리하지 않는다.
- 조건·서류 변경은 지원하는 명확한 전후 문장과 원공고의 해당 항목이 일치해야 한다. 다른 조건·예외는 삭제하지 않는다. 서류 대상자 발표와 당첨자 발표, 신청과 계약, 순위·지역별 일정을 혼합하지 않는다.
- 원자료와 SHA는 수정하지 않는다. 컴파일 단계의 항목별 우선순위와 일정 투영에 변경 근거를 사용하며 새 값을 예전 출처에서 읽은 것처럼 표시하지 않는다.
- 역사 법령·임의 외부 사이트를 자동으로 검색하거나, 지난 작업의 공고 ID별 수동 답안을 재생하지 않는다. 본래 검토 원고의 `SupplementalSourceVerifier` 경로는 별도로 유지한다.

## 상태 구분

| 상황 | 처리 |
|---|---|
| 확인된 일반 규칙·일정 | 준비 안내 제공 |
| 같은 범위의 공식 값이 실제로 상충 | 기존 항목별 `reviewIssues`로 해당 부분만 확인 필요 |
| 검색 미완료·다운로드 실패·OCR 판독 미확정 | 기술적 재검토 대기와 재시도. 기관 확인 사유를 만들지 않음 |
| 관계·문장·적용 범위를 자동으로 해석하지 못함 | 자동 해석 대기. 미해석을 정답 또는 충돌로 바꾸지 않음 |
| 확인된 후속 변경으로 기존 자동 안내가 무효이나 새 안내를 안전하게 완성하지 못함 | 이전 원고·날짜는 감사에 보관하고 공개 안내·확정 일정을 재검토 상태로 전환. 개인 기록 유지 |
| 단순 네트워크 실패 | 이전 공개 안내를 삭제하지 않음 |
| 이전에 반영한 후속 공지·첨부가 검색 결과에서 빠짐 | 과거 원공고 값으로 되돌리지 않고 의존 자료 재확인 대기 |

검증된 정정본에 기존 원문과 달라진 지배 조항이 있으나 전후 값을 해석하지 못한 경우에도, 해당 문장·위치·관계 증명을 별도 무효 근거로 보존한다. 이는 기관 확인 이슈를 만드는 경로가 아니다. 다른 후보 하나가 읽히지 않더라도 완전히 검증된 정정 자료가 기존 안내의 무효를 입증하면 재검토 상태로 전환하며, 미완료 묶음으로 새 안내를 승인하지 않는다.

모든 자연어 공고를 해석할 수 있다는 보장은 아니다. 원문 자체의 계좌 차이, 명시되지 않은 실제 종료일 등은 관련 공식 자료에서 해소되지 않으면 그대로 남는다. 미지원 문법·자료 누락으로 검토가 끝나지 않은 경우도 자동 승인하지 않는다. 확정되지 않은 접수 경계를 임의 날짜로 채우지 않는다.

## 재검토·보존·운영

- V33의 `notice_followup_queue`는 작업 임대·다음 확인 시각·실패 횟수·직전 자료 지문을, `automatic_followup_review`는 원문·관계·비교·적용 전후 자료를 보존한다.
- 최초 HOLD뿐 아니라 기존 자동 PASS/PARTIAL도 재검색한다. 원공고 발췌가 같아도 관련 자료 묶음이 바뀌면 다시 대조한다. 동일 묶음 재조회는 확인 기록만 갱신하고 공고 버전·revision을 증가시키지 않는다.
- 기존 자동 게시 후 발췌 재사용은 당시 자동 감사의 적용 revision·현재 내용 SHA·목록 지문·발췌 지문이 정확히 일치하는 경우만 허용한다. 증거가 부족한 옛 자동 게시 원고는 새 발췌부터 요청한다.
- `FollowupDependencies`와 `latestDependencySources`는 같은 공식 원문 identity에 대해 적용·철회 근거가 된 관련 URL과 첨부 의존성을 보존한다. 새 발췌·빈 검색·빈 무변경 기록·원문 변경 후에도 이전 정정의 효력을 검색 누락만으로 취소하지 않는다.
- `automaticReviewBlocked`, 사람의 `review_audit`, 명시적 `notice_source_review`, 비정상 lifecycle은 발견·게시 양쪽에서 제외한다. 개인 준비·답변·메모·완료 상태를 옮기거나 재작성하지 않는다.
- 기본 주기는 60초마다 한 작업, 성공한 진행 공고는 6시간 뒤 재확인이다. 2026-11-10 사용자 요청에 따라 접수종료 공고는 자동 검수·후속 대조·로컬/API 보조 분석의 대기열에서 제외한다. 검증 중 마감 시각이 지난 경우에도 저장 직전에 제외한다. 실패는 15분부터 최대 6시간까지 간격을 늘린다.
- 한 번의 발견은 검색 최대 2페이지, 후보 상세 12개, 연결 자료 6개, 첨부 8개, 총 요청 25개로 제한한다. 한도 초과를 ‘자료 없음’으로 기록하지 않는다. 기존 HTTP·파일·파서 제한은 유지한다.
- `AUTOMATIC_FOLLOWUP_ENABLED` 기본 true, `AUTOMATIC_FOLLOWUP_POLL_MS` 기본 60000. 기존 `app.collection.automatic-review-enabled=false`이면 전체 자동 작업을 중지한다. 테스트 프로필은 자동 작업을 끈 별도 DB를 사용한다.
- 관리자 미리보기는 저장된 최신 후속 근거가 있는 경우에만 같은 순수 비교기를 재생한다. 조회 요청이 새 원격 수집·게시를 일으키지 않는다.

실제 실행·모바일 확인·테스트 결과 및 미확인 범위는 해당 날짜의 작업 기록에 따로 남긴다. 로컬 코드·설정 반영과 외부 운영 서버 배포는 구분한다.

## 서류마감 자동 연결 (2026-11-10)

- `ScheduleSourceReader`가 명시적인 서류 제출 기간/마감뿐 아니라 `서류 제출: 날짜`, 바로 다음 줄에 날짜가 있는 서류 제출 표제, `신청접수 및 서류제출 기간`을 읽는다. 다른 열의 표제와 날짜를 임의 연결하지 않는다.
- `ConcurrentDocumentSubmission`은 일반 신청자의 서류 동시 제출/스캔 첨부/서류 지참 접수 안내와 신청 마감이 **동일한 추출 완료 원문**에 있는 경우에만 서류마감으로 연결한다. 날짜·시각·조기중단 조건과 두 근거 위치를 보존한다. API 공고 종료일은 사용하지 않는다.
- 별도 서류 일정이 이미 있거나 미정/충돌인 경우 이를 동시 제출 날짜로 덮지 않는다. 개별 동의서, 고령자 등 일부 신청자 안내, 계약·동호지정 제출, 여러 순위·단지별 기간은 하나의 공통 날짜로 추정하지 않는다. 단일 접수 경로의 명확한 기간은 허용한다.
- OCR 미확정·미지원 표·불완전한 공식 자료·정정 관계 검증 제한을 우회하지 않는다. 원문 날짜를 언제나 판독할 수 있다는 보장이 아니며, 명확하지 않은 경우 기존 검수/확인 필요 상태를 유지한다.
- 공고에 저장된 공식 종료 사실과 한국 시각의 접수 마감을 이용해 종료 여부를 확인한다. 시간을 모르면 해당 날짜 종료까지, 시간이 있으면 그 시각부터 제외한다. 원문을 읽은 뒤 처음 발견된 지난 접수 기간도 게시하지 않는다. 아직 날짜가 확인되지 않은 공고는 읽기 전에는 종료 여부를 단정할 수 없다.
- 정책 식별자 `source-review-v7-docs` / `official-rules-v7`. 기존 원문 SHA·revision·정정/후속 공식 대조·수동 검수 보호·개인 준비 기록 보존 조건을 유지한다.
